# Tendermint v0 Markdown pseudocode

This page retains the upstream Tendermint paper's round and locking sketch.
It is a historical algorithm reference, not the current application API.
The suffix `v0` names a design variant, not a running network version.

[Current lifecycle](abci++_tmint_expected_behavior_002_draft.md) · [Next variant](v1.md)

## Current implementation map

The sketch is useful for following height, round, step, lock and valid-value
transitions in the classic algorithm. Current initialization uses genesis and
persisted state; `h_p = 0` below is abstract notation. The count `2f + 1` assumes
an equal-weight model; the running classic engine checks voting power.

The classic implementation is [`State`](../../internal/consensus/state.go),
including `enterNewRound`, `enterPropose`, `defaultDoPrevote`, `enterPrecommit`,
and `enterCommit`. Application validation enters through `ProcessProposal`;
decided blocks pass through `BlockExecutor.ApplyBlock` in
[`execution.go`](../../internal/state/execution.go), which calls `FinalizeBlock`
and then `Commit`. The original v0 sketch omits all application hooks and
persistence, so reaching its `decision_p` assignment is not an implementation
of the node's complete execution lifecycle.

Autobahn uses lane certificates and global blocks rather than these classic
round and lock rules. Its application execution and restart loop is
[`runExecute` / `executeBlock`](../../internal/p2p/giga_router.go); votes and
view justifications have their own
[persisted consensus state](../../internal/autobahn/consensus/inner.go).
The sketch does not specify that mode's safety, block identity or recovery.

## Historical pseudocode

The following transcription preserves the design's useful round, timeout and
locking material. It is illustrative notation, not compilable Go or a complete
startup, execution and crash-recovery algorithm. Callback names and fields in
this section belong to the historical model; the implementation map above
states their current applicability. Quorum counts are the paper's abstraction;
classic runtime quorums use voting power. Initialization below also omits
production state restoration.

### Initialization

```text
h_p ← 0
round_p ← 0
step_p is one of {propose, prevote, precommit}
decision_p ← Vector()
lockedRound_p ← -1
lockedValue_p ← nil
validValue_p ← nil
validRound_p ← -1
```

### StartRound(round)

```text
function startRound(round) {
    round_p ← round
    step_p ← propose
    if proposer(h_p, round_p) = p {
        if validValue_p != nil {
            proposal ← validValue_p
        } else {
            proposal ← getValue()
        }
        broadcast ⟨PROPOSAL, h_p, round_p, proposal, validRound_p⟩
    } else {
        schedule OnTimeoutPropose(h_p,round_p) to be executed after timeoutPropose(round_p)
    }
}
```

### ReceiveProposal

In the case where the local node is not locked on any round, the historical sketch used the following rules:

```text
upon ⟨PROPOSAL, h_p, round_p, v, −1) from proposer(h_p, round_p) while step_p = propose do {
    if valid(v) ∧ (lockedRound_p = −1 ∨ lockedValue_p = v) {
        broadcast ⟨PREVOTE, h_p, round_p, id(v)⟩ 
    } else {
        broadcast ⟨PREVOTE, h_p, round_p, nil⟩ 
    }
    step_p ← prevote
}
```

In the case where the node is locked on a round, the historical sketch used the following rules:

```text
upon ⟨PROPOSAL, h_p, round_p, v, vr⟩ from proposer(h_p, round_p)
  AND 2f + 1 ⟨PREVOTE, h_p, vr, id(v)⟩
  while step_p = propose ∧ (vr ≥ 0 ∧ vr < round_p) do {
    if valid(v) ∧ (lockedRound_p ≤ vr ∨ lockedValue_p = v) {
        broadcast ⟨PREVOTE, h_p, round_p, id(v)⟩
    } else {
        broadcast ⟨PREVOTE, h_p, round_p, nil⟩
    }
    step_p ← prevote
}
```

### Prevote timeout

The sketch scheduled a timeout after observing 2f + 1 prevotes.

```text
upon 2f + 1 ⟨PREVOTE, h_p, vr, *⟩ with step_p = prevote for the first time, do {
    schedule OnTimeoutPrevote(h_p, round_p) to be executed after timeoutPrevote(round_p)
}
```

with OnTimeoutPrevote defined as:

```text
function OnTimeoutPrevote(height, round) {
    if (height = h_p && round = round_p && step_p = prevote) {
        broadcast ⟨PRECOMMIT, h_p, round_p, nil⟩
        step_p ← precommit
    }
}
```

### Receiving enough prevotes to precommit

The historical sketch used the following code upon receiving 2f + 1 prevotes for the same block

```text
upon ⟨PROPOSAL, h_p, round_p, v, *⟩
  from proposer(h_p, round_p)
  AND 2f + 1 ⟨PREVOTE, h_p, round_p, id(v)⟩ 
  while valid(v) ∧ step_p >= prevote for the first time do {
    if (step_p = prevote) {
        lockedValue_p ← v
        lockedRound_p ← round_p
        broadcast ⟨PRECOMMIT, h_p, round_p, id(v)⟩
        step_p ← precommit
    }
    validValue_p ← v
    validRound_p ← round_p
}
```

And upon receiving 2f + 1 prevotes for nil:

```text
upon 2f + 1 ⟨PREVOTE, h_p, round_p, nil⟩ 
  while step_p = prevote do {
    broadcast ⟨PRECOMMIT, h_p, round_p, nil⟩
    step_p ← precommit
}
```

### Precommit timeout

The sketch scheduled a timeout after observing 2f + 1 precommits.

```text
upon 2f + 1 ⟨PRECOMMIT, h_p, vr, *⟩ for the first time, do {
    schedule OnTimeoutPrecommit(h_p, round_p) to be executed after timeoutPrecommit(round_p)
}
```

with OnTimeoutPrecommit defined as:

```text
function OnTimeoutPrecommit(height, round) {
    if (height = h_p && round = round_p) {
        StartRound(round_p + 1)
    }
}
```

### Upon Receiving 2f + 1 precommits

The historical sketch used the following code upon receiving 2f + 1 precommits for the same block

```text
upon ⟨PROPOSAL, h_p, r, v, *⟩
  from proposer(h_p, r)
  AND 2f + 1 ⟨ PRECOMMIT, h_p, r, id(v)⟩ 
  while decision_p[h_p] = nil do {
    if (valid(v)) {
        decision_p[h_p] ← v
        h_p ← h_p + 1
        reset lockedRound_p, lockedValue_p,validRound_p and validValue_p to initial values
        StartRound(0)
    }
}
```

In this historical model, a precommit timeout advanced the round after a quorum of
precommits without a block decision.
