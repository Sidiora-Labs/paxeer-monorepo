# Tendermint v4 Markdown pseudocode

This page retains the upstream experiment that forked proposal processing
on receipt and joined it before precommitting. It built on the proposed header
check in [v3](v3.md). The fork/join algorithm is historical research, not a
concurrency contract or a deployed `v4` application interface.

[Current lifecycle](abci++_tmint_expected_behavior_002_draft.md) · [Previous variant](v3.md)

## Current implementation map

In the current [`classic consensus state`](../../internal/consensus/state.go),
`defaultDoPrevote` calls `BlockExecutor.ProcessProposal` synchronously and checks
its result before a block prevote. The engine does not use this sketch's
`Fork`/`Join` scheduling. The current
[`Application`](../../abci/types/application.go) has no `VerifyHeader`,
`PrepareProposal`, `ExtendVote`, or `VerifyVoteExtension` callbacks.
`ResponseProcessProposal.Status` replaces the draft's `accept` Boolean, and
there is no `evidence_list` response field.

The node does have application-side optimistic processing in
[`ProcessProposalHandler` and `FinalizeBlocker`](../../../node/app.go).
`FinalizeBlocker` waits for outstanding work and checks eligibility and block
identity before reusing results; otherwise it processes the decided block.
That implementation is not the v4 engine-level fork/join algorithm. Persistence
still requires the separate [`App.Commit`](../../../node/abci.go) call after
`FinalizeBlock`. An application must support finalization without preceding
optimistic work, including replay and Autobahn execution.

Autobahn uses lane certificates and global blocks rather than these classic
round and lock rules. Its application execution and restart loop is
[`runExecute` / `executeBlock`](../../internal/p2p/giga_router.go); votes and
view justifications have their own
[persisted consensus state](../../internal/autobahn/consensus/inner.go).
The sketch does not specify that mode's safety, block identity or recovery.

## Historical pseudocode

The following transcription preserves the design's useful round, timeout and
locking material. It is illustrative notation, not compilable Go or a complete
startup, execution and crash-recovery algorithm. Callback names and fields in
this section belong to the historical model; the implementation map above
states their current applicability. Quorum counts are the paper's abstraction;
classic runtime quorums use voting power. Initialization below also omits
production state restoration.

### Initialization

```text
h_p ← 0
round_p ← 0
step_p is one of {propose, prevote, precommit}
decision_p ← Vector()
lockedValue_p ← nil
validValue_p ← nil
validRound_p ← -1
```

### StartRound(round)

```text
function startRound(round) {
    round_p ← round
    step_p ← propose
    if proposer(h_p, round_p) = p {
        if validValue_p != nil {
            proposal ← validValue_p
        } else {
            txdata ← mempool.GetBlock()
            // getUnpreparedBlockProposal fills in header
            unpreparedProposal ← getUnpreparedBlockProposal(txdata)
            proposal ← ABCI.PrepareProposal(unpreparedProposal)
        }
        broadcast ⟨PROPOSAL, h_p, round_p, proposal, validRound_p⟩
    } else {
        schedule OnTimeoutPropose(h_p,round_p) to be executed after timeoutPropose(round_p)
    }
}
```

### ReceiveProposal

In the case where the local node is not locked on any round, the historical sketch used the following rules:

```text
upon ⟨PROPOSAL, h_p, round_p, v, −1) from proposer(h_p, round_p) while step_p = propose do {
    if valid(v) ∧ ABCI.VerifyHeader(h_p, v.header) ∧ (lockedRound_p = −1 ∨ lockedValue_p = v) {
        // We fork process proposal into a parallel process
        Fork ABCI.ProcessProposal(h_p, v)
        broadcast ⟨PREVOTE, h_p, round_p, id(v)⟩ 
    } else {
        broadcast ⟨PREVOTE, h_p, round_p, nil⟩ 
    }
    step_p ← prevote
}
```

In the case where the node is locked on a round, the historical sketch used the following rules:

```text
upon ⟨PROPOSAL, h_p, round_p, v, vr⟩
  from proposer(h_p, round_p)
  AND 2f + 1 ⟨PREVOTE, h_p, vr, id(v)⟩ 
  while step_p = propose ∧ (vr ≥ 0 ∧ vr < round_p) do {
    if valid(v) ∧ ABCI.VerifyHeader(h_p, v.header) ∧ (lockedRound_p ≤ vr ∨ lockedValue_p = v) {
        // We fork process proposal into a parallel process
        Fork ABCI.ProcessProposal(h_p, v)
        broadcast ⟨PREVOTE, h_p, round_p, id(v)⟩
    } else {
        broadcast ⟨PREVOTE, h_p, round_p, nil⟩
    }
    step_p ← prevote
}
```

### Prevote timeout

The sketch scheduled a timeout after observing 2f + 1 prevotes.

```text
upon 2f + 1 ⟨PREVOTE, h_p, vr, -1⟩ 
  with step_p = prevote for the first time, do {
    schedule OnTimeoutPrevote(h_p, round_p) to be executed after timeoutPrevote(round_p)
}
```

with OnTimeoutPrevote defined as:

```text
def OnTimeoutPrevote(height, round) {
    if (height = h_p && round = round_p && step_p = prevote) {
        // Join the ProcessProposal, and output any evidence in case it has some.
        processProposalOutput ← Join ABCI.ProcessProposal(h_p, v)
        for evidence in processProposalOutput.evidence_list {
            broadcast ⟨EVIDENCE, evidence⟩ 
        }

        precommit_extension ← ABCI.ExtendVote(h_p, round_p, nil)
        broadcast ⟨PRECOMMIT, h_p, round_p, nil, precommit_extension⟩
        step_p ← precommit
    }
}
```

### Receiving enough prevotes to precommit

The historical sketch used the following code upon receiving 2f + 1 prevotes for the same block

```text
upon ⟨PROPOSAL, h_p, round_p, v, *⟩
  from proposer(h_p, round_p)
  AND 2f + 1 ⟨PREVOTE, h_p, vr, id(v)⟩ 
while valid(v) ∧ step_p >= prevote for the first time do {
    if (step_p = prevote) {
        lockedValue_p ← v
        lockedRound_p ← round_p
        processProposalOutput ← Join ABCI.ProcessProposal(h_p, v)
        // If the proposal is valid precommit as before.
        // If it was invalid, precommit nil.
        // Note that ABCI.ProcessProposal(h_p, v).accept is deterministic for all honest nodes.
        precommit_value ← nil
        if processProposalOutput.accept {
            precommit_value ← id(v)
        }
        precommit_extension ← ABCI.ExtendVote(h_p, round_p, precommit_value)
        broadcast ⟨PRECOMMIT, h_p, round_p, precommit_value, precommit_extension⟩
        for evidence in processProposalOutput.evidence_list {
            broadcast ⟨EVIDENCE, evidence⟩ 
        }

        step_p ← precommit
    }
    validValue_p ← v
    validRound_p ← round_p
}
```

And upon receiving 2f + 1 prevotes for nil:

```text
upon 2f + 1 ⟨PREVOTE, h_p, round_p, nil⟩ 
  while step_p = prevote do {
    // Join ABCI.ProcessProposal, and broadcast any evidence if it exists.
    processProposalOutput ← Join ABCI.ProcessProposal(h_p, v)
    for evidence in processProposalOutput.evidence_list {
        broadcast ⟨EVIDENCE, evidence⟩ 
    }

    precommit_extension ← ABCI.ExtendVote(h_p, round_p, nil)
    broadcast ⟨PRECOMMIT, h_p, round_p, nil, precommit_extension⟩
    step_p ← precommit
}
```

### Upon receiving a precommit

The sketch checked a received precommit using `ABCI.VerifyVoteExtension(precommit.precommit_extension) = true`
before accepting it. This proposed extension check was separate from the paper notation;
it is not a callback in the current application interface.

### Precommit timeout

The sketch scheduled a timeout after observing 2f + 1 precommits.

```text
upon 2f + 1 ⟨PRECOMMIT, h_p, vr, *⟩ for the first time, do {
    schedule OnTimeoutPrecommit(h_p, round_p) to be executed after timeoutPrecommit(round_p)
}
```

with OnTimeoutPrecommit defined as:

```text
def OnTimeoutPrecommit(height, round) {
    if (height = h_p && round = round_p) {
        StartRound(round_p + 1)
    }
}
```

### Upon Receiving 2f + 1 precommits

The historical sketch used the following code upon receiving 2f + 1 precommits for the same block

```text
upon ⟨PROPOSAL, h_p, r, v, *⟩
  from proposer(h_p, r)
  AND 2f + 1 ⟨ PRECOMMIT, h_p, r, id(v)⟩ 
  while decision_p[h_p] = nil do {
    if (valid(v)) {
        decision_p[h_p] ← v
        h_p ← h_p + 1
        reset lockedRound_p, lockedValue_p,validRound_p and validValue_p to initial values
        ABCI.FinalizeBlock(id(v))
        StartRound(0)
    }
}
```

In this historical model, a precommit timeout advanced the round after a quorum of
precommits without a block decision.
