# Build-time environment variables

The [explorer image](../../docker/explorer-frontend/Dockerfile) supplies the
following build inputs. Environment values are strings; boolean switches use
the literal string `true` to enable them.

| Variable | Image build input | Purpose | Required |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_GIT_COMMIT_SHA` | `GIT_COMMIT_SHA` build argument | Source commit exposed in frontend configuration and used as Rollbar's version fallback | No |
| `NEXT_PUBLIC_GIT_TAG` | `GIT_TAG` build argument | Frontend release tag displayed in the footer and preferred for Rollbar's version | No |
| `NEXT_OPEN_TELEMETRY_ENABLED` | `NEXT_OPEN_TELEMETRY_ENABLED` build argument | Enables server OpenTelemetry instrumentation when equal to `true` | No |
| `NEXT_PUBLIC_ICON_SPRITE_HASH` | Generated by `build_sprite.sh` | Hash suffix for the generated SVG sprite filename | Generated |

The [sprite builder](../../apps/explorer/deploy/scripts/build_sprite.sh) and
[environment collector](../../apps/explorer/deploy/scripts/collect_envs.sh)
package public build values into the image. At startup,
[make_envs_script.sh](../../apps/explorer/deploy/scripts/make_envs_script.sh)
loads packaged `NEXT_PUBLIC_*` defaults only for names absent from the process
environment, then writes `public/assets/envs.js`. Explicit runtime values,
including empty strings, take precedence over packaged defaults. The image
[entrypoint](../../apps/explorer/deploy/scripts/entrypoint.sh) first loads
`configs/envs/.env.<ENVS_PRESET>` when that preset exists and its name is neither
empty nor `none`. Its `NEXT_PUBLIC_*` values replace matching process values
except `NEXT_PUBLIC_APP_PROTOCOL`, `NEXT_PUBLIC_APP_HOST`, `NEXT_PUBLIC_APP_PORT`,
`NEXT_PUBLIC_APP_ENV` and `NEXT_PUBLIC_API_WEBSOCKET_PROTOCOL`.
The generated browser script excludes names beginning with `NEXT_PUBLIC_VERCEL`.

`NEXT_OPEN_TELEMETRY_ENABLED` is a server setting read by
[instrumentation.ts](../../apps/explorer/instrumentation.ts); supply it in the
server environment when enabling instrumentation. It is separate from
`NEXT_TELEMETRY_DISABLED`, which controls Next.js usage telemetry.
See [ENVS.md](ENVS.md) for the application configuration inventory.
