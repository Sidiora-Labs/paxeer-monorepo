# Paxeer 7.0.0 release notes

## Summary

Paxeer 7.0.0 integrates the LayerX kernel into `paxd` on one BFT network.
Mainnet-beta uses Cosmos chain ID `hyperpax_125-1` and EVM chain ID `125` (`0x7d`).
The proposer executes transactions in receipt order; a receipt is final when its block commits.
The `v7.0` upgrade activates native ledger, payments, authority, Programs, tenant domains and agent functions.
Node JSON-RPC serves chain reads, signed receipts and EVM transactions at the root path.
Wallet, explorer, bridge, launchpad and agent applications use the same committed chain state.

## For validators

Release `paxeer-network/v7.0.0` supplies the `paxd` binary for the governance-scheduled
`v7.0` plan. Follow the [validator runbook](7.0.0-validator-runbook.md) and
[upgrade plan](7.0.0-upgrade-plan.md) for the halt, stopped-node backup, binary
replacement and restart at the approved height `H`.

The plan's `info` contains sequencer genesis: `leaders`, `receipt_keys`,
`last_seq`, `last_seq_hash` and optional `activation_height`. It requires a
nonempty leader list, an initial sequence of zero and a governed receipt key
covering the first sequenced height. With `activation_height` zero or omitted,
that height is `H + 1`. Use `paxd q upgrade plan` to inspect the scheduled plan
and `paxd q upgrade applied v7.0` to read the applied height. `paxd version --long`
reports binary identity; `paxd start` starts the node.

The upgrade mounts `sequencer`, `layerxledger`, `layerxauth`, `layerxpay`,
`layerxchains`, `layerxprograms`, `layerxagent` and `lxphost` stores. The kernel
host executes activities against transaction state and persists them with block
commit. The handler installs Programs fee, metering and occupancy schedules
at version 1 and guest ABI version 5. Consensus and governance parameters
remain governed separately.

Sequenced blocks carry `MsgSequenceBatch` at Cosmos transaction position zero,
followed by user transactions in receipt order. The message is injected by the
proposer and is refused by CheckTx. Only validators in the governed leader list
may propose sequenced blocks. Configure the integrated runtime on those nodes
as described below. JSON-RPC `transactionIndex` counts EVM transactions, so it
differs from the Cosmos transaction position.

Activation returns anchor guarantor bonds, pending unbondings and open challenge
deposits to their owners. It cancels pending custody claims and transfers
remaining custody asset balances to the custody authority. The separate
`v7.0-anchor-store-delete` plan deletes `layerxanchor` only at a height strictly
after the applied merge height.

Keep stopped copies of every configured database directory and preserve current
validator signing state. Recovery after state migration uses a coordinated
repair binary; use the [validator recovery procedure](../runbooks/paxeer-x-fork.md)
for operational details.

Sources: [activation handler](../../node/upgrades.go),
[sequence batch keeper](../../modules/sequencer/keeper/keeper.go),
[proposer validation](../../node/process_proposal_proposer.go).

## For node operators

### Node configuration

Configure `app.toml` using the exact section and key names below. The
`[sequencer]` section controls ordering inside `paxd`.
The corresponding start flags use the `--sequencer.` prefix, for example
`--sequencer.enable` and `--sequencer.wal-dir`.

| `[sequencer]` keys | Behavior and operator action |
| --- | --- |
| `enable` | Defaults to `false`; enable on a node assigned to run the ordering runtime. |
| `mode` | `sequential` by default; `microbatch` groups admissions within configured bounds. |
| `role` | `primary` or `standby`; defaults to `primary`. |
| `wal-dir`, `wal-retain-blocks` | Supply the durable write-ahead log directory when enabled; retained committed blocks must be positive, default `2`. |
| `receipt-key-file` | Required when enabled; points to a protected Ed25519 receipt signing seed file, distinct from the consensus key. |
| `receipt-forward-url` | Receipt forwarding for nodes with `enable = false`; must be empty when enabled. |
| `nonce-queue-max-per-sender`, `nonce-queue-max-total` | Both must be positive when enabled; total must be at least the per-sender bound. |
| `standby-address`, `replication-timeout` | Configure the replication destination on a primary or listener on a standby; replication requires a positive timeout. |
| `replication-tls-cert`, `replication-tls-key`, `replication-tls-ca` | Configure mutual TLS for replication. |
| `replication-peer-name`, `replication-peer-spki` | Configure the authorized replication peer identity and public-key digest. |
| `lease-duration` | Must be positive when enabled; omission derives it as three times `replication-timeout`. |
| `microbatch-window`, `microbatch-max-count` | Both must be positive in `microbatch` mode. |

The `[evm]` section configures JSON-RPC:

| `[evm]` keys | Behavior and operator action |
| --- | --- |
| `http_enabled`, `http_address`, `http_port` | Configure the HTTP listener. |
| `ws_enabled`, `ws_port` | Configure the WebSocket listener. |
| `cors_origins`, `ws_origins` | Configure allowed client origins. |
| `deny_list` | Deny selected registered methods on either transport. |
| `enabled_legacy_pax_apis` | HTTP allowlist for gated `pax_*` and `pax2_*` methods; defaults to `pax_getPaxAddress`, `pax_getEVMAddress` and `pax_getCosmosTx`. |
| `enable_unsafe_keyring_rpc` | Defaults to `false`; enabling local keyring signing on a live chain prevents RPC startup. |
| `enable_test_api` | Defaults to `false`; the `test` namespace is available only on HTTP for non-live chain IDs. |

Keep `[state-commit] sc-enable` enabled. Include `sc-directory` in that section
and `[state-store] ss-db-directory` and `evm-ss-db-directory` in the stopped-node
backup inventory. See the [validator runbook](7.0.0-validator-runbook.md) for
storage and snapshot settings.

Sources: [sequencer flags and template](../../node/sequencer/config.go),
[EVM RPC configuration](../../rpc/config/config.go).

### Services and applications

Use upgraded node root URLs for chain access and configure hosted application
origins separately. Restore services after sequenced block commitment in the
order described in the [service operator runbook](7.0.0-service-operator-runbook.md).

| Service or application | Configuration and behavior |
| --- | --- |
| Hosted gateway | `LAYERX_GATEWAY_PAXEER_RPC_URLS` supplies two to eight distinct node root URLs. `LAYERX_GATEWAY_PROTOCOL_NETWORK_ID` is `125`; `LAYERX_GATEWAY_NETWORK_ID` is `paxeer-mainnet-beta`. Hosted receipt verification uses `LAYERX_GATEWAY_RECEIPT_KEYS_FILE`, an authenticated snapshot loaded at startup. |
| Explorer backend and frontend | `PAXEER_X_NODE_RPC_URL` selects the node; `PAXEER_X_RECEIPT_AUTHORITY_FILE` supplies governed receipt keys and validator checkpoints. Start the backend before the frontend. Index Cosmos sequence batches separately from EVM transaction indices. The application presents anchor and kernel receipt records under `Kernel archive`. |
| Agent daemon | `LAYERX_AGENT_NODE_RPC_URL` and `LAYERX_AGENT_NODE_CHAIN_ID` select the node and chain; full mode also uses `LAYERX_AGENT_NODE_ENDPOINT`. Write readiness requires a nonempty governed receipt-key set. Native scheduled jobs execute in the node's end block. |
| Bridge relayer and bridge app | `layerx-bridge-relayer` uses `PAXEER_BRIDGE_PAXEER_RPC_URL`; the app uses `NEXT_PUBLIC_PAXEER_RPC_URL`. Bridge calls use `0x1016` and registry refusal codes. |
| Launchpad indexer and web app | The indexer uses `RPC_URL`, `RPC_URLS` and `CHAIN_ID`; preserve `INDEXER_START_BLOCK`. The web app uses `NEXT_PUBLIC_PAXEER_RPC_URL`. Role contracts forward calls to `0x1017` while retaining their storage, balances and nonces. |
| Wallet app | `NEXT_PUBLIC_PAXEER_RPC_URL` selects the node. `NEXT_PUBLIC_PAXEER_HOSTED_URL` supplies registration and faucet access; `NEXT_PUBLIC_PAXEER_HUMAN_API` and `NEXT_PUBLIC_PAXEER_EXPLORER_URL` select the application services. Account, balance and history reads use the node. |

For gateway receipt-key provisioning, preserve each governed `keyId`,
`publicKey`, `firstHeight` and `lastHeight`. Node RPC returns hex bytes inside
`{"keys": [...]}`; the gateway snapshot is a JSON array with canonical base64
bytes. Authenticate the export against governance, convert the representation,
and restart the gateway to load updates. The
[gateway configuration reference](../../services/platform/hosted/gateway/README.md)
describes the snapshot format and key rotation.

Human supplies account, session, security, agent and intent APIs; retired
operations return HTTP 410 `operation-retired`. Hosted wallet and explorer
pages, agent RPC, MCP tools, gas sponsorship, interop, ramp, web search and
webhook APIs use their configured service bindings and authorization. See the
[service route reference](../system/routes.md) for admitted paths and readiness.

## For developers

### Native modules and precompiles

The merged node exposes ledger, authority, payment, Programs and tenant-domain
operations through EVM precompiles. Kernel modules include `asset`, `escrow`,
`budget`, `stream`, `service`, `perps`, `governance`, `programs` and `spot`.
`lxphost` connects kernel execution and reads to chain state; `layerxgov`
dispatches allowlisted native governance messages subject to module authority
checks.

Addresses below use shortened hexadecimal notation; left-pad with zeroes to
20 bytes when encoding an EVM destination. The `v7.0` activation enables:

| Module or precompile | Address | Supported surface |
| --- | --- | --- |
| `layerxledger` | `0x101A` | Per-asset accounts, balances, registration, mint, burn, transfers and `payExact`. |
| `layerxpay` | `0x101B` | Escrows, native budgets, streams and service agreements. |
| `layerxauth` | `0x101C` | Capability grants, session authority, revocation and activity checks. |
| `layerxprograms` | `0x101D` | Deterministic Programs deployment, calls, simulation, upgrades, interfaces, accounts and lifecycle operations. |
| `layerxchains` | `0x101E` | Tenant-domain creation, funding, allowances, operator controls and lifecycle. A domain is a database namespace within the network. |
| `layerxagent/orob` | `0x0901` | Oracle-relative offset conversion through `resolveOffset`, `resolveOffsetBatch` and `toOffset`. |
| `layerxagent/clearing` | `0x0902` | `computeClearing`. |
| `layerxagent/oracle` | `0x0903` | Price submission, validator-price reads and aggregation. |
| `layerxagent/pofq` | `0x0904` | Fill scoring, batch scoring and rolling quality scores. |
| `layerxagent/scheduler` | `0x0905` | Schedule, cancel, reschedule and inspect jobs. |
| `layerxagent/streams` | `0x0906` | Open, accrue, settle, update and close streams. |
| `layerxagent/teeattestor` | `0x0907` | Attestation verification, roots and peer bindings. |
| `layerxagent/eip712` | `0x0908` | Typed-data domain separation, hashing and signer recovery. |

The node also serves native perps at `0x1015`, bridge at `0x1016`, launchpad
at `0x1017`, fee token at `0x1018`, xweb at `0x1019` and pricefeed at `0x1020`.
Spot uses separate ABIs for `spot_pecor` (`0x1021`), `spot_orders` (`0x1022`),
`spot_stoporders` (`0x1023`), `spot_quoter` (`0x1024`) and `spot_vault`
(`0x1025`). Resolve launchpad role and pool addresses and vault share-token
pointers from chain state, using the ABI belonging to each destination.

Use the [precompile reference](../system/precompiles.md),
[chain module reference](../system/chain-modules.md) and
[kernel module reference](../system/kernel-modules.md) for method signatures
and parameters. Availability depends on applied activation and module state.
In particular:

- `layerxVerify` (`0x1012`) and `layerxCustody` (`0x1013`) refuse every method
  with `LXP_MODULE_DISABLED`. Use committed block evidence and native bank or
  ledger transfers. Outward transfers use bridge `0x1016`.
- `layerxAnchor` (`0x1014`) refuses writes; reads remain until
  `v7.0-anchor-store-delete`, after which all calls refuse.
- Ledger `issueGrant`, `revokeGrant`, `draw` and `getPayerGrant` refuse with
  `LXP_NO_PAYER_GRANT`; pay `budgetPull` refuses with `LXP_MODULE_DISABLED`.
  Use supported native budget and funding operations.
- Address binding (`0x1004`), bridge (`0x1016`) and fee-token (`0x1018`)
  refusals use registry `"<code>: <message>"` reasons at merge activation.
  Decode the code when classifying a refusal.

Programs use guest ABI version 5 and the `layerx-program-sdk` Rust guest crate.
Use `getCurrentFeeSchedule`, `getCurrentMeteringSchedule` and `quoteCallFee`
to read active schedules and budget a call. `quoteCallFee` returns the schedule
version, execution ceiling and fee asset identifier. Submit lifecycle operations
through `0x101D`; Programs governance uses kernel governance activities.

### JSON-RPC and receipts

Send node JSON-RPC to the root HTTP or WebSocket URL. HTTP registers `debug`,
`echo`, `eth`, `net`, `pax`, `pax2`, `px`, `txpool` and `web3`.
WebSocket registers `echo`, `eth`, `net`, `pax`, `px`, `txpool` and `web3`;
its `pax` service supplies `pax_sequencerReceipt`. The optional HTTP `test`
namespace is restricted to non-live chains. Method configuration and backend
availability apply on each transport.

| Purpose | Methods |
| --- | --- |
| Chain identity and head | `eth_chainId`, `eth_blockNumber`, `net_version`, `web3_clientVersion` |
| EVM calls and transactions | `eth_call`, `eth_estimateGas`, `eth_sendRawTransaction`, `eth_getTransactionReceipt`, `eth_getLogs` |
| Accounts, assets and balances | `px_resolveAccount`, `px_getAccount`, `px_listAssets`, `px_getBalances` |
| History | `px_getHistory`, `px_getUnifiedHistory`, `px_listHolderRecords` |
| Network and discovery | `px_getNetwork`, `px_getCapabilities`, `px_getRouteCatalogue` |
| Consensus and ordering | `px_getCommit`, `px_getValidators`, `px_getSequenceBatch` |
| Signed execution receipts | `pax_sequencerReceipt`, `px_getReceiptKeys` |
| Inference state | `px_getInferenceDeal`, `px_getInferencePeer`, `px_getInferencePeerAt`, `px_getInferenceReceipts`, `px_getInferenceRoom`, `px_getInferenceRoomAt`, `px_getInferenceRooms` |

Call `px_getReceiptKeys` with `[]`. It returns `{"keys": [...]}` containing
`keyId`, `publicKey`, `firstHeight` and `lastHeight`. Verify signed receipts
against the governed keys and their height bounds. Receipt progress is
`submitted`, `receipted` or `committed`; use `committed` when block finality is
required and check execution status separately.

Sign EVM transactions locally and broadcast with `eth_sendRawTransaction`.
Use standard `eth_*` and `debug_*` methods for new integrations. Gated legacy
HTTP calls outside `enabled_legacy_pax_apis` return `-32601` with
`legacy_pax_deprecated`; `pax_sequencerReceipt` is exempt from that gate.
For subscriptions, use `eth_subscribe` with `newHeads`, `logs` or
`newPendingTransactions`, and `eth_unsubscribe` to stop. Pending transaction
notifications require the node's receipt feed.

The hosted gateway's `px_` contract is
[OpenRPC](../../services/platform/hosted/gateway/openrpc.json).
`px_register` and `px_requestFunds` perform hosted identity registration and
faucet operations. On the node they return `-32004` with
`hosted_gateway_service_required`. Gateway `lx_*` calls return `-32601`.
External `/v1/programs` and `/v1/activities` ingress returns HTTP 404;
use native Programs transactions and views.

Sources: [RPC registration](../../rpc/server.go) and
[RPC method reference](../system/rpc.md).

### SDK and CLI use

In `@paxeer/wallet`, configure `EndpointClient` with `nodeUrl` for native reads
and optional `hostedUrl` for `px_register` and `px_requestFunds`. Batch calls
follow the same routing. Wallet provider configuration uses `rpcUrl` for the
node and `gatewayUrl` for authenticated wallet operations.

The agent SDKs are `@sidiora/layerx-sdk` for TypeScript and `layerx_sdk` for
Python; Cosmos bindings are `@pax-js/cosmos`. See the
[SDK reference](../system/sdk.md) for exports and receipt verification.

Use `layerx program build`, `layerx program deploy`, `layerx program call`,
`layerx program simulate` and `layerx program upgrade` for Programs.
`layerx chains create` submits tenant registration within the shared network.
`layerx receipt get` reads `pax_sequencerReceipt`; `layerx receipt verify`
checks a receipt offline against independently supplied evidence.
`layerx register --gateway-endpoint` and `layerx faucet --service-endpoint`
take explicit hosted service URLs. Use `layerx install mcp` or
`layerx install a2a` for enrolled agent transports. The
[CLI reference](../system/cli.md) describes arguments, transport requirements
and commitment options.

## For users

Wallet balances, transfers and history use the same Paxeer chain as contracts,
Programs and markets. A transaction hash means submission; a signed execution
receipt means execution progress; commitment of its block establishes finality.
Use the wallet or explorer's committed transaction status when confirming a
payment.

The wallet supports standard accounts and EVM transaction review and approval.
Funded-account operations return HTTP 410 `FUNDED_UNSUPPORTED`.
Registration and faucet funding use the hosted services configured by the
application. Native account and history reads use the node.

The explorer presents blocks, transactions, native account data and receipt
verification. `Kernel archive` holds anchor and kernel receipt records.
Bridge transfers use the external-chain bridge; launchpad, spot and perpetual
markets use their native contract interfaces. Tenant domains share network
execution and finality.

For operational instructions, see the [upgrade plan](7.0.0-upgrade-plan.md),
[validator runbook](7.0.0-validator-runbook.md) and
[service operator runbook](7.0.0-service-operator-runbook.md).
