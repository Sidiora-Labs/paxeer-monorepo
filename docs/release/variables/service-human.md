# Human service variables

The Human service workspace in `services/human` provides the Human HTTP API, privileged components, identity and security providers, and KMS provider and gateway. It uses the merged Paxeer network, whose EVM chain ID is 125. This inventory covers production environment reads, their shared-library readers, build-time inputs, and operator-supplied configuration files.

Required settings have no source default and apply to the process or feature named in their row. Conditional groups are required only when selected: remote KMS settings apply without attestor custody; attestor settings apply with `LAYERX_HUMAN_ATTESTOR_NODES`; identity assertion and binding-reader groups must be supplied together when enabled. TLS certificate and private-key paths are required for the default TLS listener and must be omitted for plain mode. Runtime-clock bindings are supplied to each process that connects to the clock supervisor.

Configuration names below use `FILE_VARIABLE / JSON section / key` to identify the selected file and its fields. All listed JSON fields are required unless placed in Optional; fields of an optional file are required when that file is supplied. Secret-file rows identify paths to protected material. Host-based defaults are identified by source constant name.

`services/human/.env.example` lists the environment inputs; it does not load automatically. Empty entries with no default need deployment values. Commented entries are optional or supplied by Cargo; uncomment only the selected groups. Empty relying-party and allowed-origin settings select their source defaults. Other absent optional inputs should remain unset, since several readers distinguish absence from an empty value. Cargo supplies its build variables. The encoded security-provider trust root and generated durable state are not JSON configuration sections.
