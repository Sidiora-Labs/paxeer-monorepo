# Platform service variables

The platform service in `services/platform` contains hosted gateways and supporting services, the native node lifecycle, price ingestion, perps data services, ramps and reference applications. It runs against Paxeer mainnet-beta, whose EVM chain ID is 125; committed blocks provide finality. The hosted gateway supplies the `px_` methods, while the node serves JSON-RPC at its root path.

Required settings apply to the component or command that reads them. Optional feature groups become required together when enabled; configuration-file fields apply when their enclosing section is present. Paths in the source column are relative to `services/platform`. Configuration names use **file / section / key**; `root` means the top level, `[]` an array entry and `<name>` a map key. Files selected through an environment variable are named by that variable. A secret-file path is not itself a secret, but its contents are. Endpoint, account and key values are supplied by the operator; endpoint defaults are described without publishing addresses. Variables read only by tests are excluded.

The root `.env.example` inventories the components together; select the settings for the process being started. Existing component examples contain their own settings. Commented assignments leave optional inputs unset, including settings whose defaults are derived or contain addresses; uncomment complete feature groups when enabling them. Secrets have empty values. The Chainflow credential name comes from `chainflow.api_key_env`, so its two rows describe variable-name patterns rather than fixed assignments.
