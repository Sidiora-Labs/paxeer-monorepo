# Paxeer 7.0.0 service operator runbook

This runbook covers what changes for each Paxeer service at the `v7.0` upgrade, what to redeploy,
and what to verify, in the order the services return after the halt. The schedule is in the
[upgrade plan](7.0.0-upgrade-plan.md); node work is in the
[validator runbook](7.0.0-validator-runbook.md).

Each statement ends with the file it comes from. **Gap** marks a step the repository does not yet
support as written; the gaps are listed at the end.

## Shared facts

| Fact | Source |
| --- | --- |
| One network: EVM chain ID `125` (`0x7d`), Cosmos chain ID `hyperpax_125-1` | (docs/runbooks/paxeer-x-fork.md) |
| Public JSON-RPC is served at the root path of `api1` to `api14` under `mainnet-beta.paxeer.network` and the alias `api-mainnet-beta.paxeer.network`; there is no `/rpc` path and no separate router | (docs/paxeer-network.md, sdk/wallet/src/endpoint.ts) |
| From `v7.0` the node root serves the `px_` methods, including `px_getNetwork`, `px_getAccount`, `px_getBalances`, `px_getHistory`, `px_getCommit`, `px_getValidators`, `px_getSequenceBatch` and `px_getReceiptKeys` | (rpc/server.go, rpc/px_account.go, rpc/sequencer_receipt.go, spec/layerx-merge/spec.kvx decision 2521) |
| Signed receipts are read with `pax_sequencerReceipt` and verified against the governed receipt keys from `px_getReceiptKeys` | (services/platform/hosted/gateway/README.md, rpc/sequencer_receipt.go) |
| From `S = H+1`, Cosmos block position 0 holds the sequence batch; JSON-RPC `transactionIndex` stays the EVM-only index | (node/upgrades.go, rpc/tx.go) |

| Refusals from `0x1004`, `0x1016` and `0x1018` use the registry `"<code>: <message>"` reason after `H` | (precompiles/addr/addr.go, precompiles/layerxbridge/layerxbridge.go, precompiles/feetoken/feetoken.go) |

## Order of work

| Step | When | Service |
| --- | --- | --- |
| 1 | Before `H` | Stage configuration for every service; release client builds that accept both refusal formats |
| 2 | `H` − 10 min | Show maintenance pages; pause bridge relaying and agent daemon writes |
| 3 | `S` committed, RPC nodes restored | Hosted gateway |
| 4 | | Explorer backend, then explorer frontend |
| 5 | | Agent daemon |
| 6 | | Bridge relayer, then bridge app |
| 7 | | Launchpad indexer, then launchpad web |
| 8 | | Wallet app |
| 9 | T+24 h | Announce `px_` at the node root to SDK consumers |

The hosted gateway comes first for hosted operations, including `px_register` and
`px_requestFunds`; native wallet and SDK reads use the node root
(sdk/wallet/src/endpoint.ts:66–110). The agent daemon cannot open writes until
`px_getReceiptKeys` returns keys, which only happens after `H` (docs/site/docs/agents/agentd.md).

## Hosted gateway

**What changes.** The gateway relays node reads and writes, and serves `px_getReceiptKeys` from an
operator-pinned snapshot. It never fetches keys from the node, and it loads them only at startup
(services/platform/hosted/gateway/README.md). Retired `lx_*` methods answer `-32601`, and the
retired activity and program routes answer `404` (services/platform/hosted/gateway/src/rpc.rs,
services/platform/hosted/gateway/README.md).

**Redeploy.**

1. After `H`, read the governed keys with `px_getReceiptKeys` at the root of an upgraded node you
   trust. The result is `{"keys":[...]}` with hex bytes (services/platform/hosted/gateway/README.md).
2. Authenticate the export against the passed plan's `receipt_keys`. Then convert `keyId` and
   `publicKey` to canonical base64, keeping the exact height bounds. Copying the raw RPC result is
   invalid (services/platform/hosted/gateway/README.md).
3. Validate it with
   `python3 services/platform/hosted/tests/sequencer-pins.py --gateway-check receipt-keys.json`.
   Then publish it through the `--gateway` and `--gateway-secret` paths, which produce the
   `layerx-gateway-receipt-keys` secret projected at `LAYERX_GATEWAY_RECEIPT_KEYS_FILE`
   (services/platform/hosted/tests/sequencer-pins.py, services/platform/hosted/gateway/README.md).
4. Set `LAYERX_GATEWAY_PAXEER_RPC_URLS` to between two and eight upgraded public node root URLs
   selected from `api1` to `api14` under `mainnet-beta.paxeer.network` (decision 2521). The shipped
   manifest lists `https://api1.mainnet-beta.paxeer.network/` through
   `https://api8.mainnet-beta.paxeer.network/` in the `layerx-mainnet-beta` namespace
   (services/platform/hosted/gateway/deployment.yaml:58, services/platform/hosted/gateway/deployment.yaml:97–106,
   services/platform/hosted/gateway/README.md:9–15).
5. Keep `LAYERX_GATEWAY_PROTOCOL_NETWORK_ID=125` and `LAYERX_GATEWAY_NETWORK_ID=paxeer-mainnet-beta`.
   Do not reset Redis idempotency, quota or audit state
   (services/platform/hosted/gateway/deployment.yaml, services/platform/hosted/gateway/README.md).
6. Roll the pods so the new key list loads (services/platform/hosted/gateway/README.md).

**Verify.** Through the gateway:

- `px_getReceiptKeys` equals the node's keys after conversion.
- `eth_chainId` returns `0x7d`.
- An `lx_*` call answers `-32601`.

(services/platform/hosted/gateway/README.md)

## Explorer

**What changes.**

- The explorer verifies sequencer receipts against a receipt authority file and reads native data
  from the node (services/explorer/backend/config/runtime.exs).
- Its `/paxeer-x` API keeps only the archive anchors and receipts, capabilities and the price feed;
  every other path returns `not_found`
  (services/explorer/backend/apps/block_scout_web/lib/block_scout_web/routers/api_router.ex).
- Its indexers must accept a sequenced block. In such a block the Cosmos position 0 transaction is
  the sequence batch, while JSON-RPC indices stay EVM-only (rpc/tx.go).

**Redeploy.**

1. Build `PAXEER_X_RECEIPT_AUTHORITY_FILE`. It needs `chain_id`, the governed `receipt_keys` (hex
   `keyId` and `publicKey`, plus `firstHeight` and `lastHeight`) and `validator_checkpoints`
   (services/explorer/backend/config/runtime.exs).
2. Preserve each governed `keyId` independently of `publicKey`, with the exact `firstHeight` and
   `lastHeight`. The backend accepts non-zero 32-byte key IDs and validates the positive, ordered
   height bounds (services/explorer/backend/config/runtime.exs:315,
   services/explorer/backend/apps/explorer/lib/explorer/chain/paxeer_x/receipt_keys_config.ex:10–19).
3. Set `PAXEER_X_NODE_RPC_URL` to an upgraded node root. `PAXEER_X_GATEWAY_URL` is read as both the
   gateway URL and the router URL (services/explorer/backend/config/runtime.exs).
4. Leave `PAXEER_X_CAPABILITIES_ENABLED` and the price feed settings as they are. The price feed
   settings are `PAXEER_X_PRICE_FEED_ENABLED`, `PAXEER_X_PRICE_FEED_START_BLOCK` and the Cosmos REST
   and CometBFT URL lists (services/explorer/backend/config/runtime.exs).
5. Redeploy the backend first. Then redeploy the frontend, with `NEXT_PUBLIC_PAXEER_X_ENABLED` as
   configured (docs/explorer/ENVS.md).

**Verify.**

- The backend boots with the authority file (services/explorer/backend/config/runtime.exs).
- Blocks `H` and `H+1` index without gaps.
- A user transaction in `H+1` shows the same `transactionIndex` as `eth_getTransactionReceipt` on
  the node (rpc/tx.go).
- The receipt view verifies a receipt from `pax_sequencerReceipt`
  (services/platform/hosted/gateway/README.md).
- The anchor-checkpoint and kernel-receipt navigation entries sit under `Kernel archive` and
  open archive data (apps/explorer/lib/hooks/useNavItems.tsx:374–387,
  apps/explorer/lib/hooks/useNavItems.tsx:445).

## Agent daemon

**What changes.** The agent functions at `0x0901`–`0x0908` and the agent scheduler go live at `H`
(node/upgrades.go, node/legacyabci/end_block.go). The daemon's readiness gate calls
`px_getReceiptKeys` and refuses an empty key set, so writes stay closed until keys exist
(docs/site/docs/agents/agentd.md).

**Redeploy.**

1. Before `H`, pause write submission.
2. Set `LAYERX_AGENT_NODE_RPC_URL` to an upgraded node root and `LAYERX_AGENT_NODE_CHAIN_ID` to
   `125` or `0x7d`. In full mode, also set `LAYERX_AGENT_NODE_ENDPOINT`
   (docs/site/docs/agents/agentd.md).
3. Start the daemon after `S`.

**Verify.**

- Readiness turns ready only after `px_getReceiptKeys` returns the plan's keys
  (docs/site/docs/agents/agentd.md).
- A scheduled job settles, and the node logs show no `agent end block failed`
  (node/legacyabci/end_block.go).
- Several agent daemon programme tasks are still pending, so check the release you deploy against
  the programme state (spec/layerx-merge/spec.kvx). **Gap.**

## Bridge

**What changes.**

- The bridge precompile `0x1016` stays live, but its refusals switch to the registry reason format
  at `H` (precompiles/layerxbridge/layerxbridge.go).
- The relayer is `layerx-bridge-relayer` (services/interop/crates/layerx-bridge-relayer).
- The checked-in attestor manifest still holds placeholder attestors pending governance, and
  `check-attestor-manifest.py` refuses it
  (services/bridge/deploy/attestors.json, services/bridge/deploy/check-attestor-manifest.py).

**Redeploy.**

1. Before `H`, deploy a relayer build that classifies both the old and the new refusal reasons from
   `0x1016` (precompiles/layerxbridge/layerxbridge.go).
2. At `H` − 10 min, pause relaying. After `S`, resume it with `PAXEER_BRIDGE_PAXEER_RPC_URL`
   pointing at an upgraded node root (contracts/bridge/README.md).
3. Redeploy the bridge app with `NEXT_PUBLIC_PAXEER_RPC_URL` and its `NEXT_PUBLIC_BRIDGE_RPC_*`
   values unchanged (apps/bridge/src/lib/bridge/config.ts).

**Verify.**

- `services/bridge/deploy/checklist.sh --all` passes against the upgraded node
  (services/bridge/deploy/checklist.sh).
- `python3 services/bridge/deploy/check-attestor-manifest.py` exits 0 once the governed signer set
  replaces the placeholders (services/bridge/deploy/check-attestor-manifest.py). **Gap.**
- One deposit and one release complete end to end.

## Launchpad

**What changes.** The launchpad precompile `0x1017` and the pool contracts do not change
(spec/layerx-merge/docs/plans/activation-and-migration.md). The indexer reads logs over `RPC_URL` and
`RPC_URLS`, and it must accept sequenced blocks
(services/launchpad/indexer/internal/config/config.go).

**Redeploy.**

1. Before `H`, record the pool state at `H−1` with
   `python3 tools/release/rehearsal/pool_parity.py record --rpc <node> --block <H-1> --out pools.json`
   (tools/release/rehearsal/pool_parity.py).
2. After `S`, restart the indexer with `RPC_URL`, `RPC_URLS` and `CHAIN_ID=125`. Do not move
   `INDEXER_START_BLOCK` (services/launchpad/indexer/internal/config/config.go).
3. Redeploy the web app with `NEXT_PUBLIC_PAXEER_RPC_URL` unchanged (apps/launchpad/web/src/core/rpc.ts).

**Verify.**

- `python3 tools/release/rehearsal/pool_parity.py check --rpc <node> --block <H+1> --record pools.json`
  passes (tools/release/rehearsal/pool_parity.py).
- The indexer head follows the chain past `S`.

## Wallet app and wallet SDK

**What changes.**

- The wallet SDK defaults to `https://api-mainnet-beta.paxeer.network`. It sends native `px_`
  reads to the node root; only `px_register` and `px_requestFunds` use the hosted URL
  (sdk/wallet/src/endpoint.ts:43–110).
- The app reads `NEXT_PUBLIC_PAXEER_RPC_URL` (required), `NEXT_PUBLIC_PAXEER_HOSTED_URL` (optional),
  `NEXT_PUBLIC_PAXEER_HUMAN_API` and `NEXT_PUBLIC_PAXEER_EXPLORER_URL`
  (apps/wallet/src/account/config.ts).
- Fee-token and address-binding refusals change format at `H` (precompiles/feetoken/feetoken.go,
  precompiles/addr/addr.go).

**Redeploy.**

1. Point `NEXT_PUBLIC_PAXEER_RPC_URL` at an upgraded node root. Keep
   `NEXT_PUBLIC_PAXEER_HOSTED_URL` configured when registration or faucet operations are used
   (apps/wallet/src/account/config.ts, sdk/wallet/src/endpoint.ts:66–110).
2. Ship a build that shows both refusal formats readably (precompiles/feetoken/feetoken.go).
3. Deploy the SDK routing native `px_` reads to the node root under decision 2521; account,
   balance and history reads work without a hosted URL (sdk/wallet/src/endpoint.ts:66–110).

**Verify.**

- After `S`, the account view loads balances and history.
- A transfer is sent and receipted.
- `eth_chainId` returns `0x7d` (sdk/wallet/src/endpoint.ts).

operator docs identify public node roots and native `px_` reads
(services/interop/README.md:3–7, services/interop/README.md:43–50,
services/platform/hosted/gateway/README.md:9–15, docs/site/docs/agents/running.md:26–34).
