# Paxeer 7.0.0 readiness checklist

Every item must be ticked, with the evidence attached, before go/no-go 1 in the
[upgrade plan](7.0.0-upgrade-plan.md). Each item names the command or artifact that proves it and
ends with its source file. Deployment values come from the operator's reviewed plan and inventory.

Paxeer is one network on EVM chain ID `125` (`0x7d`). Public JSON-RPC uses
the root URLs of `api1` through `api14` under `mainnet-beta.paxeer.network`
and the canonical alias; there is no router path. See
[network identity and endpoints](../paxeer-network.md).

## Release identity and build

- [ ] `tools/release/version.json` reads `{"version":"v7.0.0","upgrade":"v7.0"}`. Proof: `jq . tools/release/version.json` at the tag (tools/release/version.json:2–3).
- [ ] The release metadata generator `tools/release/upgrade_info.py release` accepts the plan name `v7.0`. Proof: the release build writes `upgrade-info.json` without error (tools/release/upgrade_info.py:27–38, tools/release/build-paxd.sh).
- [ ] The release identity check accepts `v7.0` through `MergeUpgrade`. Proof: the `Paxeer / Release Check` run for the release candidate is green (.github/workflows/paxeer-release-check.yml:65).
- [ ] `MergeUpgrade` is `v7.0` and `node/tags` ends with `v7.0`. Proof: `grep -n 'MergeUpgrade = "v7.0"' precompiles/common/precompiles.go` and `tail -1 node/tags` (precompiles/common/precompiles.go, node/tags).
- [ ] Tag `paxeer-network/v7.0.0` is signed and published. Proof: `git tag -v paxeer-network/v7.0.0` and the GitHub release page (RELEASE.md).
- [ ] `Paxeer / Release Publish` succeeded for the tag. Proof: `gh run list --workflow paxeer-release-publish.yml` (.github/workflows/paxeer-release-publish.yml).
- [ ] An independent rebuild matches. Proof: `tools/release/reproducible-check.sh` output and a diff of the two `SHA256SUMS` files (RELEASE.md, tools/release/reproducible-check.sh).
- [ ] The published files verify. Proof: `tools/release/verify-release.sh --tag paxeer-network/v7.0.0 --dist dist/paxeer-network/v7.0.0` exits 0 (tools/release/verify-release.sh).
- [ ] `paxd version --long --output json` reports `v7.0.0`, the tag's commit and the recorded `native_archive_digest`. Proof: the command output (tools/release/build-paxd.sh).
- [ ] The container image digest is recorded and its `paxd` matches `SHA256SUMS`, or validators are told to use only the release binary. The image workflow packages checksum-verified linux/amd64 release assets and records the digest. Proof: release notes and `sha256sum` of the `paxd` extracted from the image (.github/workflows/paxeer-docker-publish.yml:82–104, .github/workflows/paxeer-docker-publish.yml:110–121).
- [ ] A 7.0.0 consensus-commit ledger exists and passes its gate. Proof: `python3 tools/ci/consensus_commit_gate.py 68c8887a9520542d2878da3d6a44920ddd71b4b1 HEAD`. Run at the release candidate revision before go/no-go (docs/release/consensus-commits.md:1, tools/ci/consensus_commit_gate.py).

## Plan and governance

- [ ] Mainnet has applied `v6.12.0` and not `v7.0`. Proof: `paxd q upgrade applied v6.12.0` and `paxd q upgrade applied v7.0` (docs/runbooks/paxeer-x-fork.md).
- [ ] The plan `info` JSON contains a non-empty `leaders` list, a `last_seq` of zero or absent, and `receipt_keys` covering `H+1`. The release tool generates it with `plan-info` and validates it with `plan-info --check <plan-info.json> --plan-height <H>`. Proof: the checked plan info file and its SHA-256 in the announcement (tools/release/upgrade_info.py:343–361, node/upgrades.go).
- [ ] Every explorer `keyId`, `publicKey`, `firstHeight` and `lastHeight` matches the governed plan. The explorer accepts non-zero 32-byte key IDs independently of public keys. Proof: compare every staged entry with the passed plan (services/explorer/backend/config/runtime.exs:315, services/explorer/backend/apps/explorer/lib/explorer/chain/paxeer_x/receipt_keys_config.ex:10–19).
- [ ] Every leader is an active validator's consensus key. Proof: compare with `paxd q staking validators` (node/process_proposal_proposer.go).
- [ ] Two reviewers signed the plan info. Proof: the review record (docs/runbooks/paxeer-x-fork.md).
- [ ] `H` is computed from measured block time and the live voting period. Proof: `paxd q gov params` and the block-time sample (docs/runbooks/paxeer-x-fork.md).
- [ ] The passed proposal matches the review. Proof: `paxd q upgrade plan -o json`, with name `v7.0`, height `H` and an `info` hash equal to the reviewed hash (node/upgrades.go).
- [ ] No `v7.0-anchor-store-delete` proposal is pending. The deletion handler requires the merge to have applied at a positive, strictly earlier height. Proof: `paxd q gov proposals --status voting_period` and the applied merge height (node/upgrades.go:222–225).
- [ ] A cancel proposal is drafted with its deadline. Proof: the draft `cancel-software-upgrade` command (docs/runbooks/paxeer-x-fork.md).
