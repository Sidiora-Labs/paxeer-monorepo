# Paxeer 7.0.0 readiness checklist

Every item must be ticked, with the evidence attached, before go/no-go 1 in the
[upgrade plan](7.0.0-upgrade-plan.md). Each item names the command or artifact that proves it and
ends with its source file. Items marked **Gap** cannot pass on main today.

Paxeer is one network on EVM chain ID `125` (`0x7d`). Public JSON-RPC uses
the root URLs of `api1` through `api14` under `mainnet-beta.paxeer.network`
and the canonical alias; there is no router path. See
[network identity and endpoints](../paxeer-network.md).

## Release identity and build

- [ ] `tools/release/version.json` reads `{"version":"v7.0.0","upgrade":"v7.0"}`. Proof: `jq . tools/release/version.json` at the tag (tools/release/version.json:2–3).
- [ ] `python3 tools/release/upgrade_info.py` accepts the plan name `v7.0`. Proof: the release build writes `upgrade-info.json` without error (tools/release/upgrade_info.py:27–38, tools/release/build-paxd.sh).
- [ ] The release identity check accepts `v7.0` through `MergeUpgrade`. Proof: the `Paxeer / Release Check` run on the tag commit is green (.github/workflows/paxeer-release-check.yml:65).
- [ ] `MergeUpgrade` is `v7.0` and `node/tags` ends with `v7.0`. Proof: `grep -n 'MergeUpgrade = "v7.0"' precompiles/common/precompiles.go` and `tail -1 node/tags` (precompiles/common/precompiles.go, node/tags).
- [ ] Tag `paxeer-network/v7.0.0` is signed and published. Proof: `git tag -v paxeer-network/v7.0.0` and the GitHub release page (RELEASE.md).
- [ ] `Paxeer / Release Publish` succeeded for the tag. Proof: `gh run list --workflow paxeer-release-publish.yml` (.github/workflows/paxeer-release-publish.yml).
- [ ] An independent rebuild matches. Proof: `tools/release/reproducible-check.sh` output and a diff of the two `SHA256SUMS` files (RELEASE.md, tools/release/reproducible-check.sh).
- [ ] The published files verify. Proof: `tools/release/verify-release.sh` exits 0 (tools/release/verify-release.sh).
- [ ] `paxd version --long --output json` reports `v7.0.0`, the tag's commit and the recorded `native_archive_digest`. Proof: the command output (tools/release/build-paxd.sh).
- [ ] The container image digest is recorded and its `paxd` matches `SHA256SUMS`, or validators are told to use only the release binary. The image workflow packages checksum-verified linux/amd64 release assets and records the digest. Proof: release notes and `sha256sum` of the `paxd` extracted from the image (.github/workflows/paxeer-docker-publish.yml:82–104, .github/workflows/paxeer-docker-publish.yml:110–121).
- [ ] A 7.0.0 consensus-commit ledger exists and passes its gate. Proof: `python3 tools/ci/consensus_commit_gate.py` (docs/release/consensus-commits.md:1–15, tools/ci/consensus_commit_gate.py).

## Release checks and rehearsal evidence

- [ ] Candidate release evidence covers custody release, receipt order, retired-surface refusals and aggregate rehearsal outcomes at one revision. Proof: the candidate release report and rehearsal logs described in the [upgrade plan](7.0.0-upgrade-plan.md#5-go--no-go-criteria). **Gap D5.**
- [ ] Golden-vector checks reproduce the expected outputs for supported native operations and refusals. Proof: golden comparison results in the candidate release report.
- [ ] Parity checks show that the supported SDK and native execution paths agree on results, balances and receipts. Proof: parity test results in the candidate release report.
- [ ] The retired-caller scan finds no active callers of removed surfaces. Proof: the scan output and reviewed caller inventory (tools/paxeer-x/tests/retired_callers_test.py, tools/paxeer-x/retired_callers.json).
- [ ] The four ordered rehearsal tests pass on the candidate: `TestMergeRehearsalFirstSequencedBlock`, `TestExportAfterMergeKeepsSequencerState`, `TestMergePlanActivatesGatedPrecompiles` and `TestAnchorStoreDeletedAtStep`. Proof: the CI test logs at the tag (node/merge_rehearsal_test.go, node/upgrade_export_test.go, node/upgrades_merge_activation_test.go, node/store_delete_test.go, docs/runbooks/paxeer-x-fork.md).
- [ ] Bond return and custody release tests pass. Proof: `TestMergePlanReturnsGuarantorBonds` and `TestReleaseRetiredMovesEveryCustodiedBalanceToTheAuthority` (node/upgrades_merge_bonds_test.go, modules/layerxcustody/keeper/release_test.go).
- [ ] Refusal tests pass. Proof: `TestMergePlanRefusesMissingMergeConstructors`, `TestRetiredWritesRevertAfterMerge` and `TestEveryAnchorSelectorRetired` (node/upgrades_merge_gate_test.go, precompiles/layerxanchor/retire_gate_test.go, precompiles/layerxanchor/retired_surface_test.go).
- [ ] A full rehearsal ran on exported mainnet state with the exact running binary, through the halt, the swap, `S` and a rollback leg. Proof: a rehearsal receipt from `tools/release/rehearsal/receipt.sh` (tools/release/rehearsal/receipt.sh, tools/release/rehearse-v6120.sh). **Gap D6.**
- [ ] The rehearsal shows the running binary halting with `UPGRADE "v7.0" NEEDED`. Proof: the rehearsal log (sdk/x/upgrade/abci.go).

**Source of truth:** The [merge specification](../../spec/layerx-merge/spec.kvx)
defines the release acceptance criteria. Attach results from the exact candidate
revision; the presence of a check in this list does not establish that it passed.

## Plan and governance

- [ ] Mainnet has applied `v6.12.0` and not `v7.0`. Proof: `paxd q upgrade applied v6.12.0` and `paxd q upgrade applied v7.0` (docs/runbooks/paxeer-x-fork.md).
- [ ] The plan `info` JSON contains a non-empty `leaders` list, a `last_seq` of zero or absent, and `receipt_keys` covering `H+1`. The release tool generates it with `plan-info` and validates it with `plan-info --check --plan-height <H>`. Proof: the checked plan info file and its SHA-256 in the announcement (tools/release/upgrade_info.py:343–361, node/upgrades.go).
- [ ] Every explorer `keyId`, `publicKey`, `firstHeight` and `lastHeight` matches the governed plan. The explorer accepts non-zero 32-byte key IDs independently of public keys. Proof: compare every staged entry with the passed plan (services/explorer/backend/config/runtime.exs:315, services/explorer/backend/apps/explorer/lib/explorer/chain/paxeer_x/receipt_keys_config.ex:10–19).
- [ ] Every leader is an active validator's consensus key. Proof: compare with `paxd q staking validators` (node/process_proposal_proposer.go).
- [ ] Two reviewers signed the plan info. Proof: the review record (docs/runbooks/paxeer-x-fork.md).
- [ ] `H` is computed from measured block time and the live voting period. Proof: `paxd q gov params` and the block-time sample (docs/runbooks/paxeer-x-fork.md).
- [ ] The passed proposal matches the review. Proof: `paxd q upgrade plan -o json`, with name `v7.0`, height `H` and an `info` hash equal to the reviewed hash (node/upgrades.go).
- [ ] No `v7.0-anchor-store-delete` proposal is pending. The deletion handler requires the merge to have applied at a positive, strictly earlier height. Proof: `paxd q gov proposals --status voting_period` and the applied merge height (node/upgrades.go:222–225).
- [ ] A cancel proposal is drafted with its deadline. Proof: the draft `cancel-software-upgrade` command (docs/runbooks/paxeer-x-fork.md).

## Validators and RPC nodes

- [ ] Validators holding more than two thirds of voting power, plus margin, reported the staged binary hash. Proof: the staging tally (docs/runbooks/paxeer-x-fork.md).
- [ ] Each host resolves every shared library of the new binary. Proof: `ldd paxd` (docs/runbooks/paxeer-x-fork.md).
- [ ] Each host has `sc-enable = true` and an inventory of all PaxDB directories. Proof: an `app.toml` excerpt (node/paxdb.go).
- [ ] Each host has disk headroom for a stopped backup. Proof: `du -sh` and `df -h` output (docs/runbooks/paxeer-x-fork.md).
- [ ] Pinned leaders staged `[sequencer]` with `enable`, `role`, `wal-dir` and `receipt-key-file`, and the receipt key file has mode `0600`. Proof: an `app.toml` excerpt and `stat -c %a` (node/sequencer/config.go).
- [ ] The primary and standby run the same binary hash. Proof: `sha256sum` on both hosts (docs/runbooks/paxeer-x-fork.md).
- [ ] At least one trusted node serves state-sync snapshots. Proof: `snapshot-interval` and `ss-enable` in its config (docs/runbooks/paxeer-x-fork.md).
- [ ] Cosmovisor users have `DAEMON_ALLOW_DOWNLOAD_BINARIES=false`, `DAEMON_RESTART_AFTER_UPGRADE=false` and the binary at `cosmovisor/upgrades/v7.0/bin/paxd`. Proof: the env and `ls` output (sdk/cosmovisor/args.go).
- [ ] The operators of `api1`–`api14` have a withdraw-and-restore plan for each upstream. Proof: the RPC operator sign-off (docs/paxeer-network.md).
