# Paxeer 7.0.0 validator runbook

This runbook takes a validator or full-node operator through the `v7.0` upgrade of Paxeer
mainnet-beta (Cosmos chain ID `hyperpax_125-1`, EVM chain ID `125`) with release
`paxeer-network/v7.0.0` (docs/runbooks/paxeer-x-fork.md, RELEASE.md). It condenses the
[merged-network validator runbook](../runbooks/paxeer-x-fork.md), which remains the reference
for inventory, backups and recovery; where the two differ, raise it before `H`. The schedule
and go/no-go rules are in the [upgrade plan](7.0.0-upgrade-plan.md).

Commands use placeholders. Load them from your own private inventory:

| Variable | Meaning |
| --- | --- |
| `PAXD_BIN` | Installed `paxd` path |
| `PAXD_HOME` | Node home |
| `PAXD_UNIT` | systemd unit for this home |
| `COMET_RPC_URL` | Local CometBFT RPC, for example `tcp://127.0.0.1:26657` |
| `COMET_RPC_PORT` | Local CometBFT RPC port |
| `EVM_RPC_URL` | Local root JSON-RPC URL, for example `http://127.0.0.1:8545` |
| `H` | Upgrade height from the passed proposal |
| `BACKUP_ROOT` | Backup directory outside the node home |

(docs/runbooks/paxeer-x-fork.md)

## 2. Pre-checks (by T−5 d)

1. **Chain state.** The chain has applied `v6.12.0` and has not applied `v7.0`:

   ```sh
   "$PAXD_BIN" q upgrade applied v6.12.0 --node "$COMET_RPC_URL" -o json
   "$PAXD_BIN" q upgrade applied v7.0 --node "$COMET_RPC_URL" -o json
   ```

   The first must show a height, the second none (docs/runbooks/paxeer-x-fork.md).
2. **Running binary.** Record `"$PAXD_BIN" version --long` and its SHA-256. The running binary
   must not itself register `v7.0`; the core team confirms this from the rehearsal on that exact
   binary (node/tags, node/upgrades.go).
3. **Signing identity.** Exactly one active signer per consensus key; map remote signers too
   (docs/runbooks/paxeer-x-fork.md).
4. **Storage.** `[state-commit] sc-enable = true` stays set; inventory `state-commit.sc-directory`,
   `state-store.ss-db-directory` and `state-store.evm-ss-db-directory`, including external mounts
   (node/paxdb.go, docs/runbooks/paxeer-x-fork.md).
5. **Disk.** Free space on each volume must hold a full stopped copy of every PaxDB directory plus
   growth to the next check. Measure with `du -sh` on each inventoried directory and `df -h` on
   its volume (docs/runbooks/paxeer-x-fork.md).
6. **Snapshot server.** At least one trusted node has `[state-sync] snapshot-interval` and
   `snapshot-keep-recent` set and `[state-store] ss-enable = true`, so lagging nodes can recover
   after `H` (docs/runbooks/paxeer-x-fork.md).
7. **Plan review.** After the vote, decode the scheduled plan and compare with the reviewed plan
   info published by the core team:

   ```sh
   "$PAXD_BIN" q upgrade plan --node "$COMET_RPC_URL" -o json \
     | jq -r '.info' | jq '{leaders: (.leaders|length), receipt_keys, activation_height, last_seq}'
   ```

   Require name `v7.0`, height `H`, a non-empty `leaders` list, `last_seq` zero or absent, and a
   receipt key whose `first_height` ≤ `H+1` ≤ `last_height` (node/upgrades.go). An `info`
   containing only `binaries` is wrong and the handler will refuse it; report it before the
   cancellation deadline (docs/runbooks/paxeer-x-fork.md).

## 3. Obtain and verify the binary

1. Download the release assets and check them:

   ```sh
   gh release download paxeer-network/v7.0.0 --repo Sidiora-Labs/paxeer-monorepo --dir paxd-v7.0.0
   (cd paxd-v7.0.0 && sha256sum --check SHA256SUMS)
   ```

   Every line must report `OK` (RELEASE.md).
2. Compare `SHA256SUMS` with the hash published in the validator announcement, and with an
   independent rebuild if you can run one on linux/amd64 with the pinned Go, Rust and C toolchains
   (RELEASE.md, tools/release/toolchain.env):

   ```sh
   git checkout paxeer-network/v7.0.0
   tools/release/build-paxd.sh
   diff paxd-v7.0.0/SHA256SUMS dist/paxeer-network/v7.0.0/SHA256SUMS
   ```

   An empty diff proves the published files are what the tag builds (RELEASE.md).
3. Install beside the running binary without replacing it, and inspect it:

   ```sh
   install -m 0755 paxd-v7.0.0/paxd-v7.0.0-linux-amd64 "$PAXD_BIN.v7.0"
   cp -p "$PAXD_BIN" "$PAXD_BIN.pre-v7.0"
   "$PAXD_BIN.v7.0" version --long --output json | jq '{version, commit, native_archive_digest}'
   ldd "$PAXD_BIN.v7.0"
   ```

   Require version `v7.0.0`, the tag's commit, and the `native_archive_digest` that the release
   build recorded; resolve every shared library, including the three `libwasmvm` libraries, before
   `H` (tools/release/build-paxd.sh, docs/runbooks/paxeer-x-fork.md).
4. The container image `ghcr.io/sidiora-labs/pax:7.0.0` packages the released linux/amd64
   binary and runtime libraries after checking them against `SHA256SUMS`; publication records
   the image digest in the release notes. Pin that digest and compare the extracted `paxd` hash
   with the release before using the image
   (.github/workflows/paxeer-docker-publish.yml:82–104, .github/workflows/paxeer-docker-publish.yml:110–121).

## 4. Sequencing configuration (pinned leaders only)

If your consensus public key is in the plan's `leaders` list, your node proposes sequenced
blocks from `H+1`, and proposals from validators outside the list are rejected
(node/process_proposal_proposer.go). Stage the `[sequencer]` section in `app.toml` with the
values rehearsed for your role (node/sequencer/config.go):

| Key | Value |
| --- | --- |
| `enable` | `true` on primary and standby |
| `role` | `primary` or `standby`, as agreed |
| `mode` | `sequential` unless micro-batching was separately qualified |
| `wal-dir` | Persistent path included in backups |
| `receipt-key-file` | Receipt signing key file, mode `0600`, whose public key is pinned in the plan |
| `standby-address`, `replication-timeout`, `replication-tls-*`, `replication-peer-*` | As rehearsed for the primary/standby pair |
| `nonce-queue-max-per-sender`, `nonce-queue-max-total`, `lease-duration` | Positive values |

(node/sequencer/config.go, docs/runbooks/paxeer-x-fork.md)

Primary and standby must run the same binary hash and use matching standby acknowledgement formats (spec/layerx-merge/docs/plans/activation-and-migration.md). Validators outside the
leader list keep `enable = false` (docs/runbooks/paxeer-x-fork.md).

## 5. Manual procedure at `H` (supported path)

The repository supports and rehearses a manual swap under systemd (docs/runbooks/paxeer-x-fork.md).

1. **Watch for the halt.** The running binary stops at `H` and logs:

   ```text
   UPGRADE "v7.0" NEEDED at height: H: {"leaders":[...],"receipt_keys":[...]}
   ```

   (sdk/x/upgrade/abci.go)

   ```sh
   journalctl -u "$PAXD_UNIT" -n 200 --no-pager | grep 'UPGRADE "v7.0" NEEDED'
   jq '{name, height}' "$PAXD_HOME/data/upgrade-info.json"
   ```

   Require name `v7.0` and height `H`. Do not create or edit this file
   (docs/runbooks/paxeer-x-fork.md).
2. **Stop and fence.** `systemctl stop "$PAXD_UNIT"`, disable automatic restarts, confirm the
   process and any remote signer are stopped, and record the signing high-water mark from
   `data/priv_validator_state.json` or the signer (docs/runbooks/paxeer-x-fork.md).
3. **Back up.** Take a stopped-node copy of configuration, genesis, `upgrade-info.json`, keys,
   signing state, every PaxDB directory and the sequencing WAL into `BACKUP_ROOT`; record sizes
   and hashes (docs/runbooks/paxeer-x-fork.md).
4. **Swap.**

   ```sh
   sha256sum "$PAXD_BIN.v7.0"
   install -m 0755 "$PAXD_BIN.v7.0" "$PAXD_BIN"
   ```

   (docs/runbooks/paxeer-x-fork.md)
5. **Start** with `systemctl start "$PAXD_UNIT"`. Coordinate so validators holding more than two
   thirds of voting power restart promptly (docs/runbooks/paxeer-x-fork.md).

### Cosmovisor

A cosmovisor build is vendored at `sdk/cosmovisor`, but the release does not publish it and the
merge procedure is not rehearsed with it (sdk/cosmovisor/args.go, docs/runbooks/paxeer-x-fork.md).
If you run it, the plan `info` is module genesis, not a download document, so automatic download
cannot work (docs/runbooks/paxeer-x-fork.md). Set `DAEMON_ALLOW_DOWNLOAD_BINARIES=false`, place the
verified binary at `$DAEMON_HOME/cosmovisor/upgrades/v7.0/bin/paxd` before `H`, and set
`DAEMON_RESTART_AFTER_UPGRADE=false` so you can take the stopped backup before starting
(sdk/cosmovisor/args.go). Rehearse this layout yourself before go.

## 6. What to watch in the logs

| Phase | Expected | Failure and meaning | Source |
| --- | --- | --- | --- |
| Old binary at `H` | `UPGRADE "v7.0" NEEDED at height: H: ...` | No halt: the running binary already handles `v7.0`; alert the core team | (sdk/x/upgrade/abci.go) |
| New binary startup | No store panic | `upgrade v7.0 is due at height H but the store loader did not add the v7.0 stores ...`: the node did not restart from `H−1` committed; do not edit files, report | (node/upgrades.go) |
| Block `H` | `applying upgrade name=v7.0` | Handler errors: `carries no leader list`, `want 0`, `pins no receipt key for first sequenced height`, `sequencer genesis`, `missing merge constructors or activation precompiles`, `executing plan differs from scheduled plan`, `retire anchor`, `release custody` | (node/upgrades.go) |
| Block `H` events | `layerx_anchor_retired` with `returned_bond`; one `EventRetiredRelease` per custody asset | Missing events: compare with rehearsal | (modules/layerxanchor/types/events.go, modules/layerxcustody/keeper/release.go) |
| Block `H+1` onward | Blocks proposed by pinned leaders | `proposer ... is outside the pinned leader list`: a non-leader proposed; expected for rejected rounds, a problem if every round fails | (node/process_proposal_proposer.go) |
| Every block | No `agent end block failed` | Scheduler job settlement errors; logged, not halting | (node/legacyabci/end_block.go) |

## 7. Post-upgrade verification

Run against your own node; a remote node cannot prove local health (docs/runbooks/paxeer-x-fork.md).

1. **Plan applied and module versions:**

   ```sh
   "$PAXD_BIN" q upgrade applied v7.0 --node "$COMET_RPC_URL" -o json
   "$PAXD_BIN" q upgrade module_versions sequencer --node "$COMET_RPC_URL" -o json
   ```

   Require applied height `H` and a sequencer module version (docs/runbooks/paxeer-x-fork.md).
2. **Block production:**

   ```sh
   curl -sS "http://127.0.0.1:$COMET_RPC_PORT/status" | jq .result.sync_info
   ```

   Require heights above `H+1`, `catching_up: false` once synced, and block and app hashes that
   match trusted peers (docs/runbooks/paxeer-x-fork.md).
3. **EVM chain ID and head:**

   ```sh
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' \
     --data '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' \
     --data '{"jsonrpc":"2.0","id":2,"method":"eth_blockNumber","params":[]}'
   ```

   Require `"result":"0x7d"` and an advancing height above `H` (docs/runbooks/paxeer-x-fork.md).
4. **Retired executors refuse.** The addresses stay registered and revert with `Error(string)`
   carrying `LXP_MODULE_DISABLED` and `<name> retired` (precompiles/common/retire.go):

   ```sh
   # layerxCustody depositCount() at 0x1013: must revert after H
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' --data \
     '{"jsonrpc":"2.0","id":3,"method":"eth_call","params":[{"to":"0x0000000000000000000000000000000000001013","data":"0x2dfdf0b5"},"latest"]}'
   # layerxAnchor latestFinalized() at 0x1014: still served between H and the deletion plan
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' --data \
     '{"jsonrpc":"2.0","id":4,"method":"eth_call","params":[{"to":"0x0000000000000000000000000000000000001014","data":"0x6cdd45ae"},"latest"]}'
   ```

   The first must return a JSON-RPC error whose revert data decodes to a reason containing
   `LXP_MODULE_DISABLED` and `layerxCustody retired`; the second returns data until
   `v7.0-anchor-store-delete` and reverts with `layerxAnchor retired` after it
   (docs/runbooks/paxeer-x-fork.md). For `0x1012` (`layerxVerify`), build calldata for any method
   from `precompiles/layerxverify/abi.json`, for example with `cast calldata`, and expect
   `layerxVerify retired` (precompiles/layerxverify/layerxverify.go). The selectors above are
   `depositCount()` and `latestFinalized()` from `precompiles/layerxcustody/abi.json` and
   `precompiles/layerxanchor/abi.json`.
5. **A `px_` call at the node root:**

   ```sh
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' \
     --data '{"jsonrpc":"2.0","id":5,"method":"px_getNetwork","params":[]}'
   curl -sS "$EVM_RPC_URL" -H 'content-type: application/json' \
     --data '{"jsonrpc":"2.0","id":6,"method":"px_getReceiptKeys","params":[]}'
   ```

   `px_getNetwork` must return `paxeer.chain_id` `0x7d`, a `latest_block` above `H`, and a
   `consensus` object with `catching_up` false (rpc/px_account.go). `px_getReceiptKeys` must list
   the keys pinned in the plan (rpc/sequencer_receipt.go).
6. **Merged precompiles live.** Use the release's activation evidence and checked-in ABIs for
   `0x101A`–`0x101E` and `0x0901`–`0x0908`; a bare no-argument call does not prove an interface
   works (docs/runbooks/paxeer-x-fork.md, node/upgrades.go).
7. **Controlled restart.** Restart once and repeat steps 1 to 3 before returning traffic
   (docs/runbooks/paxeer-x-fork.md).
8. **Report** halt seen, upgrade file identity, checksum, backup location, restart time and first
   signed and committed heights to the core team (docs/runbooks/paxeer-x-fork.md).

Public RPC operators (`api1` to `api14` and `api-mainnet-beta`) withdraw each upstream from the TLS
proxy before the swap and restore it only after steps 1 to 5 pass; JSON-RPC stays at the root
path (docs/runbooks/paxeer-x-fork.md, docs/paxeer-network.md).

## 8. Recovery

| Situation | Action | Source |
| --- | --- | --- |
| Before `H`, a go criterion fails | Governance `cancel-software-upgrade`; withdraw the staged binary only after `q upgrade plan` shows no plan | (docs/runbooks/paxeer-x-fork.md) |
| Handler refused at `H` | Keep the node stopped with data, WAL and signing state intact; wait for the coordinated repair binary; never use `--unsafe-skip-upgrades` or restart the old binary on migrated stores | (docs/runbooks/paxeer-x-fork.md) |
| `H` committed, defect found later | Forward recovery with a repair binary that understands committed state; same-chain snapshot restore is refused | (RELEASE.md, tools/release/rollback.sh) |
| Node lagging or corrupted, never signed | State sync from trusted upgraded nodes with a verified trust height and hash, keeping your own `node_key.json` | (docs/runbooks/paxeer-x-fork.md) |
| Validator host lost | Fence the old signer, recover state as a non-signing node, preserve the newest signing state, enable signing only above the highest signed height | (docs/runbooks/paxeer-x-fork.md) |
| Pinned leader lost | Fail over to the rehearsed standby with the same binary; do not run one receipt key or consensus key in two places | (docs/runbooks/paxeer-x-fork.md, node/sequencer/config.go) |

## 9. Later: anchor-store deletion

`v7.0-anchor-store-delete` deletes the `layerxanchor` store and makes every `0x1014` method
refuse; the address stays registered (node/app.go, docs/runbooks/paxeer-x-fork.md). It has its own
proposal, height, backup and acceptance checks, strictly after merge acceptance. The handler
enforces that order by requiring a positive applied merge height strictly below the current
height (node/upgrades.go:222–225). Check the proposal against those conditions.
