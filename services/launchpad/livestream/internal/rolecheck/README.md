The livestream service opens one database pool in `config.Config.OpenRuntimePool`, using the runtime login from its database configuration. `app.New` passes that pool to the connected lifecycle store, provider workers, restriction reader, market-cap reader and shared operation ledger. Production readiness uses the same pool.

`statements.json` lists each SQL call site with its file, function, ordinal within that function, statement kind, role, tables or views, sequences, functions and named columns. Serial defaults are included as sequence dependencies. Columns include names used by CTEs and catalog queries. SQL is read from the actual Go call expressions and constants, with the registered livestream schema substituted into formatted statements. The digest binds the object description to that text. The shared functions listed in `inventory.go` are the database functions called by the service's readiness and operation ledger paths. The service sweep includes lifecycle maintenance and operator methods that use that pool.

`TestRuntimeRoleStatements` creates a coordinator-owned database for `livestream_runtime` using `coordinatortest.Bootstrap`. It connects using the runtime login and resolves unqualified ledger names in the registered livestream schema. It requests `EXPLAIN (GENERIC_PLAN)` for parameterized SQL and `EXPLAIN` for other plannable SQL. Session statements execute inside transactions that are rolled back. Every statement is inspected; entries in `Waiting` identify object rights without asserting their plan outcome. Every other statement must be accepted. A coordinator database is required through `COORDINATOR_TEST_POSTGRES_DSN`.

The inventory excludes `internal/migrate` and the embedded `migrations` package: only the development startup runs their schema migrations. The DDL-returning methods in `internal/streams` describe coordinator migration input and are not called by the connected service. It also excludes `internal/db/sqlcdb`: the connected runtime replaces the legacy query dependency with lifecycle dependencies, and legacy routes do not invoke those queries. Shared authentication identity stores, audit delivery and delivery stores are not wired into this service; only the operation ledger and its audit append run on this runtime pool. Shared database provisioning, migration application and readiness recording belong to the coordinator, while runtime readiness reads are included.
