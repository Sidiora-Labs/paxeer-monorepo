# Issue 1632: [P2] Accept explorer-imported row IDs in node-root history

## Summary

The new node-root `px_getHistory` and `px_getUnifiedHistory` handlers reject a valid indexer page whenever it contains an explorer-imported row. The Go reader accepts only decimal row IDs, but the configured indexer's actual history route deliberately returns IDs such as `explorer:1`.

Introduced by [745659e6d62d69b4f1aa8b2afd12d6b2bf7982f2](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/745659e6d62d69b4f1aa8b2afd12d6b2bf7982f2), task 22.34.3. Rechecked against main at `f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb`; the affected Go reader and producer are unchanged.

## Expected versus actual

Expected: Node-root history accepts both indexer ID forms, retains the ID as a string, and preserves the indexer's ordering and cursor behavior.

Actual: [rowFrom](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/src/modules/history/indexer.go#L172-L187) validates `id` with `decimal(..., 64)`. `explorer:1` makes `idOK` false, so the whole page is rejected. [Client.Page](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/src/modules/history/indexer.go#L253-L262) propagates that error; [the RPC handler](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/rpc/px_history.go#L17-L34) returns `-32001 / History unavailable / data.code=invalid_indexer_response`.

## Source-derived reproduction and impact

1. Import a historical transfer for an EVM account through the existing indexer `Store::import_explorer` path.
2. Read that account through `GET /v1/history/{account}`; the returned page contains an `explorer:<n>` ID.
3. Configure the node to use that indexer and call either node-root history method for the account.
4. The Go decoder rejects the ID and returns the unavailable error above, instead of the valid history page.

This affects normal accounts with backfilled explorer history. An affected page cannot be traversed through the new node API. No data mutation or financial loss is claimed.

## Acceptance criteria

- Accept validated decimal and `explorer:<decimal>` row IDs without stripping their namespace.
- Preserve indexed-before-imported and numeric-ID ordering at equal positions when merging.
- Add a regression using a page produced by the real indexer with both imported and ordinary rows, exercised through node-root HTTP and WS history. Verify paging to the end without missing or repeating rows.
- Continue rejecting malformed IDs.
