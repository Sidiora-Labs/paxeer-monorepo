# Issue 1810: [P2] Decode the node catalogue in the wallet SDK after routing discovery to the node

## Expected and actual

After 6cfc7652ced4aa7499c9d02fcc6a23653a642a47, EndpointClient.getRouteCatalogue() requests px_getRouteCatalogue from the node root. It still passes that result to the hosted-catalogue decoder. The node and decoder disagree on required fields and readiness structure, so the typed SDK call rejects a valid node response rather than returning discovery data.

This is a P2 functional interface regression. No deployed-service or funds impact is claimed.

## Source evidence

Reviewed at main commit 12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df:

- [getRouteCatalogue uses this.rpc](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/sdk/wallet/src/endpoint.ts#L97-L99), which is built from nodeUrl/url at [lines 44–49](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/sdk/wallet/src/endpoint.ts#L44-L49).
- [The decoder](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/sdk/wallet/src/endpoint.ts#L464-L560) requires canonical_origin, exactly 31 services, upstream/health_predicate service fields, upstream route fields, and readiness.complete plus readiness.services.
- [The node catalogue generator](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/rpc/generate_px_catalogue.py#L6-L29) omits canonical_origin, includes only product services, omits upstream/health_predicate from service entries, and strips upstream from routes.
- Independently of the generated JSON contents, [the runtime producer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/rpc/px_discovery.go#L61-L78) assigns readiness to a flat service-ID map with a node_rpc entry. It does not return the nesting the decoder requires.
- [Node tests](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/rpc/px_node_root_account_test.go#L309-L325) explicitly assert flat readiness and stripped upstream fields. The added wallet repair test exercises this method only through [raw batch routing](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/12ca7af6a4ddd5034ba93c76f0486eef7ea7e8df/sdk/wallet/test/repair-22-31-591.test.ts#L138-L171), bypassing the typed decoder.

## Suggested repair and regression test

Give node discovery an explicit supported response contract and update the typed SDK reader accordingly. Preserve the public projection and its unknown hosted-dependency readiness; do not restore private upstream fields or falsely mark dependencies ready to satisfy the old decoder.

Add a cross-boundary test using the actual node catalogue projection and runtime readiness shaping, then invoke EndpointClient.getRouteCatalogue(). It should decode successfully with and without hostedUrl. Keep malformed response validation.
