# Issue 1598: [Coherence] The ABI-5 switch tasks change Programs receipts to module_version 5, but the Rust proof verifier and the Go lifecycle verifier still accept only 4

## Defect and impact

Decision 2516, 1.23.7 and 5.99.1 make every Programs receipt on the hosted kernel carry module_version 5 after the merge upgrade. The decision says the Go receipt decoders accept both versions, and no task changes any other verifier. At the state-commitment protocol, the Rust proof crate accepts exactly SANDBOX_DESTROY (4). Its generated ABI table only collects enumerators ending in ABI_VERSION, so it never picks up LX_PROGRAMS_GUEST_ABI_V5_VERSION. The Go VerifyProgramLifecycleReceipt also hard-codes ModuleVersion != 4. After the upgrade, the agent daemon's proofs and SDK lifecycle verification would refuse every Programs receipt.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: The switch should include, or require, changes that make the Rust layerx-proof/layerx-types version check and Go VerifyProgramLifecycleReceipt accept module_version 5 at protocol 3, with vectors for both versions.

Actual: No task touches these verifiers, and the decision says the Go decoders already accept both versions, which verify.go:200 shows is not true.
