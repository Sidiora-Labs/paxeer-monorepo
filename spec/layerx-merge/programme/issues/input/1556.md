# Issue 1556: [P2] Reconcile agent event ingestion with sequencer logs that have no block hash

## Expected versus actual

The event ingestor port in [3cb44ec](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/3cb44ec2b2e4190e388f7f80163b2b2dff3dcc6e) consumes NodeSubscription logs, but refuses the actual sequencer's receipted log format.

Expected: the supported subscription and ingestion boundary agree on how receipted versus committed logs are handled.
Actual: the sequencer emits a receipted log with seq and blockHash:null, while the new decoder requires a 32-byte block hash. EventIngestor.read_log consumes that notification and returns InvalidLog before queueing it.

## Both sides of the contract

- [Client subscription request](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/services/agent/crates/layerx-client/src/subscription.rs#L67-L86) is eth_subscribe logs with optional address/topics, with no blockHash or committed-only selector.
- [Server wiring](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/rpc/server.go#L505-L520) attaches the sequencer receipt feed. [Subscription selection](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/rpc/subscribe.go#L304-L334) uses that feed for this request.
- [FilterLog.MarshalJSON](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/rpc/filter.go#L463-L489) explicitly emits blockHash:null when Seq is present, because the transaction is receipted but not committed.
- [read_log and ingest_log](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/services/agent/crates/layerx-agentd/src/events/ingest.rs#L701-L724) pass that notification into CoreEvent construction.
- [decode_log](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/services/agent/crates/layerx-agentd/src/events/ingest.rs#L663-L698) unconditionally decodes blockHash as fixed bytes. Null cannot satisfy log_bytes' string requirement.
- [CoreEvent construction](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/7a79677b38ae7a4b2f411311883e680574f06312/services/agent/crates/layerx-agentd/src/events/ingest.rs#L621-L640) also initializes BATCH_INCLUDED rather than deriving the event's actual commitment state. Merely substituting zero bytes for the missing hash would not be a correct repair.

Current source rechecked at 7a79677b38ae7a4b2f411311883e680574f06312. The intervening historical-admission fixture change does not repair these paths.

## Concrete validation (not executed)

1. Extend the new ingest_eth_subscribe fixture to emit the JSON produced by the real FilterLog marshaler for a receipted event: valid blockNumber, transactionIndex, logIndex, address, topics and data, plus seq and blockHash:null.
2. Connect with the supported Logs subscription and call EventIngestor.read_log.
3. Current source returns InvalidLog before queueing. The committed-shaped mock with a non-null hash does not expose the mismatch.
4. Exercise the corresponding committed/backfill representation and verify correct cursor identity and deduplication.

## Impact and limits

This proves a fail-closed mismatch in the exported ingestion path. Searches found the read_log API and tests; no production caller occurrence or deployed event loss is asserted. No tests, builds, node or WebSocket runtime calls were executed for this report.

## Acceptance

- Define and implement correct handling of the sequencer's receipted log shape, or use an explicitly compatible committed-log source with a proven recovery path.
- Preserve the actual verification rung. Do not invent a block hash or label a receipted event committed merely to satisfy the decoder.
- Add producer-shaped subscription/ingestion coverage, including committed recovery, cursor ordering and no duplicate delivery.
- Preserve malformed-log refusal.
