# Issue 1893: [Coherence] The ledger is declared complete while it leaves out the commits that change the upgrade plan handlers in node/upgrades.go

## Defect and impact

The commit claims to complete the 7.0.0 consensus-commit ledger and ticks the readiness item. But the gate's CONSENSUS_PATHS does not include node/upgrades.go, the file where the ledger itself says both plans are registered. Seventeen commits in the 68c8887a..8c5a7acd range change that file, and only the ones that also touch another listed path got a row. For example, 74b284ed2b (makes the anchor store delete plan refuse unless the merge plan was applied at a lower height) and 1db0093cc6 (generates and checks the merge plan info the node decodes at the upgrade height) both change upgrade-handler behaviour and have no row. The narrow path list was there before, but this commit turns it into a claim of completeness and closes the release item.

Kind: semantic. Severity: major.

Expected: Every commit in the range that changes consensus behaviour gets a row, including changes to the upgrade plan handlers. That means adding node/upgrades.go to the gate's path list and regenerating the rows.

Actual: Commits that change only node/upgrades.go, such as 74b284ed2b and 1db0093cc6, are missing from the ledger, yet the gate passes and the checklist calls the ledger complete.
