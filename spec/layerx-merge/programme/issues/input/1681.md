# Issue 1681: [Coherence] The clean-checkout corpus test no longer checks that the generated corpus excludes the retired budget pull, even though the repair claims to keep that check

## Defect and impact

The removed subcase ran the layerx-wire registry test against the generated replay corpus. That was the only consumer-side check that activity 0x0003000B (Budget ordinal 11, the retired budget pull) is absent from the bytes on disk. The replacement EIP-1559 round trip runs against the root SDK and never reads the corpus. The only exclusion evidence left is a log line that the generator prints unconditionally after it filters, so a generator that wrote the pull into the corpus would still pass. The new preservation test treats the presence of that log string as the exclusion check.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: After regeneration, the clean-checkout test reads the generated replay corpus and asserts that activity 0x0003000B is not in it, so the exclusion is checked on the output and not just in the generator's log.

Actual: No test reads the generated corpus to check for the budget pull any more. The exclusion is checked only through the generator's own unconditional log message.
