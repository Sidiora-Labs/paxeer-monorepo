# Issue 1647: [P2] Preserve cancellable subscription handshakes across 50 ms polls

## Problem

The cancellation support added in [1acab361](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/1acab3615a57d104083c0a3adfcc106643aae38e) makes a healthy subscription fail after the first 50 ms handshake wait whenever the caller supplies a cancellation flag, even if that flag remains false and the requested timeout is several seconds.

Rechecked at main [263eb04b](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f). This is a Rust client availability/API regression. No deployed failure, chain execution, transaction, or security impact is asserted.

## Source trace

- [DeadlineTcp::prepare:111–126](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f/services/agent/crates/layerx-client/src/subscription.rs#L111-L126) caps socket I/O at 50 ms whenever `cancellation.is_some()`, regardless of whether the flag is set.
- [subscribe_with_options:218–230](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f/services/agent/crates/layerx-client/src/subscription.rs#L218-L230) gives that adapter to `client_tls_with_config`, then immediately returns `Unavailable` for `HandshakeError::Interrupted`. It drops the resumable handshake instead of treating this as a cancellation-poll interval. A timeout represented as a failure also maps to `Unavailable`.
- [Cargo.toml:20](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f/services/agent/crates/layerx-client/Cargo.toml#L20) pins tungstenite 0.29.0. That version's [handshake machine](https://github.com/snapview/tungstenite-rs/blob/c2921718b76f0ed8c69a895397ed981e4a321f6f/src/handshake/machine.rs#L42-L102) preserves a blocked operation, and [MidHandshake::handshake](https://github.com/snapview/tungstenite-rs/blob/c2921718b76f0ed8c69a895397ed981e4a321f6f/src/handshake/mod.rs#L33-L50) returns it as `Interrupted` on WouldBlock.
- In contrast, the client's [receive loop:359–375](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f/services/agent/crates/layerx-client/src/subscription.rs#L359-L375) retries poll timeouts while the absolute deadline remains. The handshake path lacks that handling.
- The new [cancellation test:563–588](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/263eb04bfc4c6c0cd0105dad5e94ffe9001ad87f/services/agent/crates/layerx-client/tests/repair_22_33_1541.rs#L563-L588) completes ordinary `subscribe` before enabling cancellation for `next_with_options`, so it cannot detect the establishment failure.

## Concrete validation

Source-derived reproduction, not executed:

1. Start a local TCP listener. Accept the connection, wait 150 ms, then complete a real `tungstenite::accept` WebSocket handshake and serve the subscription response.
2. Call public `subscribe_with_options` on its loopback URL with `SubscriptionTopic::NewHeads`, a 2-second timeout, and `Some(Arc::new(AtomicBool::new(false)))`. Leave the flag false.
3. Expected: the valid handshake and subscription succeed within the 2-second budget.
4. Actual source path: the first idle handshake read reaches the 50 ms poll timeout and returns `SequencerError::Unavailable`, before the server's valid response. The equivalent call without a cancellation flag retains the full deadline and can succeed.

Use the real local peer and public client API for the regression, with enough timing margin. No public endpoint is needed.

## Acceptance criteria

- Preserve handshake progress across cancellation-poll timeouts while the flag is false and the absolute deadline has not elapsed. Handle the platform's timeout/WouldBlock representation without restarting or duplicating the handshake.
- Add the delayed-handshake success case above, plus actual cancellation and deadline-expiry cases during establishment.
- Preserve the existing total-deadline bounds for control traffic, notification waits, and unsubscribe; do not remove cancellation or weaken the existing assertions.
