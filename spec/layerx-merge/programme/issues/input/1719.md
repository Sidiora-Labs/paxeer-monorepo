# Issue 1719: Restore token category filters on browser history navigation

## Summary

The new token-market category chips introduced by [bca01ee3](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/bca01ee3e28e0a69f01a723820305b04c4e35c05) push URL history, but the selected token types are initialized from the URL only on mount. At [640b2564](https://github.com/Sidiora-Labs/paxeer-monorepo/tree/640b25642b1c4703cbd7cc4692a18c0123181fb9), [local state drives the API filter](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/640b25642b1c4703cbd7cc4692a18c0123181fb9/apps/explorer/ui/pages/Tokens.tsx#L39-L54), while [chip handlers push history](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/640b25642b1c4703cbd7cc4692a18c0123181fb9/apps/explorer/ui/pages/Tokens.tsx#L77-L130). The [component key](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/640b25642b1c4703cbd7cc4692a18c0123181fb9/apps/explorer/ui/pages/Tokens.tsx#L201-L204) changes only for bridged versus all, so switching category history does not remount it.

## Validation

On the token markets page, click Fungible, then NFT, then use browser Back. Expected: the restored Fungible URL, selected chip and API filter agree. The source predicts the NFT local state and query remain selected despite the restored URL. The mount-only state design predates this commit; the new chips expose it through their navigation. Existing [tests](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/640b25642b1c4703cbd7cc4692a18c0123181fb9/apps/explorer/ui/tokens/repair-22-35-5.spec.tsx#L71-L92) cover forward clicks with a push stub, not Back/Forward history.

This is source-verified only; no browser or test run was performed.

## Acceptance criteria

- Keep selected category and API filter synchronized with URL changes, including browser Back and Forward.
- Add history-navigation coverage for Fungible and NFT transitions, preserving bridged/all behavior and existing query parameters.
- Avoid unnecessary duplicate requests or history entries during synchronization.
