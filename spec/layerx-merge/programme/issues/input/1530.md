# Issue 1530: [Coherence] wasmtime stays on 34.x because the direct workspace dependency in tools/wasm-tools/Cargo.toml was not raised, which do_2 requires

## Defect and impact

do_2 says that when a floor cannot be reached without raising a direct dependency, the task raises that dependency in the manifest. wasmtime is a direct workspace dependency in tools/wasm-tools/Cargo.toml, pinned at 34.0.1. The commit leaves it there, so the lock still resolves 34.0.2, below the 36.0.8 floor. It records this as owned by 'vendored upstream' and calls the task 'lockfile-only', but the spec says the manifest change belongs to this task and that a breakage should go in the qualification note rather than the fix being skipped. The bridge manifest's direct pin libsecp256k1 = "=0.6.0" was handled the same way, and it is what holds rand at 0.7.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: workspace.dependencies.wasmtime is raised to the lowest version that resolves at or above 36.0.8 (and libsecp256k1 likewise where a patched release exists), the lock is regenerated, and any build breakage is recorded in the qualification note.

Actual: The manifests are unchanged, wasmtime resolves 34.0.2, and the unmet floor is labelled an upstream finding.
