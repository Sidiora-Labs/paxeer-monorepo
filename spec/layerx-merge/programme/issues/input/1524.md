# Issue 1524: [Coherence] The new standalone sdk/wallet/pnpm-lock.yaml makes the vitest floor pass against a lock no build uses, while the lock that is actually installed still resolves the advised vitest 3.2.7

## Defect and impact

The floor checker resolves package.json through the nearest ancestor lock, so the newly added sdk/wallet/pnpm-lock.yaml (vitest 4.1.12) satisfies the sdk/wallet vitest>=4.1.11 floor. But sdk/wallet is installed only through the services/wallet workspace, whose lock still resolves vitest 3.2.7 (and 2.1.9) for that importer. The task says every resolved copy must meet its floor, so the advisory stays open in the dependency tree that is actually installed, and the floor check reports success.

Kind: semantic. Severity: major.
