# Issue 1754: [Coherence] Task 22.31.564 tells the Rust runtime to add a replay fuel total to the replay record, but the kernel parses that record at fixed offsets and is not in the task's paths

## Defect and impact

Decision 2649 and task 22.31.564 do_1 ask for the replay fuel total to be recorded in the replay record so a verifier can recompute it. The task may only touch Rust runtime files (host/mod.rs, replay_record.rs, commit.rs, execute.rs, ffi_call.rs). The C kernel decodes the record the runtime publishes field by field: version 1, fixed header offsets, then a witness length that must equal everything left in the buffer. A new field written in the declared paths would make every profiled CALL fail with LXP_ERR_NON_CANONICAL or VERSION_UNSUPPORTED in layerx_programs_call_replay_record_finish, which is the opposite of what 22.99.77 is waiting for.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: Either the task paths include the kernel record decoder (call.c replay_record_finish, plus the state_record.c layout if the staged record changes) and their tests, or the fuel total goes somewhere the kernel does not parse.

Actual: The task orders a record layout change while forbidding changes to the only decoder of that layout. Following the spec as written breaks every profiled CALL at the kernel boundary.
