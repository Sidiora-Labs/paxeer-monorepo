# Issue 1853: [Coherence] Narrowing the touches leaves three tasks that retire baseline entries with no declared path for the baseline file they must edit

## Defect and impact

Decision 2890 removes the tests/ci/data directory touch from every baseline-family task. The producer tasks now name their new baseline file in planned_paths. But the consumer tasks that must delete entries from that same file (22.39.145, 22.39.117 and 22.39.144) lost the directory touch and got no file-level touch or planned path in its place. Under the path policy that every task carries (a task touches only the paths it declares), each of these tasks must now either leave its baseline untouched or edit an undeclared path. Either way its own do_ step that retires the baseline entries cannot be met within scope.

Kind: connective. Severity: major.

Expected: Each consumer task names the baseline file it edits, as decision 2890 requires ("names that file in touches"). Where the touch-must-exist rule blocks that at plan time, the task keeps the directory entry, or the touch is added once the producer lands, the way 22.39.92 is handled.
