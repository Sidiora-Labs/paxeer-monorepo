# Issue 1753: [Coherence] evidence_inventory now refuses every version-1 evidence record, so the legacy with_evidence branch can never be filled and tenants with old evidence fail recovery outright

## Defect and impact

The new pre-check in evidence_inventory calls check_evidence_version on the public evidence key, and that check accepts only version 2. persist_evidence still writes version-1 records to that same public key, and serve_kernel_evidence (a few lines below) explicitly accepts version 1 there and returns it as with_evidence. As a result, any tenant that holds a version-1 record now gets EvidenceVersion for its whole inventory instead of a populated with_evidence list. The mixed-format recovery added in 22.31.559, and its production consumers in managed_agent and human_runtime, depend on that list.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: The inventory should keep sorting version-1 public evidence into with_evidence, as serve_kernel_evidence, persist_evidence and the 22.31.559 mixed-format recovery assume. It should refuse only records that really are stale, such as unknown versions or legacy-archive entries.

Actual: Any version-1 record under the public evidence key now makes evidence_inventory return EvidenceVersion for the whole tenant. The with_evidence branch is unreachable, and the tests and production paths that recover legacy evidence fail.
