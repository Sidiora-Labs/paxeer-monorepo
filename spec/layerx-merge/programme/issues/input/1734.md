# Issue 1734: [Coherence] Gotcha 3188 and do_12 say read_before_deadline turns every transport failure into None, but it passes errors on unless the deadline has already run out

## Defect and impact

The new guidance says read_before_deadline reports any transport failure inside the deadline as None. That is how it explains a peer-thread panic showing up as Pending. In the code, None is returned only when the remaining deadline is zero, before or after the call. Any transport or remote error that comes back while time remains is passed on to the caller. A peer that crashes and drops its socket would surface as Transport, not Pending. Only a call that hangs until the deadline is turned into None.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: The record should say that only a call still unanswered when the deadline expires becomes None, and that any other transport failure surfaces as an error.

Actual: The record says every transport failure inside the deadline is masked as None, which points the investigation the wrong way.
