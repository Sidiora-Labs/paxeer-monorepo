# Issue 1702: [Coherence] Legacy Rsync now kills any segment transfer that takes longer than five minutes, and the push path has no way to raise that limit

## Defect and impact

`Rsync` now goes through `RsyncContext` with the default `Transfer` timeout of 5 minutes. That timeout is a deadline on the whole operation, and it also covers the durability acknowledgment. The push CLI builds its session with `NewSSHSession`, which takes no timeout options, so every push and sync transfer is capped at 5 minutes. Value files default to a target size of about 4 GiB, and the throttle is split across threads. Any throttled or large segment transfer is therefore killed with SIGKILL and reported as a failure every time it runs, so push and sync of large tables can never succeed.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Whole-file transfers should be bounded by an idle or progress timeout, or by a limit that callers can configure and that grows with file size and throttle. Existing push and sync callers should keep working for large segments.

Actual: Each transfer has a fixed 5-minute wall-clock deadline that cannot be configured through NewSSHSession. Transfers that run longer are killed and reported as rsync failures.
