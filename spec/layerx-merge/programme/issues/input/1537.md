# Issue 1537: [Coherence] The VerificationStatus declaration is added only by the Rust sdkgen splice, so generate_jvm.py --check now rejects the committed GeneratedSchema.java and platform-sdk-check fails

## Defect and impact

GeneratedSchema.java has two generators. generate_jvm.py writes the file, and sdkgen now splices a hand-templated VerificationStatus record into it. generate_jvm.py was not changed and still never emits VerificationStatus, so its own `--check` mode compares the committed file with output that lacks the record and fails with 'generated JVM schema is stale'. That check is the second step of `make platform-sdk-check` and of the prebuilt JVM conformance runner. The commit fixes the dangling type reference, but it breaks the platform SDK drift gate on main, and the two generators now disagree about what the file should contain.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Exactly one generator emits VerificationStatus, preferably generate_jvm.py's render_models from [record.VerificationStatus]. With that, generate_jvm.py --check and sdkgen --check both accept the committed GeneratedSchema.java.

Actual: Only sdkgen's post-processing adds the record. generate_jvm.py --check reports the committed file as stale, so `make platform-sdk-check` and run-jvm.sh --prebuilt fail at this revision.
