# Issue 1821: [P2] Align Compose image tags with local cluster and CI producers

## Summary
The image namespace change in [commit 55854228](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/55854228e7a459ec35d93e2b5b62490450cac403) (spec:layerx-merge/22.39.111) changes the local cluster's Compose image contract without updating its callers and producers. This is a local development/integration CI regression, not a demonstrated production or security incident.

## Source evidence
Reviewed at `450b0b318c1864ed886e45117b56ae9aa7f5522d`; Compose and Make source were rechecked unchanged at current main `ebb6937263e29874c5292aded2ba2fddeb7a13c9` on November 7, 2026, 15:47 UTC.
- [Compose node images](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/docker/docker-compose.yml#L2-L7) require LOCALNODE_IMAGE_TAG and use ghcr.io/sidiora-labs/localnode; [x-websearch](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/docker/docker-compose.yml#L127-L135) additionally requires X_WEBSEARCH_IMAGE_TAG.

Its environment helper exports GHCR_LOCALNODE/GHCR_LOCALNODE_RUN_IMAGE, not LOCALNODE_IMAGE_TAG.

## Expected behavior
The documented local-cluster targets should resolve the exact image they build, and the CI target should resolve the run-specific image pulled by its prepare step, without requiring undocumented tags.

## Actual behavior and reproduction
In a clean checkout with neither image-tag variable set, the documented cluster start and integration start reach a Compose interpolation error in their stop prerequisite rather than starting the cluster. Standalone stop has the same issue. Supplying arbitrary tag values alone does not reconnect the node images: Compose requests ghcr.io/sidiora-labs/localnode:<tag>, while the local build and CI retag produce pax-chain/localnode.

A safe config-only reproduction on a machine with Compose is:
`env -u LOCALNODE_IMAGE_TAG -u X_WEBSEARCH_IMAGE_TAG docker compose --env-file /dev/null -f docker/docker-compose.yml config --images`
Then render with explicit values and compare node image names with chain.mk and the integration workflow's tags.

This report is source-verified. Docker is absent from the review environment, so Compose rendering, builds, and cluster execution were not run.

## Acceptance criteria
1. Local start, skipbuild, CI start, monitoring/mixed overlays, and stop all receive a consistent explicit image identity contract.
2. The resolved node image equals the image built locally or pulled for that CI run; simply adding tag variables must not leave the repository-name mismatch.
3. Add a config-only regression test using the real caller environment and compare rendered image names with the producer/retag contract, alongside the namespace checks.
4. Keep the explicit-tag policy, and update documented inputs if any remain caller-supplied.
