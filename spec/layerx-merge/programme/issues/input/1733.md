# Issue 1733: [Coherence] Decision 2631 and the 22.33.1569 attempt-6 repair blame the 60-second Pending on missing node commit trust, but the SDK returns MissingFinalityTrust straight away in that case and never waits it out as Pending

## Defect and impact

Gotcha 3188, decision 2631 and do_12 of 22.33.1569 say that receipt_at_commitment refuses a Batched receipt with no node commit trust, and that this explains the RpcError::Pending seen after 60 seconds. In the SDK, MissingFinalityTrust is a hard error. The wait loop does not retry it, so it reaches the caller on the first committed poll. A wallet without the trust would fail fast with MissingFinalityTrust, not time out as Pending. Installing the authority, as the attempt is told to do, will not touch whatever is actually keeping the receipt pending: a rung that never reaches committed, repeated -32001/-32005 answers, or a px_getCommit/eth_getBlockByNumber read that blocks until the deadline.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: The repair task should start from causes that can actually produce Pending after the full deadline: a rung that never reaches committed, repeated -32001/-32005 remote answers, or a read that blocks until the deadline. Missing trust would show up as MissingFinalityTrust.

Actual: Decision 2631 and do_12 tell the attempt to install node commit authority as the fix for a symptom that missing authority cannot cause, so the real cause stays unaddressed.
