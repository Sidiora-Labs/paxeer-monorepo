# Issue 1925: [Coherence] The bridge relayer and its deployment manifests still require a five-member attestor set at threshold three, so they cannot run against the governed one-of-one signer set this commit wires into every chain

## Defect and impact

This commit sets all nine chain configurations to one signer at threshold 1, matching the manifest. The relayer has the set size fixed at 5 and the threshold fixed at 3, and it refuses any membership that does not have exactly five distinct members at threshold 3. The container entrypoint also checks the approved membership against the 5/3 values in relayer-1..5.toml. With the governed membership, every relayer instance fails at startup, so no release attestation can be produced. The release runbook still reports no open gaps, and spec.kvx has no task that changes the relayer constants.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: Once the governed signer set is one address at threshold 1, the relayer's set-size and threshold rules, the five relayer deployment manifests and the signer-key renderer should accept that set. If that work is pending, the runbook should list the relayer as an open gap.

Actual: The chain configurations and manifest say 1-of-1, but the relayer code, entrypoint and deployment manifests only accept 5-of-3. This commit also removes the last gap row from the runbook.
