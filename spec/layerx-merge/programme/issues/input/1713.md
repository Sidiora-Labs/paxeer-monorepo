# Issue 1713: Web-search exact-payment adapter rejects valid two-log receipts

## Summary
At [ebb7357e](https://github.com/Sidiora-Labs/paxeer-monorepo/tree/ebb7357e2543a9b0923fabad512ed3541102829c), the optional web-search exact-payment log adapter introduced by [cb501805](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/cb50180548c81a93044fcc5883195a0670f127f4) [requires exactly one total receipt log](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/services/agent/sdk/typescript/src/web-search.ts#L405-L421). Current Ledger `payExact` [emits a Transfer followed by PaymentExact](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/modules/layerxledger/keeper/events.go#L74-L100); its [producer test expects both](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/precompiles/layerxledger/payments_test.go#L231-L241), and the [receipt RPC retains all logs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/rpc/sequencer_receipt.go#L602-L633).

## Validation
Supply a genuine valid `payExact` receipt, raw transaction and the full RPC log list through `WebSearchExactLogPayment`, as the [SDK test adapter forwards receipt.logs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/services/agent/sdk/typescript/test/web-search.test.ts#L167-L179). Expected: a valid matching payment proceeds to header preparation. Actual from the source guard: a two-log receipt is rejected with receipt-offer-mismatch before header delivery. Existing historical test recordings contain only one log, so they do not exercise this producer shape.

This is a source-verified compatibility mismatch; no test or transaction was executed in this review. No deployment impact or signature-verification bypass is established.

## Acceptance criteria
- Accept exactly one matching PaymentExact event within the complete receipt log list, rather than requiring one total log.
- Preserve receipt signature, calldata, payer, payee, asset, amount and reference validation, and reject duplicate matching payment events.
- Add a positive regression using a current producer-derived Transfer plus PaymentExact receipt and retain negative cases.
