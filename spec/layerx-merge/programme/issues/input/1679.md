# Issue 1679: [Coherence] The live-transfer socket and the new-items notice still follow the server page, not the page the user is looking at

## Defect and impact

The new useTokenTransferPages hook splits one server response into several display pages and returns its own display pagination. TokenTransfer still uses the raw server `pagination.page === 1` to keep the socket subscription open and to show the new-items notice. With 25 rows per page, display pages 2 and 3 both come from server page 1, so the 'N new transfers' notice appears and live counts keep arriving on pages that are not the head of the list. Before this commit, server page 1 and the first display page were always the same, so the problem did not exist.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: The socket subscription and both new-items notices should be active only on the first display page (`displayPagination.page === 1`).

Actual: They stay active on every local subpage of server page 1, such as display pages 2 to 4 when 25 rows are shown, so new-transfer notices appear in the middle of the list.
