# Issue 1749: [Coherence] The reopen test proves 'no second transfer' with a payout effect it builds itself, not the effect the replay produced

## Defect and impact

After reopening, the test replays each stored request through dispatch. It then builds RewardEffect::AlreadyApplied by hand and passes it to value_adapter::plan. That function returns ValueAction::None for AlreadyApplied whatever the ledger says, so the assertion can never fail, and the effect the replay actually produced is never planned. The checks on the stored result, event and plan only re-read keys the test wrote and nothing rewrites, and no recipient balance is checked. So the claim that a recipient is paid exactly once after restart is not established.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Replaying after reopen should take the effect and value plan from the production replay path, ideally through rewards::apply on the reopened state, and assert that it plans no transfer and that the recipient balance is unchanged.

Actual: The replay effect is invented by the test, and the persisted records the test checks are written and read only by the test.
