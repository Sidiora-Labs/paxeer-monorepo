# Issue 1724: [P2] Use node-consistent amounts in the current-receipt restart fixture

## Expected versus actual

The startup recovery regression should use a receipt emitted by the node for the exact transaction it retains, then prove nonzero budget spend survives restart. At snapshot 304b9064b65843c134de8b2bd906d7097e697317, the new fixture instead signs a receipt with amount 25 for transaction bytes whose value is zero. This leaves the nonzero-spend restart claim without a producer-consistent fixture.

## Source proof

- [current_node::authenticated_receipt](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-agentd/tests/support/current_node.rs#L123-L154) obtains signed_transaction(id), then supplies amount 25 to sequencer_receipt_with_details.
- [signed_transaction](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-agentd/tests/support/mod.rs#L74-L85) uses Eip1559Call. Its [encoder](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-crypto/src/evm_transaction.rs#L178-L189) writes the value field as zero.
- The fixture [writes the independent amount](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-agentd/tests/support/mod.rs#L812-L826) into the receipt and [signs those handcrafted bytes](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-agentd/tests/support/mod.rs#L859-L890).
- The real node [sets in.Amount = etx.Value()](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/node/sequencer/receipt.go#L401-L423), then [encodes in.Amount](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/node/sequencer/receipt.go#L260-L268). Its amount for these exact zero-value transaction bytes is therefore zero, not 25.
- The recovery test [asserts protocol_consumed and receipt_consumed are both 25, reconciliation succeeds and writes are admitted](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/304b9064b65843c134de8b2bd906d7097e697317/services/agent/crates/layerx-agentd/tests/outbox_recover.rs#L241-L261), using this fixture after the store is reopened.

## Acceptance criteria

- Replace the synthetic positive receipt with bytes emitted through the current node receipt producer for the exact signed transaction used by the scenario. Preserve and assert transaction hash, transaction value and receipt amount consistency.
- Retain a meaningful nonzero-spend case (25 or an equally explicit nonzero amount) with producer-derived budget state and matching evidence. Do not resolve the discrepancy by changing the entire positive scenario to zero spend.
- Preserve persistence, store close/reopen, exact receipt-byte retention, current-evidence inventory, receipt re-verification, reconciled accounting and evidenced-tenant write-admission assertions.
- Preserve legacy-evidence refusal, missing-evidence holds and invalid/unreconciled-budget refusal coverage.
- If the real producer-consumer path cannot represent the required nonzero spend, report that specific interface blocker rather than inventing receipt fields or weakening the assertions.
