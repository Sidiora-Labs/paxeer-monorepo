# Issue 1703: [Coherence] Push never closes its SSH session, which now leaks a temporary copy of the private key on every push or sync cycle

## Defect and impact

`NewSSHSessionContext` now copies the operator's private key and known-hosts file into a fresh `os.MkdirTemp` directory and starts a supervisor goroutine. Only `Close` or cancellation of the parent context removes that directory. `push()` creates a session from `context.Background()` and never calls `Close`. The sync engine calls `push()` on every interval, so each cycle leaves another readable copy of the private key in the temp directory and another goroutine that never exits. Before this change, an unclosed session leaked nothing on disk.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Push should close its SSH session, for example with a deferred Close, so the copied key material and the supervisor goroutine are released after each push.

Actual: Every push leaves a litt-ssh-* directory holding a copy of the private key, plus a goroutine that never exits. Neither is ever cleaned up.
