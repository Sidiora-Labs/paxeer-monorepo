# Issue 1692: [Coherence] The new generated-output allowlist misses the dist output of nine of the eleven launchpad SDK packages, so routine SDK builds now enter provenance and fail ownership checks

## Defect and impact

The repair replaces the global build/dist/coverage name exclusion with a fixed list of repository-relative output paths. For sdk/launchpad/packages it lists only `packages/dist` and `sidiora-launchpad-v3/dist`, but every package under sdk/launchpad/packages compiles into its own `<package>/dist` (`outDir: "dist"`), and the package-level .gitignore treats `dist/` as generated at any depth. After any `tsc` build of sdk, sdk-v2, stats-sdk, candles-sdk, indexer-sdk, metadata-sdk, ranking-algo-sdk, users-sdk, production-contracts or production-contracts-v2, the snapshot hashes the emitted JS. `verify` then reports source drift and `diff` fails with 'change outside owned paths' for untracked build output. Before this commit those files were excluded, so the change makes the false positives live.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Generated-output locations should cover every launchpad build output: each SDK package's dist, plus nested build, dist and logs under apps/launchpad/web. Tracked source under bootstrap/build and protocol/coverage should stay inventoried.

Actual: Only two of the SDK package output directories are excluded. Build output from the other packages is hashed as source and makes verify and diff fail.
