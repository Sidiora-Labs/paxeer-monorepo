# Issue 1809: [Coherence] The SDK manifest promotes ed25519-dalek and layerx-programs-registry to normal dependencies without refreshing the three independent lockfiles that build layerx-sdk by path, so their --locked gates now refuse to resolve

## Defect and impact

The commit moved the `[dev-dependencies]` header below ed25519-dalek and layerx-programs-registry, which makes both of them normal dependencies of layerx-sdk. Only services/agent/Cargo.lock was regenerated. The separate workspaces at tests/parity, tests/qualify and qualification/pay2 depend on layerx-sdk by path and keep their own tracked Cargo.lock files. Those lockfiles still list layerx-sdk's dependencies without either crate. Every spec gate on those workspaces runs `cargo test --locked`, and those gates now stop with "lock file needs to be updated". At the parent revision the same parity resolution got past lock checking.

Kind: connective. Severity: major.
