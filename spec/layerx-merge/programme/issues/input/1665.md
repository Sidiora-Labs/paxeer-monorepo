# Issue 1665: Node px_listAssets does not implement its declared cursor schema

## Problem
At [131ca5cf](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/131ca5cf77d8eea3514d4ccede53ca225703a6af), [node ListAssets](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/rpc/px_assets.go#L182-L198) accepts no cursor and returns `height`, `assets`, and `joined_limit` only. The [gateway OpenRPC schema](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/services/platform/hosted/gateway/openrpc.json#L1288-L1402) now specifies an optional positive decimal cursor and requires `next_cursor` and registration `order`. The [node RPC contract](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/spec/layerx-merge/contracts/evm-rpc.md#L3592-L3599) expressly adopts that parameter and result schema. Gateway contract changes were made in [ac3a6069](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/ac3a6069).

## Expected versus actual
A client using the declared schema should be able to request successive pages and interpret the returned cursor/order on the node endpoint. The current node method rejects extra arguments and omits those fields, so a conforming cursor-based client cannot traverse the node result as documented. This is separate from the existing SDK pagination handoff.

## Validation
Against a test node backed by an indexer with more than one page of registered assets, call `px_listAssets` without a cursor and then with the returned cursor. Validate both responses against the OpenRPC schema, check stable registration order and end-of-list behavior, and test invalid cursors. Compare existing node tests, which exercise unavailable indexer and parameter rejection rather than successful schema parity.

## Acceptance criteria
- Reconcile node implementation and declared schema, including cursor validation, `next_cursor`, registration order and stable pagination.
- Add producer-backed contract tests for first, subsequent and final pages, invalid cursors, and unavailable upstream behavior.
- Preserve fail-closed upstream errors and coordinate with the already assigned SDK pagination work.

Source inspection only; no tests or node requests were executed.
