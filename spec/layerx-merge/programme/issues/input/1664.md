# Issue 1664: [P2] Align registration tenant length with generated identity subjects

Impact: With a valid configured tenant of 96–128 ASCII bytes, the gateway's tenant validation accepts that configuration, but every direct or email px_register request is rejected by identity because the generated subject exceeds its 128-byte limit. Shorter names continue to work.

Source proof:

- Gateway rpc_register.rs:436–447 accepts a tenant up to 128 bytes.
- rpc_register.rs:99–103 derives subject as tenant + "." + 32 hexadecimal characters, adding 33 bytes.
- Identity main.rs:288–299 caps subject at 128 bytes; POST /v1/principals rejects it at 852–854 and POST /v1/signup at 1017–1022.

Boundary proof (source-level calculation, not a live service run): tenant lengths 95/96/128 yield subject lengths 128/129/161. All three pass gateway configuration; only 95 can pass identity subject validation. A correctly tenant-bound signature does not change this length.

Expected: Tenant validation and identity subject derivation should agree. Either reject tenant names longer than 95 before accepting provisioning configuration, or introduce a coordinated bounded subject format with compatibility handling. Add a real identity HTTP boundary test at 95 and 96; the current repair test calls identity Store directly and bypasses HTTP request validation.
