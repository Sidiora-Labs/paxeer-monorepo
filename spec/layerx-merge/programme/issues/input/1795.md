# Issue 1795: [Coherence] The new COPY of docs/explorer/ENVS.md fails because the Dockerfile's ignore list keeps docs/ out of the build context

## Defect and impact

The builder stage now runs `COPY docs/explorer/ENVS.md`, but the Dockerfile's own ignore list, docker/explorer-frontend/Dockerfile.dockerignore, starts with `*` and re-includes only `apps/explorer`. That leaves docs/ outside the build context, so the COPY fails with a file-not-found error. The explorer-images job still breaks (it now fails one step before collect_envs instead of at the .env.registry copy), so the red public check this task was meant to fix stays red. The new test checks the Dockerfile text and runs the script on the host, never inside the Docker build context, so it passes even though the image cannot be built.

Kind: connective. Severity: blocker.

## Expected versus actual

Expected: Dockerfile.dockerignore re-includes the document (for example `!docs/explorer/ENVS.md`), so the builder-stage COPY succeeds and collect_envs.sh writes .env.registry inside the image build.
