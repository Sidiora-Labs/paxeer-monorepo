# Issue 1873: [P2] Quote the node test alternatives in task 22.39.155

## Problem

Commit [e16566d0](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/e16566d092bd7926cba7efd17734f122aec65902) adds the workflow-inventory test to task 22.39.155, but also removes the quotes around the Go `-run` regular expression. The shell now interprets its two `|` characters as pipelines instead of passing the three test alternatives to Go.

Verified against current main [17b70dbc](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/17b70dbc5eb6e67f3d2973632a08b5d8cb746698) on 2026-11-08 at 04:27:46 UTC. The complete intervening compare only changes task 22.39.120 from pending to done, so this command remains unchanged.

## Source

- [Task 22.39.155 verification command](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/e16566d092bd7926cba7efd17734f122aec65902/spec/layerx-merge/spec.kvx#L210423) now ends with:
  `go test -timeout 15m -count=1 -run TestEVMServerServesSequencerReceiptOption|TestStandbyReplicatesRecorderGroupsThroughOpenAccount|TestV640ToV66UpgradeServesTheExchangeBridgeAndLaunchpadPrecompiles ./node/`
- The previous command encloses that entire regular expression in single quotes, as shown in the commit diff.
- The [qualification consumer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/e16566d092bd7926cba7efd17734f122aec65902/tools/hyperfide/plugins/hyperfide-qualify/lanes.ts#L42-L47) takes `task.verify_cmd` for verify mode and [executes it with `sh -c`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/e16566d092bd7926cba7efd17734f122aec65902/tools/hyperfide/plugins/hyperfide-qualify/lanes.ts#L89).

The large spec file's full-content read was unavailable; the exact command and line above were recovered from the pinned commit patch, and its continued presence was checked with the complete intervening compare.

## Expected versus actual

Expected: Go receives one `-run` argument containing all three alternatives and receives `./node/` as the package.

Actual: Go receives only `TestEVMServerServesSequencerReceiptOption` and no package argument. The shell tries to launch the other two test names as executables, with `./node/` attached to the final pipeline command. Once the preceding guards pass, the declared gate exits 127 on an ordinary test environment instead of running the intended tests.

## Reproduction and validation

This isolated reproduction replaces Go with a shell function and clears PATH, so it does not build or run repository tests:

```sh
PATH= /bin/sh -c 'go() { printf "go arg: <%s>\n" "$@" >&2; }; go test -timeout 15m -count=1 -run TestEVMServerServesSequencerReceiptOption|TestStandbyReplicatesRecorderGroupsThroughOpenAccount|TestV640ToV66UpgradeServesTheExchangeBridgeAndLaunchpadPrecompiles ./node/'
```

Observed exit: 127. Both latter test names produce `not found`; the stub Go output ends after the first test name.

The complete old and new verification commands were also executed in a scratch harness with empty guard files and Go/Python stubs. The old quoted command exits 0 and passes the complete regular expression plus `./node/`; the new command exits 127. This validates shell parsing only. The qualification service, actual Python test and Go node suite were not run.

## Impact

Task 22.39.155 cannot pass its declared verification command after its earlier guards are satisfied. Its intended receipt, standby and upgrade test coverage is not reached correctly. This finding does not assess runtime upgrade behavior.

## Acceptance criteria

- Keep the added workflow-inventory pytest check.
- Restore quoting around the full Go `-run` regular expression.
- Verify that the shell passes all three alternatives as one argument and `./node/` as the package.
- Run the repaired task verification against its final revision, distinguishing any unrelated test failures from this parsing failure.
