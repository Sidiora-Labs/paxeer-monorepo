# Issue 1671: PR #1645 selects bincode 3, which cannot build perf-db

## Problem

[PR #1645](https://github.com/Sidiora-Labs/paxeer-monorepo/pull/1645), at head [ab5f5170](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/ab5f517099188c17eafd246cdc4e2f9a83c44078), changes the [perf-db dependency](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ab5f517099188c17eafd246cdc4e2f9a83c44078/services/platform/perf-db/Cargo.toml#L29-L31) from bincode 1.3.3 to 3.0.0. The published [bincode 3.0.0 source](https://docs.rs/crate/bincode/3.0.0/source/src/lib.rs) contains an unconditional compiler error. Existing [WAL](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ab5f517099188c17eafd246cdc4e2f9a83c44078/services/platform/perf-db/src/storage/wal.rs#L169-L175) and [snapshot](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ab5f517099188c17eafd246cdc4e2f9a83c44078/services/platform/perf-db/src/storage/snapshot.rs#L274-L304) code also uses the v1 serialization API.

## Expected versus actual

The dependency group should build perf-db and preserve the ability to recover existing WAL and snapshot data. The selected bincode release deliberately fails compilation, before existing v1 API usage can compile. This concerns the PR head, not the default branch.

## Validation

Run `cargo check --locked --manifest-path services/platform/perf-db/Cargo.toml --all-targets` at the PR head, then run storage and recovery tests. Confirm previously written WAL/snapshot fixtures remain readable after any dependency change.

## Acceptance criteria

- Remove the incompatible bincode 3 upgrade from the group or implement an explicitly reviewed compatible migration.
- Locked all-target build and storage/recovery tests pass.
- Preserve existing persisted data compatibility, with regression coverage for old WAL and snapshots.

This is source-based verification; no local build or tests were executed, and no deployment impact is claimed.
