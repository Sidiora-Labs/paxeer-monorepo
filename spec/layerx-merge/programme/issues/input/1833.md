# Issue 1833: [P2] Accept the seller's committed settlement metadata in the Python buyer

## Expected versus actual

The Python buyer should accept the TypeScript seller's ordinary committed settlement response, then perform the existing receipt and commitment verification. Instead, `BuyerMiddleware.fetch()` calls `capture_settlement()`, which passes the entire `extensions.layerx` object to the strict payment-proof parser. The seller's intentional `landingBlockHeight` and `landingBlockHash` fields are not in that parser's allowed set, so capture raises `ValueError("invalid-payment-fields")` before verification.

This is a fail-closed cross-language compatibility defect. It blocks capture of committed responses from this seller; no successful bypass, funds loss or deployment incident is claimed.

## Reproduction / validation

1. Take an otherwise well-shaped `layerx-receipt-proof-v2` object with the six required members and a well-shaped `receiptKey`. With no landing fields, `_parse_proof` accepts its shape.
2. Add the seller's `landingBlockHeight: "0x1"` and `landingBlockHash: "0x" + "44" * 32`. Calling `_parse_proof` now raises `invalid-payment-fields`. Either field alone also triggers the failure.
3. Put that object in a successful settlement's `extensions.layerx`, with matching network/amount and the same proof in the submitted payment. `BuyerMiddleware.capture_settlement` fails at the same key check before either `_verify_proof` call.
4. For the integration regression, produce the committed header through the real TypeScript seller and consume it unmodified through Python `fetch`/`capture_settlement`, using the existing valid receipt and commitment fixtures.

Steps 1–3 were executed using AST-extracted functions from the exact pinned Python source with synthetic, well-shaped proof bytes. Requirement validation was isolated for that parser-boundary probe. This was not cryptographic verification, a full conformance run or a live transaction.

## Acceptance criteria

- Separate settlement-envelope metadata from the strict submitted-proof shape, or explicitly parse the documented landing fields without dropping existing proof checks.
- Preserve signature, receipt binding, trusted committed-evidence and downgrade refusals. Merely allowing fields must not make them trusted evidence.
- Add a TypeScript-seller-to-Python-buyer committed round-trip regression, plus unchanged receipted behavior and malformed/mismatched evidence refusals.
