# Issue 1883: [P2] Align reference-ramp HTTP proof with current internal rewrites

## Defect and impact

The reference-ramp HTTP proof imports apps/web/next.config.mjs and expects no rewrites when LAYERX_HUMAN_SERVICE_URL is unset. The current configuration always returns three internal Human API rewrites. The test also expects /readyz to rewrite directly to https://human.example.test/readyz after setting the variable, while the configuration always targets /api/human/readyz.

These stale assertions make the route proof fail when its Node step is reached, blocking an honest passing run of the layerx-reference-ramp suite. This is a test/configuration contract mismatch; no production routing or security failure is alleged.

## Expected versus actual

Expected: The proof asserts the current internal routes /human/v1/:path* and /v1/:path* to /api/human/v1/:path*, and /readyz to /api/human/readyz, while retaining its checks that no /internal/ route is exposed and readiness is not cached.

Actual: It requires [] with the environment variable absent, then an external readiness destination with the variable set. Neither condition matches the current configuration.
