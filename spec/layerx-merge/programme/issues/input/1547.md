# Issue 1547: [Coherence] px_getReceiptKeys on a node that is not serving answers with an error message naming pax_sequencerReceipt

## Defect and impact

GetReceiptKeys reuses errSequencerReceiptNotServed when the node has neither a Source nor a ForwardURL. That error's text is hard-wired to SequencerReceiptMethod. A caller of px_getReceiptKeys therefore gets a -32000 error that names the wrong method, which misleads operators who are diagnosing why the agent readiness gate (which reads this method) stays NotReady.

Kind: semantic. Severity: minor.

## Source proof

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b333bce4cf409f360f0e236826d6ad24a3258d79/rpc/sequencer_receipt.go#L354 — This is the px_getReceiptKeys path when the node is not serving.

  ```
  return nil, errSequencerReceiptNotServed{}
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b333bce4cf409f360f0e236826d6ad24a3258d79/rpc/sequencer_receipt.go#L73 — The message always says pax_sequencerReceipt.

  ```
  return SequencerReceiptMethod + " served by sequencer"
  ```


Reviewed commits: b333bce4cf409f360f0e236826d6ad24a3258d79

## Expected versus actual

Expected: The error for px_getReceiptKeys names px_getReceiptKeys, or uses a method-neutral message.

Actual: The error reads "pax_sequencerReceipt served by sequencer".
