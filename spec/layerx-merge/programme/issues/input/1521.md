# Issue 1521: [Coherence] The blanket glob override hands glob 14 to rimraf 2 and globby 6, which call glob as a callback function, so the next-pwa clean step in `next build` breaks

## Defect and impact

The new override `glob@<14.0.2 → 14.0.2` rewrites every nested glob, including the ones used by rimraf@2.7.1 and globby@6.1.0. Both packages come in through del@4.1.1 → clean-webpack-plugin → next-pwa. Both call `require('glob')` as a function with callbacks (glob 7 API). From glob 9 on, the module only exports named `glob`/`globSync` and is no longer callable. next-pwa is turned on for every non-development build, so the production `next build` will throw when CleanWebpackPlugin runs. Task 22.24.6 do_2 says the build/typecheck must run after the raise and any breakage go in a qualification note, but this task has no qualification entry.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Parents that need the glob 7 API should get a glob version they can call. If the floor cannot be met without breaking them, that should be recorded in a qualification note, or the parent chain (next-pwa/clean-webpack-plugin) should be replaced.

Actual: rimraf 2.7.1 and globby 6.1.0 now resolve glob 14.0.2 in both pnpm-lock.yaml and package-lock.json, so the production build path calls a glob module that isn't callable.
