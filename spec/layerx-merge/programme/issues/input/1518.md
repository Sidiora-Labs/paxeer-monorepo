# Issue 1518: [Coherence] The Python and TypeScript web search clients now disagree on which receipt settles a metered search

## Defect and impact

After this commit the Python web search verifier accepts only sequencer receipts with module 12, operation 2, and refuses module 1, operation 6 with settlement-operation-mismatch. The TypeScript web search client still does the opposite for metered settlements: it refuses anything that is not module 1, operation 6. It also keeps the module 1 balance arm that this commit removed from Python. A real sequencer receipt from the live producer (every fixture case decodes to 12/2) therefore settles a metered search in the Python SDK but fails in the TypeScript SDK with settlement-operation-mismatch. A synthetic 1/6 receipt does the reverse. The TypeScript mismatch already existed, but this commit makes the two SDKs contradict each other. The spec has no pending task that ports the TypeScript side.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: Both SDKs apply the same receipt-shape rule to a web search settlement. The TypeScript client should accept the module 12, operation 2 sequencer receipt for metered searches and drop the module 1 arms, as the Python client now does.

Actual: Python accepts only 12/2 and refuses 1/6. TypeScript refuses 12/2 for metered searches and accepts only 1/6. The same seller settlement succeeds in one SDK and fails in the other.
