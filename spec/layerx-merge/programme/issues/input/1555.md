# Issue 1555: [Coherence] Repeated revokes can no longer return LXP_IDEMPOTENT_REPLAY, but the revoke tests still expect it

## Defect and impact

The commit removes the module's 0x04 replay marker from RevokeGrant and says a repeated revoke now gets its refusal from the kernel. Nothing in that path can return -302. The host only checks idempotency for LX_ASSET_SEND, and admission is always told the key does not exist. In the kernel, the governance revoke handler compares the payload's revocation sequence with the current global sequence, which moves past 44 once the first revoke commits, so it returns LXP_ERR_AUTH_SCOPE (-204), which maps to ErrAuthScope. Three updated assertions in revoke_test.go still expect ErrIdempotentReplay, so either the tests fail or the documented replay result no longer holds.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: A repeated revoke of a committed grant should return the result the kernel actually produces (ErrAuthScope, or ErrAuthRevoked), and the tests should assert that. Otherwise, if the spec requires LXP_IDEMPOTENT_REPLAY for this case, some component has to produce it.

Actual: Once the marker is removed, a repeated revoke from the bound actor gets ErrAuthScope from the kernel's revocation-sequence check. TestRevokeGrantAdvancesRevocation and TestRevokeGrantReplayRequiresCommittedSuccess still assert ErrIdempotentReplay.
