# Issue 1791: [Coherence] The gateway ingress rule now admits a control pod label, layerx-mainnet-beta-control, that no workload carries

## Defect and impact

The commit rewrote the label `app: layerx-testnet-control` as `app: layerx-mainnet-beta-control` as part of the namespace rename. The control service is still deployed as layerx-testnet-control, and every other manifest admits it by that label, so the control plane can no longer reach the gateway on 9443.

Kind: semantic. Severity: major.

## Source proof

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8efee4ff17c3784f392c61be46946bd5875faf8d/services/platform/hosted/gateway/deployment.yaml#L185 — This is the only occurrence of this label in the repository.

  ```
  {podSelector: {matchLabels: {app: layerx-mainnet-beta-control}}}
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8efee4ff17c3784f392c61be46946bd5875faf8d/services/platform/hosted/interop/deployment.yaml#L69 — The peer manifests use the real control pod label.

  ```
  {podSelector: {matchLabels: {app: layerx-testnet-control}}}
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8efee4ff17c3784f392c61be46946bd5875faf8d/docker/platform-testnet/Dockerfile#L13 — The control workload is still layerx-testnet-control.

  ```
  ENTRYPOINT ["/usr/local/bin/layerx-testnet-control"]
  ```


Reviewed commits: 8efee4ff17c3784f392c61be46946bd5875faf8d

## Expected versus actual

Expected: The ingress rule admits the existing control pod label, together with a namespaceSelector if the namespaces now differ.

Actual: The rule admits a label no pod has.
