# Issue 1874: [P2] Provide the history required by the Python baseline-retirement test

## Problem

The new `test_payment_baseline_entries_are_retired_and_the_transport_baseline_is_preserved` test reads a baseline from historical commit `3a0f70d0fce59d96719043d5294b98aa3718e3bd` with `git show`. Its owning SDK workflow uses a fresh default-depth checkout, which does not provide that historical commit. The test therefore fails before checking any retirement assertions.

Introduced in [5247adc5](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/5247adc56b93433fa7d8ad18a98455124a7e19df). Revalidated at current main [ed28b382](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/ed28b382872cd691bb0479c55b5e71c84e899ce3) on 2026-11-08 at 04:30:51 UTC: the test, agent workflow and Makefile blobs are unchanged from the reviewed snapshot.

## Producer and consumer

- [The new test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ed28b382872cd691bb0479c55b5e71c84e899ce3/tests/agent/sdk/python/test_repair_22_33_702.py#L389-L411) unconditionally calls:
  `git show 3a0f70d0fce59d96719043d5294b98aa3718e3bd:tests/ci/data/agent_sdk_python_baseline.json`
- [The sdk-python checkout](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ed28b382872cd691bb0479c55b5e71c84e899ce3/.github/workflows/agent.yml#L85-L115) sets only `persist-credentials: false`, with no `fetch-depth` override or subsequent history fetch.
- [The pinned checkout action](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/action.yml#L74-L76) defaults `fetch-depth` to 1.
- The workflow runs `make agent-test-sdk-py`. [That target](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ed28b382872cd691bb0479c55b5e71c84e899ce3/Makefile#L2400-L2411) collects `tests/agent/sdk/python`, including this new test.

## Expected versus actual

Expected: the SDK test can validate retired payment entries and preserved transport entries using inputs available in its declared CI checkout.

Actual: in a fresh checkout without the pinned historical object, `subprocess.check_output` raises `CalledProcessError` from `git show` (exit 128), even though the current baseline file is present.

## Reproduction and validation

In a clean depth-1 checkout of the affected revision, confirm the missing input:

```sh
git rev-parse --is-shallow-repository
git show 3a0f70d0fce59d96719043d5294b98aa3718e3bd:tests/ci/data/agent_sdk_python_baseline.json
```

Then, with the SDK test prerequisites installed, run:

```sh
PYTHONPATH=services/agent/sdk/python python3 -m pytest -q tests/agent/sdk/python/test_repair_22_33_702.py::test_payment_baseline_entries_are_retired_and_the_transport_baseline_is_preserved
```

Executed evidence: the unmodified test function was extracted from the pinned source with Python AST and run in an isolated synthetic one-commit shallow Git repository containing the real current baseline. The harness confirmed `shallow=true`, commit count 1, current baseline present, and `CalledProcessError` with subprocess exit 128 at that exact `git show` call. The harness exited 0 because it expected and checked the failure. This was not a GitHub Actions run or full SDK-suite execution; the workflow incompatibility is established by the source wiring above.

## Impact

Fresh SDK CI checkouts gain a failing test unrelated to the payment repairs. A full-history local checkout can hide the missing CI input, so a local task pass does not qualify this workflow path.

## Acceptance criteria

- Make the test independent of unavailable historical Git objects while preserving its retirement assertions, or explicitly provide the required pinned history in the owning CI path.
- Exercise the exact test from a clean checkout matching CI's history configuration.
- Run the normal SDK CI path against the repaired revision and report any separate failures.
- Do not skip the new test or silently weaken the baseline assertions to hide a missing input.
