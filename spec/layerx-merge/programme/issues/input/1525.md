# Issue 1525: [Coherence] Deleting go.sum from core/deps/db-backend and core/deps/tm-db leaves both modules unable to verify or build

## Defect and impact

The commit deletes core/deps/db-backend/go.sum and core/deps/tm-db/go.sum and does not regenerate them. The commit changes only the requirement lines of the two go.mod files. With no go.sum, `go mod verify` and `go build ./...` stop with "missing go.sum entry" errors for every external package, so the task's own verify_cmd cannot pass in either directory. The spec asks for the lock files to be raised with the manifest's own package manager. Deleting them does the opposite.

Kind: semantic. Severity: blocker.

## Expected versus actual

Expected: After raising the requirements, run `go mod tidy` in each module and commit the regenerated go.sum, so that `go mod verify && go build ./...` succeeds.

Actual: Both go.sum files are deleted (the stat shows 25825 → 0 and 21341 → 0 bytes), so both modules fail at checksum resolution before anything compiles.
