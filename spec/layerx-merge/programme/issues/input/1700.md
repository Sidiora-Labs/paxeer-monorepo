# Issue 1700: [Coherence] The deferred Close in the blocksim CLI now re-reports every workload failure as a close failure

## Defect and impact

This change makes Close() return the first recorded workload or teardown error, which it gets from BlockUntilHalted. The CLI's deferred Close handler was not updated and still prints any error it gets as a close failure. So when a block write, flush or prune fails, the CLI prints the error three times: once from recordError, once as "Error closing blocksim: …" and once as "Error: …" from CLIExitCode. A write failure is therefore also reported as a database-close failure, which points the operator at the wrong operation.

Kind: connective. Severity: minor.

## Expected versus actual

Expected: A workload failure is reported once, through CLIExitCode, and the deferred Close in main does not relabel it as a close error (for example, the defer ignores the error when run already returned it).

Actual: A failed write, flush or prune is printed as itself, then as "Error closing blocksim: failed to write block …", then as "Error: failed to write block …".
