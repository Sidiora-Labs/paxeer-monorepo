# Issue 1688: [Coherence] An invalid RPC override now throws while rpc.ts loads, so the new RpcConfigurationError never reaches backendConfigurationProblems or the configuration error page

## Defect and impact

getPaxeerRpcUrls now throws RpcConfigurationError on an unusable override, and rpc.ts still evaluates it at module scope for PAXEER_RPC_URL. backend-origins.ts imports rpc.ts, so a bad NEXT_PUBLIC_RPC_URL* value (an empty string included) throws while the module is being loaded. That happens before the new try/catch in backendConfiguration() can turn the error into a problem. next.config.ts, instrumentation.ts, layout.tsx and middleware.ts all import backend-origins, so a bad value crashes the build, server and middleware instead of showing the configuration error state. The test misses this because rpc.ts is first imported with the variables unset.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: An invalid RPC override shows up as a BackendOriginError in backendConfigurationProblems(), and the app renders the configuration error state.

Actual: The module throws while loading, which crashes next.config, instrumentation, the layout and the middleware before any problem is collected.
