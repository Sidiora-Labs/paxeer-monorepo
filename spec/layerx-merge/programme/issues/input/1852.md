# Issue 1852: [Coherence] The interface registry still says pax_sequencerReceipt is HTTP only, while the updated proof test now requires it over WebSocket too

## Defect and impact

This commit rewrites TestProofNodeGoApi so the WebSocket client must get the same receipt answers as HTTP, and changes the file header to say the method is served on both transports. The interface registry entry for pax_sequencerReceipt, and its copy in the evm-rpc contract, still say it is served over HTTP only. The server change that caused this landed earlier. This commit turns the WebSocket behaviour into a tested guarantee but leaves the spec saying the opposite, so clients that read the contract will think WebSocket refuses the method.

Kind: connective. Severity: minor.
