# Issue 1648: [P2] Migrate the dApp integration before upgrading to Hardhat 3 in #1646

## Scope

PR #1646 at `bb386691c644de3fe8082734cea40643529631f7` changes only `tests/integration/dapp_tests/package.json` and its lockfile, upgrading resolved Hardhat from 2.29.1 to 3.21.2. Base: `2a8418f3ce46275830d68ea57514c30466a3493f`.

This is a development/integration-test tooling compatibility regression. **Static review only:** no install, build, test, deployment, RPC request or live-chain interaction was run. No observed failure exit code or deployed impact is claimed.

## Expected versus actual

Expected: the dependency update preserves a valid dApp test plugin graph and its retained compile/test entry points, or includes the coordinated Hardhat 3 migration.

Actual:
1. [The new lock resolves only Hardhat 3.21.2](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/package-lock.json#L9914-L9941), but retains [`@nomiclabs/hardhat-ethers` 2.2.3 and `@nomiclabs/hardhat-waffle` 2.0.6, both requiring `hardhat ^2.0.0`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/package-lock.json#L4922-L4943). Those same plugin versions and peer constraints were compatible with the base lock's Hardhat 2.29.1. The updated dependency graph does not satisfy them.
2. [The unchanged config](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/hardhat.config.js#L1-L39) registers these plugins through CommonJS `require` side effects and exports with `module.exports`. [The package](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/package.json#L1-L24) has no `"type": "module"`. Hardhat's [migration guide](https://hardhat.org/docs/migrate-from-hardhat2) requires an ES-module config and explicit plugin registration. Bypassing peer resolution would therefore leave a second compatibility barrier.
3. Existing consumers still depend on the old injected runtime and ethers-v5 API, for example [Uniswap setup's `hre.ethers.Wallet.fromMnemonic` and `hre.ethers.provider`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/uniswap/uniswapTest.js#L29-L32), and [the shared helper's `hre.ethers.utils.parseEther`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/utils.js#L67-L84). The two-file PR does not migrate these consumers.

## Impact

The retained [combined runner](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/dapp_tests.sh#L16-L23), [NFT/Steak runner](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/dapp_nft_steak_tests.sh#L5-L14) and [Uniswap runner](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb386691c644de3fe8082734cea40643529631f7/tests/integration/dapp_tests/dapp_uniswap_tests.sh#L5-L13) perform `npm ci`, then invoke Hardhat compilation and tests. The major-version bump leaves their plugin graph and config incompatible before meaningful integration qualification. This package has its own lockfile and plugin/config consumers; repairing `contracts/` alone does not repair it.

## Validation for the repair owner

In a disposable checkout of the pinned PR head with a supported Node runtime:
1. Compare the lock's `node_modules/hardhat` version with both `@nomiclabs` plugins' `peerDependencies.hardhat`.
2. Run `npm --prefix tests/integration/dapp_tests ci --ignore-scripts --no-audit --no-fund` without `--force` or `--legacy-peer-deps`; record the actual dependency-resolution result.
3. After resolving the graph, run `(cd tests/integration/dapp_tests && npx --no-install hardhat --help)` to validate config loading, then the package's compile command.
4. Validate one migrated test and then each retained launcher only against a disposable local chain with the documented prerequisites. These tests deploy contracts and submit transactions; do not use public or funded production environments.

## Acceptance criteria

- Keep a compatible Hardhat 2 version until migration is ready, or migrate this package's plugins, config, runtime consumers and test runner together.
- Regenerate a consistent lock with no unsatisfied Hardhat peers; do not conceal the mismatch with forced/legacy peer resolution.
- Config loading and compilation succeed, and meaningful integration checks pass against a disposable local chain with revision, commands and results recorded.
- Keep the launcher instructions and any supported Node requirements consistent with the selected version.
