# Issue 1543: [Coherence] The Android sample app still pins the old Jackson and BouncyCastle versions, and its Gradle verification metadata has no checksums for the new ones

## Defect and impact

The sample app takes layerx-android 0.1.0 from mavenLocal. That POM now requires jackson-databind 2.18.9 and bcprov-jdk18on 1.85, but the sample app still declares 2.17.2 and 1.78.1 directly. Gradle picks the highest requested version, so the build resolves 2.18.9 and 1.85. Metadata verification is on, and the verification file only has checksums for 2.17.2 and for bcprov 1.77 and 1.78.1, so the sample-app build will fail its dependency-verification check. The advised versions also stay declared in the app's own build file.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Raise the sample app's direct Jackson and BouncyCastle declarations to the new floors, and regenerate verification-metadata.xml so it covers jackson 2.18.9 (with its core, annotations and BOM) and bcprov 1.85.

Actual: The sample app still declares 2.17.2 and 1.78.1, and the resolved 2.18.9 and 1.85 artifacts have no verification entries, so the Gradle build of the sample fails verification.
