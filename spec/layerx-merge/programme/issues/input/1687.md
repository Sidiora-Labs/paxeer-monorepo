# Issue 1687: [Coherence] Removing an approved image while a save is in flight drops the save acknowledgment and leaves the editor stuck in the saving state

## Defect and impact

The new Remove handler calls invalidate(), which bumps the shared generation counter that save(), transfer(), refreshImage() and the load effect all use to drop stale results. The Remove button is still shown and enabled while a save is running, because the upload is only cleared after the save succeeds. If the user clicks Remove during a save, the server applies the uploaded asset, but save() sees a generation mismatch and returns early. The state is never moved out of 'saving', the revision is never advanced, and the draft has gone back to the baseline image. Before this commit Remove did not touch the generation counter, so a save in flight always finished normally.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: Removing a draft upload should only cancel the upload or refresh for that image, or Remove should be disabled while a save is in flight, so a save the server committed still reaches the 'committed' state and advances the revision.

Actual: Clicking Remove during a save discards the acknowledgment. The modal stays in 'saving' with the button spinning, shows the baseline image even though the server stored the upload, and keeps the old revision, so any retry after reopening hits a precondition conflict.
