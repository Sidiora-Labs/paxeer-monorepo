# Issue 1704: [Coherence] Benchmark config validation accepts a random pool exactly equal to the value size, which panics in the data generator

## Defect and impact

The new Validate says it rejects configuration that cannot safely reach the benchmark's runtime consumers. It checks RandomPoolSize and ValueSizeMB separately but never compares them. When the value length equals the pool size, the generator takes its in-pool branch and calls rng.Intn(0), and that panics. So a config that passes LoadConfig still crashes the benchmark on its first write instead of returning an error.

Kind: semantic. Severity: minor.

  ```
  if c.RandomPoolSize == 0 || c.RandomPoolSize > maxInt {
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/520da02a9f9f34cd99114afb9103db27cd741246/storage/db_engine/litt/benchmark/config/benchmark_config.go#L230 — The value size is checked on its own, never against RandomPoolSize.

  ```
  {"ValueSizeMB", c.ValueSizeMB, 1, math.Min(float64(math.MaxUint32)+1, float64(maxInt))},
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/520da02a9f9f34cd99114afb9103db27cd741246/storage/db_engine/litt/benchmark/data_generator.go#L60 — The fallback branch is only taken when the value is strictly larger than the pool, so an equal size goes to the else branch.

  ```
  if valueLength > uint64(len(g.dataPool)) {
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/520da02a9f9f34cd99114afb9103db27cd741246/storage/db_engine/litt/benchmark/data_generator.go#L67 — With equal sizes this is rng.Intn(0), which panics.


- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/520da02a9f9f34cd99114afb9103db27cd741246/storage/db_engine/litt/benchmark/data_tracker.go#L146 — The tracker passes the validated value size to the generator.

  ```
  valueSize := uint64(config.ValueSizeMB * float64(unit.MB))
  ```


Reviewed commits: 520da02a9f9f34cd99114afb9103db27cd741246

## Expected versus actual

Expected: Validate (or the generator) should handle a pool size equal to the value size, for example by requiring RandomPoolSize to be larger than ValueSizeMB*MB or by making the generator take its fallback branch when the sizes are equal.

Actual: A config such as ValueSizeMB=1 with RandomPoolSize=1048576 passes LoadConfig, then panics with 'invalid argument to Intn' the first time a value is generated.
