# Issue 1712: Restore real HTTP coverage after explorer fetchApi switches to global fetch

## Summary

[050e1cbc](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/050e1cbc17da350964bccc3fa262dd2452c5f34d) switches explorer [fetchApi](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/apps/explorer/nextjs/utils/fetchApi.ts#L25-L39) from imported node-fetch to global fetch. At current revision [ebb7357e](https://github.com/Sidiora-Labs/paxeer-monorepo/tree/ebb7357e2543a9b0923fabad512ed3541102829c), [Vitest setup](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/apps/explorer/vitest/setup.ts#L4-L9) enables the global fetch mock, while the retained [543 HTTP regression](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/apps/explorer/nextjs/utils/repair-22-33-543.spec.ts#L16-L36) starts a real loopback server without disabling that mock. Previously its imported node-fetch bypassed the mock.

## Validation

In a prepared checkout, run `cd apps/explorer && yarn vitest run nextjs/utils/repair-22-33-543.spec.ts`. Expected: requests reach the loopback server, real 400/404/500/503 responses are refused, 200/201 payloads and stats metadata are returned, and the server sees twelve requests. With global fetch mocked, the source path instead intercepts those calls and cannot exercise the upstream behavior; the positive payload and request-count assertions are incompatible with that path. The [543 contract](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/apps/explorer/nextjs/utils/repair-22-33-543.kvx#L1-L6) expressly calls for the real HTTP chain. The [512 gate](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ebb7357e2543a9b0923fabad512ed3541102829c/apps/explorer/repair-22-31-512.kvx#L13-L19) only runs its own boundary test before the build.

This is source-verified; the test was not executed in this review, so the first runtime failure is unconfirmed. No production or deployment impact is established.

## Acceptance criteria

- Ensure the HTTP regression uses real loopback fetch and restores the global mock afterward so other tests remain isolated.
- Run the retained 543 regression and boundary tests together, verifying the expected status handling, payloads and request count.
- Include the retained HTTP regression in relevant qualification for future fetch-boundary changes.
