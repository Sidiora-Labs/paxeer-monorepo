# Issue 1656: [P2] Align protocol TVL card with six-decimal snapshot amounts

## Defect and impact

The protocol TVL card now consumes aggregate snapshots, but interprets their six-decimal USDL amount as 18-decimal USD. Its displayed dollar value is understated by a factor of 10^12. This affects analytics, not custody or movement of funds.

## Producer-to-consumer proof

At reviewed revision 3d4875e96150d48fc11feac48c4aaf590400efbb:
- [The new card conversion](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/3d4875e96150d48fc11feac48c4aaf590400efbb/apps/perps/src/widgets/analytics/AnalyticsLiquidStat.tsx#L47-L64) divides protocolSnapshots.tvlUsd by 1e18. It is [mounted on the analytics page](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/3d4875e96150d48fc11feac48c4aaf590400efbb/apps/perps/src/page-modules/analytics/index.tsx#L83-L89).

The new frontend fixture instead manufactures tvlUsd with usd * 10^18, so it does not exercise the actual producer's units.

## Expected versus actual and focused check

For 5 USDL entering custody and 1.5 USDL leaving before the snapshot, the producer emits tvlUsd = "3500000". Expected display value: $3.50. Actual card conversion: Number("3500000") / 1e18 = 3.5e-12 dollars, normally rounded to zero.

An isolated Node probe executed the exact pinned buildTvlTimeline body with only TypeScript type annotations removed and this snapshot. It returned 3.5e-12 versus expected 3.5. No repository suite, database, browser, live transfer or deployed service was executed. The producer path is source proof, supported by its existing test source, not a claim that the producer test was run.
