# Issue 1584: [P2] Align native program constructor with HTTP transaction binding

## Problem

At [1ec518f](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/1ec518f2c70d85d0dbf7e8df6c222af18574e15a), the public [NativeProgramCallRequest::new](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/1ec518f2c70d85d0dbf7e8df6c222af18574e15a/services/agent/crates/layerx-sdk/src/programs.rs#L107-L143) requires signed transaction data to equal `call.encode()` and uses the transaction hash as idempotency key. Both HTTP native methods call [wire_native_call](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/1ec518f2c70d85d0dbf7e8df6c222af18574e15a/services/agent/crates/layerx-sdk/src/program_http.rs#L1902-L1912), which reconstructs via `from_signed_transaction` and requires exact equality. That constructor instead requires [selector-prefixed ABI calldata](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/1ec518f2c70d85d0dbf7e8df6c222af18574e15a/services/agent/crates/layerx-sdk/src/program_http.rs#L195-L220) and derives a domain-separated idempotency key. The [schema](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/1ec518f2c70d85d0dbf7e8df6c222af18574e15a/services/agent/schema/agent-api/programs.kvx#L136-L147) requires ABI binding and HTTP idempotency equal to the transaction hash.

The relevant earlier migrations include [084623ad](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/084623ad84effe5edc68bc0d1718840b180b353c), [98d64cd4](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/98d64cd4f56046d69ea3bcc5116658362aafb83e), and [af9b1ccc](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/af9b1ccc595adb3ac31726da325b2f627a8ca331).

## Expected vs actual

A valid public request should pass the supported HTTP transport with one consistent calldata, fee and idempotency contract. Currently a request accepted by `new()` fails the transport's rebinding locally before HTTP dispatch; the HTTP constructor's derived key also disagrees with the schema. No deployed server impact is claimed.

## Validation

Use a valid signed request accepted by `new()` in both actual native simulation and submission methods with a capture transport; verify dispatch and schema-conformant calldata and idempotency. Add the converse ABI-encoded fixture and tamper cases. Static source inspection only; tests were not executed. The aggregate spec was unavailable, so later task ownership could not be exhaustively excluded.

## Acceptance criteria

- Public constructor, HTTP rebinding, server/schema agree on signed calldata, fee limit and idempotency.
- Producer-backed tests cover both public construction and HTTP dispatch while preserving identity and signature checks.
- Altered transaction/call/key combinations still fail closed.
