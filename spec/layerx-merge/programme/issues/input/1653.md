# Issue 1653: RPC config rejects the documented zero interval for disabling stats

## Problem

At [039e5adc](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/039e5adc21d328c5a1b7275e9649076c7d444e31), configuration validation [rejects `rpc_stats_interval <= 0`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/rpc/config/config.go#L483-L490). The stats consumer instead [treats a nonpositive interval as disabled](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/rpc/stats/tracker.go#L49-L74), and [audit 22.30.68](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/spec/layerx-merge/programme/audit/records/22.30.68.kvx#L1054-L1061) explicitly calls for zero to disable this setting. The validation was introduced in 263febe8 and reinforced by [b52499c3](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/b52499c3134e694aee4bf0059144d2ab2cbb4de5).

## Expected and actual

Expected: a configuration with `rpc_stats_interval = 0` reaches the stats tracker and disables periodic tracking, as specified. Actual: configuration loading rejects it; [node construction panics on the returned configuration error](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/node/app.go#L1006-L1009). This prevents starting with the specified disabled setting. The separately scheduled worker-pool printer is started with a fixed five-second interval, not this setting ([rpcstack](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/rpc/rpcstack.go#L220-L222)).

## Validation

1. Set `rpc_stats_interval` to zero in a valid RPC configuration and load it through the normal configuration path; observe the validation error before tracker construction.
2. Compare with the existing [tracker zero-disable regression test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/039e5adc21d328c5a1b7275e9649076c7d444e31/rpc/stats/repair_m1294_test.go#L150-L195) and the audit requirement linked above.

## Acceptance criteria

- Reconcile the configuration contract with the tracker and governing specification. If zero remains the supported disable value, accept zero and safely disable tracking through normal startup while rejecting invalid negative values as appropriate.
- Add configuration-to-tracker coverage for zero and positive intervals, and retain protection against invalid ticker intervals on the separate printer path.

Evidence is static source inspection; these validation steps were not executed.
