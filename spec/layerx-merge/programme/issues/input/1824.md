# Issue 1824: [P3] Emit the declared license in both Python wheel metadata generators

## Summary

The manifest update in [51fdcd59](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/51fdcd5919fc922ce1ea7080a310a0d1f7a29289) declares Apache-2.0 for the Python SDK and FastAPI integration, but their custom wheel generators still emit the previous generic license text. Rechecked at current main `f9eba5cd3830db8b94bc032efb90e57d3ffb8591` on 2026-11-07 at 18:17 UTC.

## Producer and consumer evidence

- [FastAPI pyproject.toml](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/sdk/integrations/fastapi/pyproject.toml#L1-L13) and [Python SDK pyproject.toml](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/services/agent/sdk/python/pyproject.toml#L1-L12) both select the local `build_backend` and declare `license = "Apache-2.0"`.
- [FastAPI metadata generation](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/sdk/integrations/fastapi/build_backend.py#L18-L30) and [SDK metadata generation](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/services/agent/sdk/python/build_backend.py#L17-L29) hardcode `License: See the LayerX repository LICENSE`. Neither reads the project license.
- Their `_source_files` functions place this generated content in the wheel's `.dist-info/METADATA`.
- [The new manifest tests](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/tests/ci/test_manifest_license_fields.py#L145-L165) read pyproject.toml. The [license checks](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9eba5cd3830db8b94bc032efb90e57d3ffb8591/tests/ci/test_manifest_license_fields.py#L215-L254) never inspect a built wheel, so they cannot catch the divergence.

## Expected versus actual

Expected: both distributed wheels expose the license declared in their project metadata, using an appropriate core-metadata field and version.

Actual: both wheels contain `License: See the LayerX repository LICENSE` and no `License-Expression`. Artifact consumers such as installed-package metadata readers and license inventories do not receive the new Apache-2.0 declaration. This is a packaging metadata defect; no installation failure or legal-compliance conclusion is claimed.

## Reproduction and validation

In a disposable checkout, run this dependency-free check from the repository root:

```python
import email
from pathlib import Path
import runpy
import tempfile
import tomllib
import zipfile

for root in (
    Path("sdk/integrations/fastapi"),
    Path("services/agent/sdk/python"),
):
    project = tomllib.loads((root / "pyproject.toml").read_text())["project"]
    backend = runpy.run_path(str(root / "build_backend.py"))
    with tempfile.TemporaryDirectory() as output:
        wheel = backend["build_wheel"](output)
        with zipfile.ZipFile(Path(output) / wheel) as archive:
            metadata = email.message_from_bytes(
                archive.read(f'{backend["DIST_INFO"]}/METADATA')
            )
    print(root, project["license"], metadata["License"],
          metadata["License-Expression"])
```

Observed for both backends: manifest `Apache-2.0`, wheel `See the LayerX repository LICENSE`, expression `None`.

During this review, the actual unchanged backend files were executed in isolated temporary directories, and the generated METADATA was read from the resulting wheels. Package source was intentionally not populated; this verifies the metadata generator, not a complete package build, installation or test suite.

## Acceptance criteria

1. Make the SDK and FastAPI wheel metadata reflect their declared project license without a second drifting source of truth.
2. Use a core-metadata version and license field that agree with each other.
3. Add a regression that invokes both real backends, opens the wheels and compares their license metadata with pyproject.toml.
4. Preserve deterministic wheel output and existing dependency metadata.
