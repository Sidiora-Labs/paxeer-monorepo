# Issue 1771: [Coherence] Explorer docs relocation leaves the image builder reading the deleted environment catalogue

## Defect and impact

The Explorer documentation move in e715884386cf0807c06b68ff7e98490c6e68b2c4 relocates the environment catalogue from apps/explorer/docs/ENVS.md to docs/explorer/ENVS.md, but the production image still copies only apps/explorer and reads the deleted in-image path.

A clean frontend image build that reaches the builder stage cannot generate its required .env.registry from that path. The collector masks the missing-input error, and the runner later requires the missing registry. Catalogue-only changes also no longer match the image workflow's path filter.

Kind: connective. Suggested severity: build blocker.

## Expected repair and regression coverage

1. Copy the relocated catalogue explicitly into the frontend builder and align the collector argument with its in-image location.
2. Include the catalogue in the image workflow's path filter.
3. Fail immediately when the collector input is missing or unreadable.
4. Test the production build-context mapping and assert that registry generation contains known catalogue variables. Include a missing-input negative case.
