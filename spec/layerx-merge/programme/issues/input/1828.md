# Issue 1828: [P2] Scope interop baseline skips to their recorded Cargo target

## Expected versus actual

The interop failure baseline identifies each exception by member, Cargo target and qualified test name. Retiring one repaired entry should put that individual test back on the CI path. The new runner instead passes all names as global `--skip` arguments to `cargo test --workspace`, so a remaining entry in another binary continues to suppress the repaired test.

This is already reproducible with real baseline identities: `layerx-interop-service --test private_network private_network_route_coverage` and `layerx-interop-service --test repair_22_33_91 private_network_route_coverage`. Both are currently recorded failures. This report does not claim either currently passes or is an unlisted exception today. It concerns the runner's failure to honor individual retirement, and the same selection behavior can suppress an otherwise unlisted same-named test in another target.

## Bounded reproduction and impact

Load the committed runner and baseline in a scratch copy. Remove only the `--test private_network` entry above from the list returned by `read_baseline()`, representing its retirement after repair. Call `workspace_test_command()`.

Observed in an executed Python command-generation check: the result still contains `--workspace --no-fail-fast -- --exact` and `--skip private_network_route_coverage`, contributed by the retained `--test repair_22_33_91` entry. There is no package or target selection separating the two. Thus the repaired private_network test remains filtered out even though its baseline entry is gone.

## Acceptance criteria

- Scope each skip to the recorded member and Cargo target, preserving execution of all other workspace tests and failure propagation.
- Add a regression with identical qualified test names in two targets. After retiring one entry, that target's test must run while the other remains skipped.
- Verify a same-named test in a third, unlisted target is never skipped.
- Run the runner's regression suite and an appropriate Cargo integration check at the final revision; record actual results.
