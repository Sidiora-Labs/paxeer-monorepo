# Issue 1682: [Coherence] IsHistoricalReplay disagrees with the precompile version selector, so the final part of the v5.7.5 replay range takes the current association path

## Defect and impact

The new guard decides from ctx.ClosestUpgradeName(), which the trace context fills from UpgradeKeeper.GetClosestUpgrade. That function returns the earliest upgrade whose done height is at or after the requested height, so it names the next upgrade. The precompile selector works the other way and uses the most recent versioned upgrade at or before the height. At traced heights after v5.9.0 and before v6.0.0, the selector still runs the v5.7.5 addr precompile, but ClosestUpgradeName is "v6.0.0". The guard therefore returns false, and AssociateAddresses and MigrateBalance are rerouted to the current helper. That helper keeps a self-migrated account, copies account number and sequence, and rejects keys differently, so historical traces in that window stop reproducing the original state transitions.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Every traced height at which the selector runs the v5.7.5 addr precompile should take the historical association and migration body, as the comment "matches the owning precompile selector's v5.7.5 range" claims.

Actual: Between the v5.9.0 and v6.0.0 done heights, ClosestUpgradeName is "v6.0.0" and the guard returns false, so v575 traces run the current helper. The tests set ClosestUpgradeName by hand and never check it against GetClosestUpgrade.
