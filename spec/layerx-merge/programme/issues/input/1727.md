# Issue 1727: [Coherence] Existing CLI tests still assert the retired /rpc and /rpc/ws routes and the old dropped-reply error, so they now fail

## Defect and impact

The commit moves program submission, receipts and subscriptions to the root path. It also makes a dropped submission reply return Ok with rung "unknown" instead of an error. None of the existing tests that pin the old behaviour were updated. Unit tests in rpc.rs build RpcClient::new("http://127.0.0.1:1/rpc") with `?`, which now returns Err, so the tests abort. The program EVM capture servers assert `POST /rpc` and expect submit_* to return Err when no reply comes. wallet_watch_logs still expects the upgrade on /rpc/ws.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Tests that pin the endpoint path and the dropped-reply outcome move to the root endpoint and the rung-unknown recovery result, matching the new repair test.

Actual: rpc.rs unit tests, program_evm_lifecycle, program_evm_calls, program_evm_registry, wallet_watch_logs and wallet_estimate_fee still assert /rpc, /rpc/ws or an error on a dropped reply, which contradicts the new code.
