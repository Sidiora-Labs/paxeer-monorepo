# Issue 1643: [P2] Align Autobahn newHeads test fixture with committed-block hash validation

## Summary

Commit [0bdbbf4a9afba2badd9cddf2594a1b4209e82e89](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/0bdbbf4a9afba2badd9cddf2594a1b4209e82e89) makes the newHeads consumer load the committed HTTP block and refuse an event whose hash differs from that block. The existing Autobahn subscription test still injects an unrelated hash and expects the injected header's other fields, so its positive-delivery fixture no longer satisfies the production contract.

Rechecked on main at 682071e466ac88ee2dfbe65f87e1870a5d3a5a2c; rpc/subscribe.go, rpc/subscribe_test.go and rpc/setup_test.go are unchanged from the reviewed b664b08b724ec5b190920b99ba70b283c8a796c9 snapshot. This is a static finding. No tests, builds, node calls or transactions were executed.

## Expected and actual

Expected: a positive Autobahn subscription fixture represents the same committed block returned by the mock consensus client, receives its notification and reaches the nested committed-block coverage.

Actual from source: this fixture's event is intentionally refused by the new hash check. In an isolated run its own notification never arrives; in a package run, an unrelated notification cannot satisfy the test's expected 0x4242… hash either. This blocks the positive subscription regression and can prevent the nested test from executing. No deployed subscription failure is claimed here.

## Validation and acceptance

1. In the repository's supported Go test environment, run `go test ./rpc -run '^TestSubscribeNewHeadsAutobahn$' -count=1` and record the exact revision, exit status and output. This command has not been run for this report.
2. Build the positive event and its expected hash, parent, timestamp, proposer and state fields from the exact block served by the fixture. Retain the hash equality check in production.
3. Keep a separate negative test proving that a genuinely mismatched event is refused without killing subsequent valid notifications.
4. Verify the top-level test reaches its nested committed-block test. Diagnose any subsequent failure independently instead of weakening assertions.
