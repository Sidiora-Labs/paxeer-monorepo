# Issue 1715: Reconcile nextSequence identifier used by web payer with Ledger ABI

## Summary

[e986a769](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/e986a76986d1edcbfbc52251a405797a438f1208) changes [GrantTerms.next_sequence_call](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/882840b59509ce8ab836301539341fb7d08a37fa/services/agent/crates/layerx-mcp/src/tools/web.rs#L756-L763) to pass a receiver DID key. The [production payer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/cd92cc7ca508130c829d79dd34fb8d418c86fe62/services/agent/crates/layerx-agentd-host/src/payer.rs#L401-L422) executes that read directly, but current [Ledger dispatch](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/882840b59509ce8ab836301539341fb7d08a37fa/precompiles/layerxledger/views.go#L96-L106) resolves an account ID. The [native regression](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/cd92cc7ca508130c829d79dd34fb8d418c86fe62/precompiles/layerxledger/repair_144_test.go#L191-L202) explicitly rejects a DID key in this argument.

## Validation

Using the existing native fixture with distinct receiver DID key and canonical asset-account ID, encode `GrantTerms.next_sequence_call()` and send it as a read to the Ledger precompile. Expected: the account's sequence is returned. The current source instead passes the DID key, which the native regression expects to reject as `LXP_UNKNOWN_ACCOUNT_NAMESPACE`. Supplying the account ID is the supported native path. No draw execution is needed.

The web-payer repair record cites decision 2592/gotcha 3133 for the DID-key choice, while native repair 144 specifies account-ID resolution; please reconcile those contracts. This finding is source-verified; no tests or transactions were executed here. Built-in metered purchasing is already unavailable through retired grants and current exact-only offers, so this report does not assert a new live purchasing outage or request restoration of retired grants.

## Acceptance criteria

- Reconcile the web-payer and native ABI owners and align the exported helper with the supported identifier contract.
- Update consumer tests to exercise native account lookup with distinct DID and account identifiers, including rejection of the wrong namespace.
- Preserve the existing retirement behavior for metered grants unless separately authorized.
