# Issue 1922: [Coherence] The layerx-agentd-host and layerx-mcp lint tasks lint targets whose source files lie outside the paths those tasks may touch

## Defect and impact

Task 22.39.223 runs clippy with --all-targets on layerx-agentd-host. That package's binary and four of its five test targets are files inside layerx-agentd (src/main.rs and host-tests/*.rs), but the task only touches services/agent/crates/layerx-agentd-host. Its do_2 says "nothing outside the touched paths changes", so any lint in those files is reported but cannot be repaired, and the task cannot go green. Task 22.39.222 cannot pick these lints up either: it lints the daemon with --lib only, so main.rs is never covered. Task 22.39.224 has the same problem: the layerx-mcp test target `injection` lives at services/agent/tests/mcp/injection.rs, outside its touched path. Task 22.39.229 already handles this case for limits-exactly-once by adding services/agent/tests/limits to its touched paths.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Tasks 22.39.223 and 22.39.224 should list every path their --all-targets lint compiles: layerx-agentd/src/main.rs, layerx-agentd/host-tests and services/agent/tests/mcp. Alternatively, those targets should go to a task that touches those paths.

Actual: Both tasks lint targets they are not allowed to edit, so a lint there either can never be repaired within the task or forces an edit that breaks its path policy.
