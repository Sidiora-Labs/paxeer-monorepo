# Issue 1701: [Coherence] A failed segment construction still leaks the value file handles of shards that opened before the failing shard

## Defect and impact

The repair adds a deferred close for the key file handle when CreateSegment fails, and its record says no segment descriptor survives a constructor failure. The shard loop still returns straight out on a createValueFile error, though, so every value file that already opened for an earlier shard stays open: each one holds an os.File and a bufio.Writer and nothing ever closes them. The new constructor test only uses sharding factor 1 and makes shard 0 fail, so no earlier shard is ever open and the test cannot catch this leak.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: When CreateSegment fails it closes every handle it has already opened, both the key file and the value files of earlier shards, as the repair record states.

Actual: Only the key file handle is closed. If shard k>0 fails, for example when its value file already exists, the value file descriptors of shards 0..k-1 leak.
