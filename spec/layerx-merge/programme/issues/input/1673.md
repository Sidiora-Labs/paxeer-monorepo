# Issue 1673: [Coherence] Signed ID-token verification breaks the existing confirm-OTP controller test, which still feeds an unsigned HS256 token and mocks no key-set request

## Defect and impact

get_user_from_token used to just read the claims from the ID token. It now only accepts RS256 tokens that carry a key id, are verified against the Auth0 key set at /.well-known/jwks.json, and have matching iss/aud/exp/iat claims. The block_scout_web authenticate-controller test "confirm OTP successfully" was not updated. It still builds a fake token with alg HS256, no kid, a junk signature and no iss/aud/exp/iat, and its Tesla mock allows exactly three calls with no key-set GET. The header check now returns :error, so the endpoint answers with an error instead of 200 and the test fails. It was the regression guard for the confirm_otp body-params fix.

Kind: connective. Severity: major.

## Expected versus actual

Expected: The confirm-OTP controller test should sign its ID token with an RS256 key that has a kid and valid iss/aud/exp/iat claims, and should mock the /.well-known/jwks.json response, so it still exercises the success path.

Actual: The test still sends an unsigned HS256 token with no kid, so get_user_from_token returns :error, confirm_otp responds with an error instead of 200, and the test fails.
