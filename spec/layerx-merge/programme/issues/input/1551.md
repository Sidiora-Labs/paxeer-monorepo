# Issue 1551: [P2] Decode canonical receipt-key responses in both public PxClient SDKs

## Expected versus actual

TypeScript PxClient.getReceiptKeys and Python PxClient.get_receipt_keys should read the served px_getReceiptKeys response. Both currently reject it before returning pins.

Verified at current main bb835c328bf7242fe3b45e75e58c2d615b82b03e during review of [b333bce's node endpoint](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/b333bce4cf409f360f0e236826d6ad24a3258d79). This is a preexisting gateway/client mismatch exposed by another producer of the same format, not a claim that b333 introduced the obsolete clients.

## Producer/consumer evidence

- [Node](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/rpc/sequencer_receipt.go#L329-L379) and [gateway](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/platform/hosted/gateway/src/chain_reads.rs#L281-L300) return result: {keys:[...]}, with 0x-prefixed 32-byte keyId/publicKey and numeric firstHeight/lastHeight.
- [TS public method](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/typescript/src/px.ts#L177-L178) calls the transport, which [wraps the result again](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/typescript/src/px.ts#L227-L242). Its keys property is now an object, and [array-only decoding](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/typescript/src/px.ts#L470-L504) throws Invalid gateway receipt keys.
- [Python public method](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/python/layerx_sdk/px.py#L291-L292) traverses [call's list-only special case](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/python/layerx_sdk/px.py#L377-L381), which rejects the canonical object as invalid-px-result.
- Both byte decoders still require canonical 44-character base64, so fixing only the envelope is insufficient: [TS](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/typescript/src/px.ts#L498-L504), [Python](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/python/layerx_sdk/px.py#L578-L607).
- [Shared parity fixtures](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/services/agent/sdk/typescript/test/px.test.ts#L654-L857) use bare lists/base64 and explicitly reject {keys:[...]}. They prove agreement between stale consumers, not agreement with either producer.
- [D801](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bb835c328bf7242fe3b45e75e58c2d615b82b03e/spec/layerx-merge/docs/decisions/D801.md) requires clients and router to share pinned receipt keys.

## Concrete validation (not executed)

Serve a loopback JSON-RPC fixture that echoes the request ID and returns:

```json
{"jsonrpc":"2.0","id":1,"result":{"keys":[{"keyId":"0x1111111111111111111111111111111111111111111111111111111111111111","publicKey":"0x2222222222222222222222222222222222222222222222222222222222222222","firstHeight":1,"lastHeight":100}]}}
```

Invoke each exported PxClient receipt-key method against it. Expected: one decoded entry. Actual by source: TS rejects the nested object and Python rejects the result object; unwrapping alone then encounters the base64-only check.

No builds, tests or live RPC calls executed. This is fail-closed pin retrieval failure, not a deployed incident or receipt-verification bypass. Rust SequencerEndpoint, Python x402 RPC and TypeScript gatewayReceiptKeys have separate canonical decoders; this report does not claim all SDK receipt handling is broken.

## Acceptance

- Consume the canonical object and hex fields in both public PxClient paths.
- Preserve key bytes, order and inclusive ranges, including empty and rotated key lists.
- Retain malformed-key/range/duplicate rejection and JSON-RPC error propagation.
- Add public-method loopback success tests using actual producer format, not only cross-language decoder parity.
