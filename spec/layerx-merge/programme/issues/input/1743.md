# Issue 1743: [Coherence] The production daemon's native-read 503 body now includes a Debug dump of the internal error, which contradicts the serve-errors contract and the module's own no-behaviour-change claim

## Defect and impact

The commit is described as test isolation, but it moves the shared HTTP module into tests/proof_native_reads.rs, and main.rs compiles that module into the shipped daemon through proof_serve_errors.rs. In the same move, native_read_response stopped returning the fixed body {"error":"verified_read_unavailable"} and now adds a "detail" field holding format!("{error:?}") of NativeReadError. That value includes variants such as Connection(SequencerError::Rpc(RpcRefusal{message})), so upstream node error text reaches agent clients unfiltered. agent-api.md still documents these as small {"error":"..."} listener errors, and the module header still says no error code or status semantics change.

Kind: cross-system. Severity: minor.

## Expected versus actual

Expected: A commit that only isolates the live-node tests should leave the daemon's wire body as {"error":"verified_read_unavailable"}. Any added diagnostic field should be specified in agent-api.md and kept free of upstream error text.

Actual: Every native-read 503 from the production daemon now carries a "detail" string with the Rust Debug form of the internal error. The contract and the module header were not updated.
