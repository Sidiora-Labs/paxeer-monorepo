# Issue 1882: [P2] Align compiled gateway schema test with the 22-method publication

## Problem

The compiled gateway schema test still expects 17 methods, while the OpenRPC document it embeds contains 22. The real router-authority-schema gate runs this test before its newly aligned Python inventory check, so it refuses before reaching that check or its node probes.

Verified at main `dd4addbf677b3c65e139efa6b4f44c2858fdedbd` on 2026-11-08 at 17:50:08 UTC. This mismatch already exists at interval base `996b8669dae51129b0f1c7e97791e7b8a6144b2c`; this review found it while checking the new Python alignment, rather than attributing its introduction to that change.

## Expected versus actual

Expected: the current-source schema gate executes one successful compiled schema test, validates the combined publication and then reaches its node dispatch probes.

Actual:

- [schema_lists_every_public_method](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/dd4addbf677b3c65e139efa6b4f44c2858fdedbd/services/platform/hosted/gateway/src/rpc.rs#L288-L325) embeds `../openrpc.json`, checks one copy of each of 17 declared names, then asserts `methods.len() == published.len()`.
- The [current OpenRPC document](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/dd4addbf677b3c65e139efa6b4f44c2858fdedbd/services/platform/hosted/gateway/openrpc.json) has those 17 entries plus `px_getInferenceRooms`, `px_getInferenceRoom`, `px_getInferenceDeal`, `px_getInferencePeer` and `px_getInferenceReceipts`: 22 entries in total.
- [The Python qualifier](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/dd4addbf677b3c65e139efa6b4f44c2858fdedbd/tools/qualification/paxeer-x/router-authority-schema.py#L119-L145) first executes the source-bound gateway test binary with this exact Rust test name. It requires a successful exit and exactly one passing test before calling `hosted_schema`.
- `hosted_schema` was aligned to the combined 17 hosted plus five inference publication, but the preceding compiled test remains unchanged.

The real gate therefore encounters a 22-versus-17 assertion failure before the updated Python path. This is a maintenance/test-contract defect; no production routing failure, security bypass or deployed impact is established.

With repository build prerequisites installed, run:

`cargo test --locked --manifest-path services/platform/Cargo.toml -p layerx-platform-gateway rpc::tests::schema_lists_every_public_method -- --exact --nocapture`

Both source blobs are identical between the interval base and current main. Cargo/Rust tests and live node probes were not run.
