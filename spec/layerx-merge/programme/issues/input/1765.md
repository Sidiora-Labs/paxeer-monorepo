# Issue 1765: [Coherence] The repair_22_31_564 byte-limit test still asserts the old observer refusal text without a site, so it fails now that every supplement refusal adds a site name

## Defect and impact

After this commit, every path that makes the runtime's supplement callback fail records a site name first, and wasmi turns any callback error into SupplementRejected. So `execution_observer_reason` now always ends the reason with " at <site>". The existing test `replay_capture_still_refuses_byte_and_boundary_profile_limits` runs a trivial guest under the same 128-boundary, 512-byte profile as the new refusal test, but still expects the exact string with no site. The commit did not update it, and the task's verify_cmd only runs `--test repair_22_31_569`, so the crate's test suite now fails at that assertion.

Kind: connective. Severity: major.
