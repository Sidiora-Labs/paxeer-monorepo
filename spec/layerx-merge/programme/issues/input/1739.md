# Issue 1739: [Coherence] Two of the five refusal cases check nothing in production code; each asserts a value the test set itself one line earlier

## Defect and impact

The repair record says the gate checks an altered membership proof and insufficient read verification against the consumer's rejected promotions. In the test, case 4 sets read_verification = 1 and then asserts read_verification == 1. Case 2 appends a byte to the proof and then asserts that its SHA-256 differs from the saved digest. Both assertions always hold, so no guest, codec or membership refusal path runs for these two cases, and they would still pass if the refusal broke.

Kind: semantic. Severity: minor.
