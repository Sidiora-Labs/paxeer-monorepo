# Issue 1772: [P2] Source Control cannot submit a successful host checkpoint

## Defect and impact

A successful checkpoint from an attached host cannot enable **Submit durable revision** in the Source Control panel. The new submit gate requires `durableEvidence`, but the host-checkpoint path returns a slice summary and never sends durable checkpoint evidence to the reducer. The workspace read that follows updates the revision without restoring the missing evidence.

Severity: P2. This is a UI workflow blocker, not a claim of lost data or an authorization bypass.

Introduced by 12a2cd53683f87ee80ee4878b4ad7cbb320a99ff. Source checked on main at 761ad72306b035aa1a8aa878549870f0b5fef3f3.

[That evidence must match the current workspace and base revision](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/plugins/hyperfide-source-control/views/workspace-detail.tsx#L87-L102).
- [The host checkpoint handler](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/plugins/hyperfide-source-control/views/workspace-detail.tsx#L183-L195) calls `checkpointHost`, stores its slice-summary result only in the local display, then executes a `workspace` read. Neither step updates the panel's evidence reducer.
- [workspaceReceiptEvidence](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/plugins/hyperfide-source-control/app.tsx#L49-L99) creates initial ACKNOWLEDGED evidence only for a successful `execute` action with `kind: "checkpoint"`. A `workspace` read produces no evidence.
- [The panel initializes evidence as an empty in-memory array](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/plugins/hyperfide-source-control/app.tsx#L128-L149). Existing workspace data alone cannot satisfy the gate.

- [The actual host provider completes NativeWorkspaceCheckpoint, saves its workspace/revision, then returns only sliceId, snapshotChain and fallbackReason](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/sdk/source-control/src/host/provider.ts#L446-L479). The full checkpoint receipt is not carried through this host response.

## Reproduction from the source path

1. Open an assigned file-backed workspace in a fresh Source Control panel and attach its host.
2. Make a valid workspace change and successfully checkpoint it through the host checkpoint control.
3. Inspect the matching assignment after the workspace refresh. Assume no pending request or dirty panel edit, so the other submit conditions are satisfied.

Expected: The acknowledged host checkpoint makes its durable revision available for submission.

Actual: The host slice summary is displayed and the refreshed workspace names the checkpointed revision, but no matching `durableEvidence` exists. **Submit durable revision** remains disabled. An ordinary panel reload also discards previously acknowledged evidence.

## Suggested repair and regression coverage

Carry the acknowledged checkpoint identity through the host response, or obtain it through an authoritative read, then apply the same validated evidence update used by the API-only checkpoint path. Match operation/workspace/revision identity rather than treating the current slice summary as a full checkpoint receipt. Restore or revalidate durable evidence when reopening a workspace, without accepting an unacknowledged local edit as durable.

Cover an attached-host checkpoint followed by assignment submission, plus reopening a previously checkpointed workspace. The new browser fixture uses [an empty assignments list](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/761ad72306b035aa1a8aa878549870f0b5fef3f3/tools/hyperfide/tests/hyperfide/support/native_source_product_browser.mjs#L136-L142), so its current journey does not exercise this submit gate.

Validation: static producer/consumer and UI state-flow inspection only. No browser run, build, deployed failure, or data-loss claim. Current-head and all-state issue/PR duplicate checks were completed before filing.
