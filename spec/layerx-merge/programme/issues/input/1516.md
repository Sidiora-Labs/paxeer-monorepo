# Issue 1516: [Coherence] The shipped example fulfilment repository still enforces the request digest on read, so a reused receipt gets fulfillment-conflict instead of settled_receipt_reuse

## Defect and impact

The seller now stores fulfilments under a key built from the verified receipt and leaves the request-digest comparison to handle(), which raises 409 settled_receipt_reuse. The example FileFulfillmentRepository was not updated. On a key hit it still compares the stored requestDigest with the proposed one and raises FULFILLMENT_CONFLICT. Integrators who copy the example therefore get a 409 {"error":"fulfillment-conflict"} for a reused receipt, never the receipt-reuse refusal the task specifies.

Kind: connective. Severity: minor.

## Expected versus actual

Expected: The example repository returns the stored record on a key hit and leaves the request-digest comparison to SellerMiddleware, so a reused receipt is refused with settled_receipt_reuse.

Actual: The example repository raises FULFILLMENT_CONFLICT when the request digest differs, so the receipt-reuse refusal never reaches clients built on the example.
