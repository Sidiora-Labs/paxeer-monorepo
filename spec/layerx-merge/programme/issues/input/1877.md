Verified on current main `ca33c0c50b4166d7a73afe0a728a9459a3d78610` and PR #658 source `72fbd902a78cd70ddebde8daf4ce4bd726f7cc64`, with identical affected blobs. ## Expected versus actual
Expected: the surface test follows the SDK's authenticated fallback contract and asserts the requests actually needed for the signed fixture, while retaining receipt verification.

Actual: [repair-22-33-206.test.ts](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ca33c0c50b4166d7a73afe0a728a9459a3d78610/apps/wallet/src/surfaces/test/repair-22-33-206.test.ts#L131-L153) expects ten RPC requests. [sendModuleTransaction fallback](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ca33c0c50b4166d7a73afe0a728a9459a3d78610/sdk/wallet/src/modules/index.ts#L82-L112) returns the already authenticated polling result after checking authentication and transaction identity, so the trace has eight requests. The extra keys/raw-transaction pair is no longer performed.

The [receipt reader](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ca33c0c50b4166d7a73afe0a728a9459a3d78610/sdk/wallet/src/receipt.ts#L626-L637) and [polling return](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ca33c0c50b4166d7a73afe0a728a9459a3d78610/sdk/wallet/src/receipt.ts#L687-L695) preserve authentication. The [producer repair record](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/ca33c0c50b4166d7a73afe0a728a9459a3d78610/sdk/wallet/test/repair_22_39_145.kvx#L207-L209) explicitly documents removal of redundant reads. This is test-consumer drift, not a finding of missing authentication or unsigned receipt acceptance.
