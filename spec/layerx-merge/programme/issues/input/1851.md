# Issue 1851: [Coherence] The new FastAPI `test` extra is declared in pyproject.toml but the package's own build backend never emits it, so `layerx-fastapi[test]` installs no test dependencies

## Defect and impact

The commit adds `[project.optional-dependencies] test = [...]` to sdk/integrations/fastapi/pyproject.toml. But the package builds through its own deterministic backend, which hardcodes the wheel metadata from a REQUIRES tuple and never reads pyproject.toml. The built wheel therefore has no `Provides-Extra: test` and no conditional `Requires-Dist` lines. Anyone who runs `pip install layerx-fastapi[test]` gets a warning about an unknown extra and none of pytest, httpx or cryptography. The new wiring test only compares the pyproject table with tests/requirements.txt, so it passes even though the declared extra does nothing.

Kind: connective. Severity: minor.

## Expected versus actual

Expected: A declared `test` extra should appear in the built wheel's metadata, for example as `Provides-Extra: test` with conditional `Requires-Dist` lines. Otherwise the extra should not be declared, and tests/requirements.txt should stay the only source.

Actual: pyproject.toml advertises a `test` extra that the deterministic backend drops, so installing `layerx-fastapi[test]` silently installs no test dependencies.
