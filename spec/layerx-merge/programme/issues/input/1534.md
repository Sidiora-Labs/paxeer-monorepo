# Issue 1534: [Coherence] The new build_cmd of task 22.9.33 asks for a serve_routes test target on a package that does not have one, so the build fails before it compiles anything

## Defect and impact

The rewritten build_cmd opens with `cargo test -p layerx-agentd --test proof_serve_errors --test serve_routes --no-run`. serve_routes is declared only as a [[test]] of layerx-agentd-host, whose source sits in layerx-agentd/host-tests/, and layerx-agentd has no tests/serve_routes.rs. Cargo will reject the command with "no test target named serve_routes". The verify_cmd already had this error, but this commit copies it into the build, so the attempt that decision 2374 was meant to unblock now fails at the build step instead of qualifying.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: The build, and the verify too, should select serve_routes from its owning package, for example `-p layerx-agentd --test proof_serve_errors` plus `-p layerx-agentd-host --test serve_routes --no-run`.

Actual: Both build_cmd and verify_cmd pass `--test serve_routes` to `-p layerx-agentd`, so the first command of the build exits with an error and the task cannot qualify.
