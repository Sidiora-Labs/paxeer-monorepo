# Issue 1583: [P2] Refresh retained Rust sequencer receipt fixtures

## Problem
[Commit 8f269091](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/8f26909112d273c2e2215d00eafea8f29b12a797) requires `paymentDenom` and canonical receipt bytes in the Rust client. At [8b703ec](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/8b703ec72e65d1ee56c9e5c5c56ddefc2c1de22b), the retained [fixture helper](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8b703ec72e65d1ee56c9e5c5c56ddefc2c1de22b/services/agent/crates/layerx-client/tests/sequencer.rs#L125-L130) omits that field and supplies truncated receipt bytes. The [receipted/committed success test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8b703ec72e65d1ee56c9e5c5c56ddefc2c1de22b/services/agent/crates/layerx-client/tests/sequencer.rs#L196-L225) expects this response to decode successfully, but the [exact field check](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/8b703ec72e65d1ee56c9e5c5c56ddefc2c1de22b/services/agent/crates/layerx-client/src/sequencer.rs#L914-L958) rejects it. Adding the field alone is insufficient because canonical decoding and asset binding are also required.

## Expected vs actual
Both valid rungs should decode using producer-compatible full receipts. The retained fixture is now malformed, and negative cases derived from it can pass for the wrong reason. This is a source-verified test regression, not a claimed production incident.

## Validation
Run `cargo test --locked --manifest-path services/agent/Cargo.toml -p layerx-client --test sequencer receipted_and_committed_receipts_decode_every_field -- --exact`. This test was not executed here. Full aggregate specification ownership could not be exhaustively checked.

## Acceptance criteria
- Replace the helper and expected receipt with valid producer-derived bytes and payment/fee denomination fields.
- Verify successful decoding of both receipted and committed rungs.
- Ensure each malformed test starts with a valid response and fails for its intended mutation.
