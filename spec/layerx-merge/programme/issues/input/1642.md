# Issue 1642: Reconcile merged staking key-length errors with retained regression tests

## Defect and impact

The merged staking key-length guard preserves safe input refusal but changes the error text before the existing detailed guard can execute. Two retained task 1201 regression tests still require the detailed error, so their activated malformed-key cases contradict the integrated production path.

- [Direct wrapper assertion](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/64e36714e3c1ce81b232d9fe7bece6c561dadf59/precompiles/staking/repair_m1201_test.go#L136-L141) requires the exact detailed message for an empty key after activation.
- [Wrapper](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/64e36714e3c1ce81b232d9fe7bece6c561dadf59/precompiles/common/precompiles.go#L365-L376) invokes HandlePrecompileError before replacing the outer error with execution reverted; [handler](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/64e36714e3c1ce81b232d9fe7bece6c561dadf59/precompiles/common/precompiles.go#L257-L263) stores the original error, so GetPrecompileError cannot contain the absent suffix.

Expected: the integrated producer and both regression consumers agree on the refusal contract. Actual: the first guard's shorter error contradicts both tests. This is a test-contract integration regression, not a claim that malformed keys are admitted or that deployed staking fails.
