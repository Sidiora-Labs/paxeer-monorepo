# Issue 1634: [P2] Keep state-size scanning after the memiavl true-to-stop change

## Defect and impact

Commit [7776fa009cdb31ed4b6a5f9c085a8d03574a658a](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/7776fa009cdb31ed4b6a5f9c085a8d03574a658a) makes memiavl `ScanPostOrder` honor **true = stop**, but the kept `collectModuleStats` caller still returns true after every node. A nonempty tree therefore stops at its first leaf. For modules with multiple keys, `paxdb state-size` silently reports one key and only that leaf's bytes, prefix counts and contract totals. The same incomplete `ModuleResult` feeds console output and optional DynamoDB export.

Confirmed present on current main `7db6d22eaa62b539c8b57f4a181aef4403389ad9`. This concerns operator analytics; no consensus, stored-state corruption or security impact is claimed.

## Expected versus actual

Expected: the visitor continues over every node and includes every leaf in state-size totals, while exporter cancellation keeps the new true-to-stop behavior.

Actual: the first leaf ends the scan, so a two-key module reports one key and undercounts its bytes.

## Reproduction / validation

Run the existing focused consumer test:

```sh
go test -count=1 -v -run '^TestRepairM_1177_ModuleInventory$' ./storage/tools/cmd/paxdb/operations/
```

Source-predicted failure: the report contains `total numKeys:1` rather than the unchanged expected `total numKeys:2`, with correspondingly incomplete byte totals.

Static review only: no build, test, production command or DynamoDB write was performed.

## Acceptance criteria

1. Adapt the state-size visitor to the true-to-stop contract so it visits all leaves.
2. Preserve the existing two-key inventory/count/byte assertions without weakening them; verify both default and explicit-module reports.
3. Preserve the memiavl early-stop and export-cancellation assertions from task 22.33.1200.
4. Cover multiple prefixes and contract keys so their aggregate totals are also complete.
