# Issue 1511: [P2] Restore PAY2's standalone lockfile for its declared locked qualification gates

## Summary

[a9a7222](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/a9a72229033ad1ff9513a28c686c6e6b6537d376) deletes services/agent/qualification/pay2/Cargo.lock while task 22.9.32 still declares locked Cargo build and test-compilation gates. The lockfile remains absent at current revision 2c94eb0e41325a640dc2842f8e6e815503c5634f.

## Contract evidence

- [PAY2 Cargo.toml](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c94eb0e41325a640dc2842f8e6e815503c5634f/services/agent/qualification/pay2/Cargo.toml#L1-L9) declares a standalone workspace. The parent agent workspace lockfile does not supply this package's dependency resolution.
- [PAY2 ignore rule](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c94eb0e41325a640dc2842f8e6e815503c5634f/services/agent/qualification/pay2/.gitignore#L1-L2) ignores its local Cargo.lock, so an existing working-directory lock can hide the clean-checkout problem.
- [Task 22.9.32](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c94eb0e41325a640dc2842f8e6e815503c5634f/spec/layerx-merge/spec.kvx#L127002) declares:
  - cargo build --locked --manifest-path services/agent/qualification/pay2/Cargo.toml --all-targets
  - cargo test --locked --manifest-path services/agent/qualification/pay2/Cargo.toml --no-run
- The exact commands were introduced in [cbecc219's task block](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/cbecc219e90f3e467ae5e393b631eec43bb6a696). Subsequent bounded comparison through the current revision changes the task status to done but leaves those commands unchanged.
- [build.rs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c94eb0e41325a640dc2842f8e6e815503c5634f/services/agent/qualification/pay2/build.rs) reads retained qualification source files; it does not supply a lockfile.

## Expected versus actual

Expected: a fresh checkout contains the dependency lock required by the declared --locked gates.
Actual: Cargo needs to create the missing standalone workspace lockfile, but --locked forbids that. This prevents reproducing the gate from a clean checkout; it is not evidence of a deployed runtime failure.

## Reproduction / validation

Static source verification only; these commands were not executed.

1. Use a fresh checkout of 2c94eb0e41325a640dc2842f8e6e815503c5634f, without an ignored pre-existing PAY2 Cargo.lock.
2. Confirm services/agent/qualification/pay2/Cargo.lock is absent.
3. Run the two declared commands above with the repository toolchain and dependencies available.
4. Confirm that missing lockfile resolution prevents the locked build/test-compilation gates.

## Acceptance criteria

- Restore a valid tracked lockfile for this standalone workspace and reconcile the ignore policy.
- Preserve --locked and verify both gates from a clean checkout without local generated prerequisites.
- Keep the LNI-to-node-readiness migration intact.
- Distinguish gate compilation from execution: the retained pay2e_test.rs is a build input, not a registered funded integration-test target, so passing --no-run must not be represented as live PAY2 execution.
