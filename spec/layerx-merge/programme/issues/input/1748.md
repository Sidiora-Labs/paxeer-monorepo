# Issue 1748: [Coherence] The finality proof scenario never makes reward authorization depend on the authenticated SnapshotBinding

## Defect and impact

The finding asks for modified value, key, block and app-hash witnesses to be refused before the binding that authorizes reward actions is accepted. The test only runs the tampered witnesses through its own CommittedRead::verify helper, which checks a header signed by a test-only key. It then routes CLAIM through dispatch without passing it the binding. Nothing in the crate outside queries.rs uses SnapshotBinding, so the Claim would succeed the same way with a forged or missing binding, and the claim that witnesses are refused before authorization is not proven.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: A tampered witness should make the reward-authorizing step itself refuse, with the production consumer reading the binding. If no production consumer exists, that gap should be written up as a wiring request.

Actual: The witnesses are refused only by a test-local helper, and the Claim then succeeds through dispatch whatever the binding contains.
