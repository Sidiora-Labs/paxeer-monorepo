# Issue 1831: [Coherence] Repository-level Python payment tests still use the retired `layerx:125` network and base64 receipt payload

## Defect and impact

`validate_requirements` now accepts only `eip155:<chain>` networks, and the exact payload is now receipt-proof-v2. The repository-level suites under tests/agent/sdk/python were not ported. They still build offers on `layerx:125`, register buyers for `("exact", "layerx:125")`, and compare the prepared payload with the retired `receipt`/`sequencer-signed` shape. `SellerMiddleware.__init__` runs `validate_required` and raises `unsupported-network`, so these tests now fail. They are the verification contracts of other spec tasks.

Kind: connective. Severity: major.
