# Issue 1870: [Coherence] The cancelled-release assertion is satisfied by the new early context check, not by context propagation into the WAL release

## Defect and impact

The repair note says the test asserts that a cancelled driver release writes no WAL entries. That is meant to show the caller context reaches the two ordered releases. But OnCommitContext now returns ctx.Err() right after taking the lock, before any height check, snapshot or release. So the assertion would also pass if d.release still used context.Background(). No test covers a context that expires during the COMMITTED or OPEN release.

Kind: semantic. Severity: minor.

## Source proof

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bc89ead834ccbc9670b2b23aaa16894524057843/node/sequencer/driver.go#L66 — Returns before any release, so propagation is never reached.

  ```go
  if err := ctx.Err(); err != nil {
  		return err
  	}
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bc89ead834ccbc9670b2b23aaa16894524057843/node/sequencer/commit_release_test.go#L207 — The context is already cancelled on entry, so only the early-return check runs.

  ```go
  require.ErrorIs(t, n.Driver.OnCommitContext(cancelled, committedTip, primary.LastCommitID().Hash), context.Canceled)
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/bc89ead834ccbc9670b2b23aaa16894524057843/node/sequencer/driver.go#L158 — The propagation path the repair claims to cover. The test never reaches it.

  ```go
  func (d *Driver) release(ctx context.Context, entry wal.Entry) error {
  ```

Reviewed commits: bc89ead834ccbc9670b2b23aaa16894524057843

## Expected versus actual

Expected: A test should cancel or expire the context while Replicator.Release is in progress and check that the driver halts with that error.

Actual: The test cancels before entry, so only the up-front ctx.Err() guard runs. Propagation into the WAL wait and the replication wait is untested.
