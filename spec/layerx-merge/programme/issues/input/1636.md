# Issue 1636: [P2] Migrate the contracts integration before upgrading to Hardhat 3 in #654

## Scope
PR #654 at `11c7e25858c03e55dc0edc513152ec2f083a0760` changes only `contracts/package.json` and `contracts/package-lock.json`, upgrading the resolved Hardhat from 2.29.1 to 3.21.2 (base `35dd23333c804e28edb33cac3b34e2e7678ad037`). This is a contracts development/build-tooling compatibility regression, not a claim about deployed contracts.

**Static review only.** No npm install, build, test, deployment, RPC request, or live-chain interaction was run. The failure modes below are derived from the checked-in dependency constraints, consumers, and the exact upstream release.

## Expected versus actual
Expected: the dependency update preserves a valid plugin graph and the existing contracts build/test entry points, or includes the coordinated Hardhat 3 migration.

Actual:
1. [The new lock resolves Hardhat 3.21.2](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/package-lock.json#L9011-L9040), but retains twelve plugins with Hardhat-2-only peer requirements. The actively loaded [toolbox 6.1.2 requires `hardhat ^2.28.0`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/package-lock.json#L2642-L2667), and [OpenZeppelin upgrades 3.9.0 requires `hardhat ^2.0.2`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/package-lock.json#L3070-L3095). These same plugin versions/constraints were compatible with the base lock's Hardhat 2.29.1. The new lock has only one Hardhat installation, version 3.21.2, so it does not satisfy those peers.
2. [`contracts/hardhat.config.js`](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/hardhat.config.js#L1-L30) is unchanged: CommonJS `require` calls register those plugins by side effect and `module.exports` exports the configuration. [The package](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/package.json#L1-L31) has no `"type": "module"`. Hardhat's [migration guide](https://hardhat.org/docs/migrate-from-hardhat2) requires an ES-module config and explicit plugin registration. Thus bypassing peer resolution would not complete this migration.
3. The existing [compiler prerequisite](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/scripts/workspace/check-hardhat-compilers.mjs#L12-L19) loads `hardhat/internal/solidity/compiler/downloader` and `hardhat/internal/util/global-dir` from the contracts installation. Neither is exposed by the [exact Hardhat 3.21.2 package export map](https://github.com/NomicFoundation/hardhat/blob/hardhat%403.21.2/packages/hardhat/package.json#L18-L52). [The Makefile](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/Makefile#L2488-L2504) runs this prerequisite before `paxeer-npm-build`.
4. Existing consumers still use the Hardhat 2 runtime API, for example [`hre.ethers` in deploy.js](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/scripts/deploy.js#L23-L29), [`ethers` imported from Hardhat in ERC721Test.js](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/test/ERC721Test.js#L1-L15), and [the CommonJS parity test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/test/hardhat_solc_parity.test.js#L6-L17). They are not migrated by this two-file PR.

## Impact
The contracts package cannot be treated as a drop-in major-version upgrade: its peer graph is invalid, and its existing config/compiler prerequisite are incompatible with Hardhat 3. This blocks the retained contracts build and local-chain test workflow. The [documented workflow](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/11c7e25858c03e55dc0edc513152ec2f083a0760/contracts/README.md#L47-L61) still starts with `npm ci` and invokes Hardhat directly. `npm test` is an existing placeholder and is not useful qualification for this update.

## Reproduction / validation for the repair owner
In a disposable checkout of the pinned PR head, with an appropriate supported Node runtime:
1. Inspect `contracts/package-lock.json`: compare `packages["node_modules/hardhat"].version` with the toolbox and upgrades `peerDependencies.hardhat`.
2. Run `npm --prefix contracts ci --ignore-scripts --no-audit --no-fund` without `--force` or `--legacy-peer-deps`; record the actual dependency-resolution result. No observed exit code is claimed here.
3. After resolving the dependency graph, run `(cd contracts && npx --no-install hardhat --help)` and validate config loading.
4. Validate `node scripts/workspace/check-hardhat-compilers.mjs` with its declared installations/compiler caches prepared; distinguish missing environment prerequisites from the removed Hardhat import paths.
5. Run the project's focused compile/parity checks, then the documented integration test only against a disposable local chain.

## Acceptance criteria
- Keep the compatible Hardhat 2 version until migration is ready, or migrate the contracts package, plugins, config, runtime consumers and compiler prerequisite together.
- Regenerate a consistent lock with no unsatisfied Hardhat peer requirements; do not hide the mismatch with forced/legacy peer resolution.
- Hardhat loads the config; compiler prerequisite/build no longer depend on removed v2 internals; meaningful focused checks pass with recorded revision, command and result.
- Update the supported Node requirement and local test instructions if the selected migration requires it.
