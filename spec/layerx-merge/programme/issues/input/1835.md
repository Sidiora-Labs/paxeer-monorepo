# Issue 1835: [Coherence] Decision 2879 and task 22.39.137 do_4 remove the SequencerReceiptVerificationError pass-through from verify_rpc_payment, but existing SDK tests outside the task still assert that typed error, and the task's verification never runs them

## Defect and impact

The new do_4 says to delete the clause that re-raises SequencerReceiptVerificationError in verify_rpc_payment, so every verifier failure becomes ValueError('payment-binding-mismatch'). It also says nothing else changes and limits the scope to x402_rpc.py and test_x402_rpc_surface.py. Two existing suites call verify_rpc_payment and assert SequencerReceiptVerificationError along with its .check and .code fields for unpinned keys, out-of-range keys and bad signatures. The verify_cmd runs only pay6/test_rpc.py and test_x402_rpc_surface.py, so the task would qualify while those suites turn red on main. The same consumer-test drift is what decision 2877 was written to prevent for F11.

Kind: connective. Severity: major.
