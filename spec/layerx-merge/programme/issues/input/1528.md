# Issue 1528: [Coherence] The commit deletes every go.sum in the launchpad Go modules and the workspace go.work.sum, so none of the modules can verify or build

## Defect and impact

The commit raises versions in 15 go.mod files but deletes the matching go.sum files instead of regenerating them. It also deletes go.sum for discovery and notifications, whose go.mod files did not change, and removes services/launchpad/go.work.sum. Go builds in readonly mode by default and need checksums for every module, so `go mod verify && go build ./...` in the task's own verification contract fails with "missing go.sum entry". The service image Dockerfiles also hash go.sum explicitly before downloading anything, so every launchpad container build now fails at that step.

Kind: connective. Severity: blocker.

## Expected versus actual

Expected: Each changed module's go.sum is regenerated with `go mod tidy` or `go mod download` so it records checksums for the new versions. The go.sum files of the unchanged modules (discovery, notifications) and the workspace go.work.sum are kept.

Actual: All 17 launchpad go.sum files and go.work.sum are deleted. `go mod verify`, `go build -mod=readonly` and both launchpad Dockerfiles fail for every service.
