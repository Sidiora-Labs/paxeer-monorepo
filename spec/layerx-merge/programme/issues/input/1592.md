# Issue 1592: [Coherence] The audit record reports the launchpad-user contract as missing, but spec/layerx-merge/contracts/services.md exists and has a launchpad-user section

## Defect and impact

Three adapter-registry findings and doc.14 say that the registry link `contracts/services.md#launchpad-user` points to a file that does not exist, and they propose replacing that link. Registry contract paths are relative to spec/layerx-merge. That directory has contracts/services.md with a `### launchpad-user` heading, which lists the user service's variables, interfaces and covering tasks 4.23.1–4.23.4. The record's broken-link part is therefore false. A repair task generated from it would remove a valid, authoritative contract pointer, when only the signature mismatches needed fixing.

Kind: semantic. Severity: minor.
