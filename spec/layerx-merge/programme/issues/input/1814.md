# Issue 1814: [P2] Preserve F11 NotEnabled in the widened availability regression assertions

The F11 family-table commit b5a4f2ce26c9c06539a23ecbe05679afaa239c8e changes both assertions in availability_hides_enabled_features to [Availability::Available; 11], but the same commit makes feature_availability set F11 to NotEnabled whenever F01 is Available. No returned array can have both entries Available. The existing regression test therefore cannot pass if it reaches its first widened assertion; its reopened-capture assertion has the same contradiction.

Expected: retain Available for the ten existing populated families and assert NotEnabled for the new F11 slot in this legacy fixture, before and after persistence. Actual: both assertions require Available for all eleven.

This is a test/source-contract inconsistency, not a request to enable F11 before its implementation tasks land. The F11 family test itself explicitly expects NotEnabled for a created market without a room profile. Task 22.38.1's widening instruction should be reconciled with its NotEnabled requirement rather than changing production availability merely to satisfy the all-Available literal.
