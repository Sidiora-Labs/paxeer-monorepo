# Issue 1549: [Coherence] The node merge-import test still builds the merge table from keepers without the chains keeper, so it now fails on the chains error this commit asserts

## Defect and impact

Task 22.6.4 requires every test harness that calls GetCustomPrecompilesE to pass keepers that carry the layerxchains keeper. This commit moves the precompile harnesses to precompiletest.Keepers, which wraps GetPrecompileKeepers. It also adds a test showing that app.NewPrecompileKeepers(a) on its own makes GetCustomPrecompilesE fail with 'layerxchains keeper is unavailable'. TestMergeConstructorsRegisteredForAgentOracleSchedulerStreams in the node package still passes app.NewPrecompileKeepers(a) and expects no error, so it now fails on that same error. The commit's claim that every merge-table harness has these keepers is therefore not true.

Kind: connective. Severity: major.
