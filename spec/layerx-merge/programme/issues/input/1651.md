# Issue 1651: [P2] Migrate existing BENS controller tests to the production route spelling

## Impact

Commit [08da21d2377053a40a0d0eb5793d404b4bcac9c6](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/08da21d2377053a40a0d0eb5793d404b4bcac9c6) correctly removes the test-only BENS route spelling, but leaves three existing controller regressions expecting the old underscore routes. Their real HTTP requests no longer match their Bypass listeners, so the existing transaction/log enrichment checks cannot pass as written.

Verified by static inspection on current main `44823b0a8346dd793d93d2e438a7b4688d933eda`. This is a test-integration regression; no production name-resolution outage is claimed.

- The multiprotocol controller test still registers `addresses:batch_resolve` at [L2944](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/44823b0a8346dd793d93d2e438a7b4688d933eda/services/explorer/backend/apps/block_scout_web/test/block_scout_web/controllers/api/v2/address_controller_test.exs#L2923-L2957).

These are not unused expectations.

The new repair suite covers the correct routes independently, but does not migrate these existing callers.

## Expected versus actual

Expected: all BENS integration listeners accept the same production URI that the client emits, with ENS enrichment assertions preserved.

Actual: the client sends hyphenated paths while three maintained controller tests expect underscore paths.

## Reproduction / validation

In the repository's configured explorer backend test environment, run the three cases from `services/explorer/backend/apps/block_scout_web`:

```sh
mix test test/block_scout_web/controllers/api/v2/address_controller_test.exs:1113
mix test test/block_scout_web/controllers/api/v2/address_controller_test.exs:2792
mix test test/block_scout_web/controllers/api/v2/address_controller_test.exs:2896
```

These commands are proposed validation, not executed results. The source-derived failure is an unexpected/unmatched BENS HTTP path followed by an unmet response/expectation assertion.

## Acceptance criteria

- Migrate all three cases to the production hyphenated routes using a listener that can accept those paths.
- Keep the ENS-name, metadata, address-body and multiprotocol assertions.
- Do not reintroduce environment-dependent production/test URL spelling.
- Run the three cases and repair_22_33_455_test.exs in their respective application test environments, then the relevant controller suite.
