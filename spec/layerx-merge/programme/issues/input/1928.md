# Issue 1928: [P2] Include TypeScript/TSX rows in the parity runner repair plan

## Problem

Decision 3058 and task 17.4.6 `do_4` prescribe adding C and Elixir dispatch to `command_for`, then splitting only `construct.existing-wallet-human-service-and-explorer` by toolchain. That does not cover the current TypeScript/TSX selectors in two of the named failing rows.

The new GOTCHA description calls `construct.new-signed-receipt-logs-new-case` an Elixir row, but its actual selectors are TypeScript/TSX. Both it and the wallet row fail before a test command can be built. Adding only the prescribed C/Elixir branches leaves them unsupported.

## Executed reproduction

From a checkout, this calls the actual parser and command builder without running the underlying test suites:

```sh
PYTHONPATH=spec/layerx-merge python3 - <<'PY'
from pathlib import PurePosixPath
from programme.kvx import load
from programme.parity import command_for

rows = load("spec/layerx-merge/programme/data/parity.kvx")
for name in (
    "construct.existing-wallet-human-service-and-explorer",
    "construct.new-signed-receipt-logs-new-case",
):
    row = rows[name]
    try:
        print(name, command_for(row))
    except Exception as exc:
        print(name, type(exc).__name__, str(exc))
    for suffix in (".ts", ".tsx"):
        selected = [
            item for item in row["selectors"]
            if PurePosixPath(item.split("::", 1)[0]).suffix == suffix
        ]
        try:
            print(suffix, command_for({"selectors": selected}))
        except Exception as exc:
            print(suffix, type(exc).__name__, str(exc))
PY
```

Observed on unmodified pinned sources:
- Each complete row: `ParityError: selectors must use one toolchain`.
- Each `.ts` group: `ParityError: unsupported selector toolchain: .ts`.
- Each `.tsx` group: `ParityError: unsupported selector toolchain: .tsx`.

Expected: the repair instructions identify the actual selector languages and test runners and provide a supported command path for every retained selector in both rows.

## Impact and scope

The prescribed repair remains incomplete for the parity inventory it is intended to unblock. This is a source-confirmed repair-plan gap, not a claim that the C/Elixir repair has already landed or that a runtime protocol failure occurred. Only command construction was executed; no full parity, browser or application suite was run.

- Execute the resulting selected tests through the inventory runner and record actual row outcomes rather than treating successful command construction as test success.
