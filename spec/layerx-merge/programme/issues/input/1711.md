# Issue 1711: Migrate retained middleware conformance fixtures to the verified receipt digest

## Summary
At [2c7b2965](https://github.com/Sidiora-Labs/paxeer-monorepo/tree/2c7b2965d062e20394da0e350e4057a1bcb66f5e), the PAY6 walkthrough and standard service conformance scenarios still construct or expect Keccak of the signed receipt, while the current verifier returns the receipt-signature digest. The production alignment was introduced by [797a092b](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/797a092bfa893b843b0ef4c5e708eda0ec109780); the retained fixture paths predate and were not changed by it.

- [PAY6 fixture](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/conformance/pay6/node-fixtures.mjs#L11-L18) assigns Keccak of the signed receipt, and the [walkthrough](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/conformance/pay6/walkthrough.mjs#L15-L17) expects the verifier to return it.
- The [RPC verifier adapter](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/seller/src/rpc.ts#L150-L166) returns the [authenticated signature digest](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/agent/sdk/typescript/src/verifier.ts#L558-L565). The [recorded receipt vector](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/sdk/platform/conformance/fixtures/sequencer-receipt-v1.json) pins that digest.
- The standard [service fixture](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/conformance/service.mjs#L523-L531) also constructs the old digest, which its agent scenario [expects](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/conformance/service.mjs#L681-L698).

## Validation
In a prepared checkout, run `node --test --test-name-pattern=mergedHttpEnvelopesSurviveReopen services/platform/middleware/conformance/test/repair-22-33-1479.test.mjs`. The walkthrough should verify the recorded receipt and carry its authenticated digest through the agent and settlement. Its current equality assertion instead compares that result to a different digest construction. The agent request also supplies the old proof digest, which the current seller [compares against the verifier result](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2c7b2965d062e20394da0e350e4057a1bcb66f5e/services/platform/middleware/seller/src/index.ts#L1048-L1051). Also check `npm --prefix services/platform/middleware/conformance run conformance` for the service scenario.

This is a source-verified contract mismatch. Neither command was executed in this review, so the first runtime failure and deployment impact are not established.

## Acceptance criteria
- Construct and assert the verifier's authenticated receipt digest consistently in both retained fixture paths and their downstream proof/settlement assertions.
- Retain negative coverage for incorrect digests.
- Run the PAY6 walkthrough and standard service conformance scenario against current source and record their results.
