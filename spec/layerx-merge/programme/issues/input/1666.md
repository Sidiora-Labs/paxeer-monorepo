# Issue 1666: MCP approval tests omit newly required decision time

## Problem
[9c3cd0e7](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/9c3cd0e7) makes `current_time` required for approval decisions. At [a9379026](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/a9379026dc479e3a609bcef2b60b6090744e7b3b), the [MCP session-tools tests](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a9379026dc479e3a609bcef2b60b6090744e7b3b/services/agent/crates/layerx-mcp/tests/session_tools_major_two.rs#L203-L243) still construct `DecisionRequest` without the required field and send a request without the newly required time while expecting validation success. [Another repair test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a9379026dc479e3a609bcef2b60b6090744e7b3b/services/agent/crates/layerx-mcp/tests/repair_22_31_223.rs#L1226-L1237) also omits it.

## Expected versus actual
Approval tests should compile against the current type and send explicit time when exercising valid decisions. The retained constructors are missing a required field, and the old tool requests no longer match the validation contract. Agentd test migrations are already acknowledged in [repair ownership](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a9379026dc479e3a609bcef2b60b6090744e7b3b/services/agent/crates/layerx-agentd/repair_22_31_495.kvx#L19-L38); the MCP test callers above need reconciliation as well.

## Validation
Compile and run the affected MCP test targets. Supply explicit deterministic times to valid decision constructors and requests, then add or retain refusal cases for missing/invalid time and boundary semantics.

## Acceptance criteria
- Migrate MCP test constructors and tool requests to the explicit-time contract without weakening validation.
- Cover accepted time and missing/invalid/boundary cases.
- Relevant MCP and agentd approval test targets compile and pass.

Static source inspection only; no compiler or tests were run and no runtime approval failure is claimed.
