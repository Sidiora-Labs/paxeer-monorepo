# Issue 1696: [Coherence] Existing repair_54 processor tests still call RegisterStatus without a Mode and assert HTTP 200 and a non-null lastProcessedBlock, so they now fail

## Defect and impact

Two tests in processor/repair_54_test.go mount RegisterStatus with only Store, ChainID and StartTime, then require response code 200. One also requires lastProcessedBlock to equal the committed height. With the new handler an empty Mode yields 503 and a null lastProcessedBlock, so both assertions fail. The task's do_9 requires that assertions in other tests be updated in the same change when the repair changes their behaviour. That was not done; the change only noted it as a wiring request.

Kind: connective. Severity: major.
