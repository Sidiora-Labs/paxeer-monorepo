# Issue 1826: [P3] Export SystemInstallError from the public Hyperfide SDK entries

## Summary

The install-status SDK change in [e84868db](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/e84868db5bb047e23c1e8c0dc7be2dcdf3dc3705) adds and throws `SystemInstallError`, but no supported package entry point exports the constructor as a runtime value.

Rechecked on current main `2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac` at 2026-11-07T20:29:13.172Z. This is a source-supported SDK packaging defect; no build or test was executed in this review.

## Expected versus actual

Expected: a consumer of `@hyperfide/sdk` can import the install-status error constructor and use `error instanceof SystemInstallError` to obtain the narrow `SystemInstallErrorCode` type, as the new regression test does.

Actual:

- [system.ts defines the class and narrow code type](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/areas/system.ts#L58-L90), and [the install-status reader throws it](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/areas/system.ts#L196-L210).
- [public-types.ts](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/public-types.ts#L28-L44) forwards the system module with `export type *`. [node.ts](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/node.ts#L91-L124), [browser.ts](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/browser.ts#L48-L53), and [core.ts](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/src/core.ts#L37-L38) provide no runtime re-export of the class.
- The [package exports map](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/package.json#L5-L42) exposes only root, core, browser, node and node-websocket entries. It does not expose the internal system module as a supported deep import.
- The [new test imports the class directly from internal source](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/test/install-status.test.ts#L8-L15), then [asserts its runtime identity](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cc62ab11c5ecd206ccc9dd69b3e1f8e380863ac/tools/hyperfide/sdk/client/test/install-status.test.ts#L156-L176). That bypasses the public export boundary.

The generic `HyperfideHttpError` remains usable, so install-status requests themselves are not shown to be broken. The missing value export prevents consumers from using the specialized runtime guard and its narrower error-code type through the supported package API.

## Reproduction / validation steps

1. Use this revision's normal Hyperfide workspace setup and build the SDK.
2. In a consumer resolved through the package export map, import `SystemInstallError` from `@hyperfide/sdk` and use it in an `instanceof` expression. Repeat for `@hyperfide/sdk/node`, `@hyperfide/sdk/browser` and `@hyperfide/sdk/core`.
3. TypeScript cannot use the type-only export as a runtime value. A native ESM named import from the built entry cannot obtain the constructor. An internal `areas/system` deep import is not part of the package exports.
4. After repair, extend the existing install-status regression to obtain the constructor through the public entry and verify that the real error returned by the SDK is an instance of that constructor.

These are proposed reproduction steps, not claimed executed output.

## Acceptance criteria

- Export the same `SystemInstallError` runtime constructor from the supported client entry points that expose `system.installStatus`.
- Preserve the narrowed `SystemInstallErrorCode` after an `instanceof` guard.
- Add a package-entry consumer regression rather than relying only on relative imports of `src/areas/system.ts`.
- Retain the existing NOT_FOUND, SUPERSEDED and SCOPE error-code/body assertions.

All-state issue and PR searches for `SystemInstallError`, `install status`, `getInstallStatus`, `22.37.4`, and Hyperfide export reports found no matching report or repair. Broader SDK export results were unrelated.
