# Issue 1752: [Coherence] The new state export producer is only ever called by tests, so production export of a state fact still answers NotOwned

## Defect and impact

The commit adds `retain_state_export` as the producer that keeps a `state:<activity>:<account>` bundle carrying ICS23 storage witnesses. The only callers are in the new test file. No daemon RPC, owner operation or receipt-retention path calls it. The production export handler still goes straight to `export::produce`, which only reads bundles already stored and returns NotOwned when none exists, so a real daemon can never produce the state evidence that decision 2642 and the task title promise.

Kind: connective. Severity: major.

## Expected versus actual

Expected: A production path, such as the offline-export handler or the step that keeps committed receipts, calls retain_state_export (or something equivalent) so that produce can answer a state fact with ICS23 witness evidence.

Actual: retain_state_export is reachable only from tests. In a running daemon, every state-fact export still fails with NotOwned, and the new verifier only ever sees evidence built by tests.
