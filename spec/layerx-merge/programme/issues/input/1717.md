# Issue 1717: Search results render two desktop headers after shell migration

## Summary
[6affbc65](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/6affbc654e0ec0d794b9c85b56ae5b69de33abcf) turns `HeaderDesktop` into a complete navigation header and adds it through the search-results layout, but the existing results pages still render their own instance.

At [b3f21e50](https://github.com/Sidiora-Labs/paxeer-monorepo/tree/b3f21e50dfdbf243d95d1db0e88231273f02fd10), the [route](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/pages/search-results.tsx#L12-L33) wraps either result page in [LayoutSearchResults](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/ui/shared/layout/LayoutSearchResults.tsx#L7-L16), whose NavBar renders the [full header](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/ui/snippets/header/HeaderDesktop.tsx#L16-L43). Both [ordinary](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/ui/pages/SearchResults.tsx#L287-L309) and [multichain](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/ui/multichain/searchResults/SearchResults.tsx#L145-L160) results retain a second instance.

## Validation
Open `/search-results?q=test` at desktop width in each configuration. Expected: one navigation/brand/settings/account bar, consistent with the [design brief](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/spec/layerx-merge/programme/docs/explorer-ui/design-brief.md#L82-L108). The source composition instead renders two full desktop headers and search controls. The existing [one-header test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/b3f21e50dfdbf243d95d1db0e88231273f02fd10/apps/explorer/ui/snippets/header/repair-22-35-2.spec.tsx#L124-L137) uses a generic dummy child and does not mount either results page.

This is source-verified; no browser reproduction or test execution was performed.

## Acceptance criteria
- Render one desktop navigation header on both ordinary and multichain search-results routes, while preserving the results-bound search behavior.
- Add route-composition regressions for both configurations that assert one header and usable search controls.
- Check mobile layout remains usable after the change.
