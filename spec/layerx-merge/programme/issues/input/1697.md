# Issue 1697: [Coherence] The services contract still describes the old unauthenticated publisher-backed dead-letter routes and status that is always ok

## Defect and impact

contracts/services.md still says the dead-letter routes exist only when a publisher is present and that drain removes publisher-queue entries. It also says the handler has no authorization and that read failures appear as null or zero while status stays ok. After this change the routes are always mounted and delegate to an authorized durable policy, drain never deletes anything, and failed reads return 503 unavailable or degraded. The published operational contract now contradicts the implementation.

Kind: connective. Severity: minor.

## Expected versus actual

Expected: The contract text describes canonical and legacy status modes, the 503 unavailable or degraded results, and the authenticated, audited dead-letter operations whose drain is refused.

Actual: The contract still documents unauthenticated publisher inspection and drain, and status that stays ok when reads fail.
