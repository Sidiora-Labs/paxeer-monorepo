# Issue 1627: Layerxpay genesis export drops canonical escrow receipt history

Successful escrow execution persists a canonical receipt that is omitted from both supported genesis recovery exports. After exporting and importing into fresh stores, escrow family state can remain available while GetEscrowReceipt(sequence) returns not found.

**Expected:** Preserve canonical escrow receipts across the supported genesis export/import paths, or explicitly define and reconcile a history-retention boundary.

**Source proof:** The receipt binder writes an ASCII `layerxpay/escrow-receipt/v1/` key, and GetEscrowReceipt looks up that exact key: https://github.com/Sidiora-Labs/paxeer-monorepo/blob/43a19e1aaab09c275bc47997619bf2f2850be396/modules/layerxpay/keeper/escrow_receipt.go#L44-L79. The pay module's legacy and recovery exports enumerate other module prefixes but not that receipt prefix: https://github.com/Sidiora-Labs/paxeer-monorepo/blob/43a19e1aaab09c275bc47997619bf2f2850be396/modules/layerxpay/keeper/genesis.go#L35-L55 and https://github.com/Sidiora-Labs/paxeer-monorepo/blob/43a19e1aaab09c275bc47997619bf2f2850be396/modules/layerxpay/keeper/genesis.go#L147-L176. Host store genesis export enumerates its own permitted key families, not this one: https://github.com/Sidiora-Labs/paxeer-monorepo/blob/43a19e1aaab09c275bc47997619bf2f2850be396/modules/lxphost/genesis.go#L116-L141.

**Reproduction from source:** Execute a successful escrow operation and retain its sequence; verify GetEscrowReceipt returns its bytes. Export the host and pay stores using either supported pay export, import into fresh stores, and query the same sequence. The receipt key is not among the exported entries, so the reconstructed keeper cannot find it.

**Impact:** Receipt history is lost across genesis export/import. This finding does not claim balance loss or affect ordinary reopening of the same database.

**Verification limits:** An independent prefix-selection model confirmed that the receipt key is excluded. This is a source-level reproduction; no Go/C integration test or deployed-state check was run.
