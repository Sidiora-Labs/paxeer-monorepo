# Issue 1706: [Coherence] Four replay commands in state_repairs.json select more than one case and always fail the count check

## Defect and impact

The new selector matches STATE_TEST_NAME as a plain substring of the case name, and indexed cases are named `<key>/<index>`. A replay filter ending in `/4` therefore also matches `/40` through `/49`. The replay commands for Opcodes_TransactionInit `/4` and `/6` each match 11 cases, variedContext `/2` matches 11 and `/3` matches 7. All four set STATE_TEST_COUNT=1, so they stop with `selected=N required=1` before any comparison runs. TestRepairM_1180_OwnedInventory only checks that each replay command contains the flag string, so it does not catch this.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: Each case replay command selects exactly the one recorded case, or the selector matches indexed names exactly so that a `/4` filter cannot also hit `/4N`.

Actual: Four replay commands select 7 to 11 cases with STATE_TEST_COUNT=1 and can never run the case they record.
