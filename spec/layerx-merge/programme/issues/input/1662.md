# Issue 1662: [P2] Register the nine wallet repair callbacks with Vitest

Problem
Two newly added wallet gateway repair suites pass each test function in Vitest’s name argument without supplying a test handler. The nine intended proofs therefore collect as TODO rather than execute their assertions. This is a test coverage/qualification defect, not an observed production failure or an executed CI result.

Expected and actual
Expected: all nine declared async proof functions execute, exercising lease ownership/loss/deadlines and the adapter boundary assertions. Actual: their function names identify TODO tasks, with no handler registered. These TODO entries are not behavioral evidence. The timeout number in the second slot also does not install the intended handler.

Acceptance criteria
- Register every function as an actual callback, for example test(fn.name, fn, timeout) or test(fn.name, { timeout }, fn).
- Preserve the existing assertions and per-case timeout budgets.
- Through the authorized repository gate, qualify both files and verify nine executed tests with zero TODO/skipped entries.
- Correct any qualification claim that relied only on their former collection result.

Validation
Static source/API tracing only. No build, test, signing, transaction or gate was executed for this report. Other tests using node:test are excluded because that runner supports function-only calls.
