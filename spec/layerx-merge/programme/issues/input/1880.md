# Issue 1880: [P2] Remove unavailable sandbox evidence inputs from the public qualification test

## Problem

The newly expanded qualification repair-record test depends on files from its original authoring sandbox that ordinary CI does not provide. This is a test-input regression, not an application runtime or security finding.

Introduced in the 22.31.623 changes merged by [6eeea3b0](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/6eeea3b0755ea285d12cdb7556cbd536e3a912d9). Current main was rechecked at `dd4addbf677b3c65e139efa6b4f44c2858fdedbd` on 2026-11-08 at 17:48:30 UTC.

Even if the nested qualification suite succeeds, a clean runner cannot satisfy these historical inputs. Current dependency/native prerequisite failures may occur earlier; this report does not claim the missing log is the first failure of a complete run.

## Reproduction and verification

1. Use a clean checkout with the documented test dependencies and native prerequisites, without the original `/out/logs` directory.
2. Run `python3 -m pytest -q tests/ci/test_qualification_suites_collect.py::test_repair_record_settles_every_baseline_entry`.
3. Once preceding assertions succeed, the historical file checks fail independently of the current qualification result.

Executed bounded evidence: unchanged AST assertion nodes from the pinned test were run against the exact pinned TOML repair record, with no mocks. The original loop at lines 153–155 raised `AssertionError` for `/out/logs/qualification-before-installed.log`; original assertions at lines 202 and 217 raised `FileNotFoundError` for the two XML reports above. Earlier assertions, the full fixture, and the full repository suite were not executed.

## Impact

Fresh CI and developer checkouts cannot run this regression check successfully using the inputs the repository provides. A retained authoring workspace can hide the problem.

## Acceptance criteria

- Keep current-revision qualification evidence and baseline-reconciliation assertions.
- Separate original sandbox evidence auditing from ordinary repository CI, or explicitly provision portable verified artifacts through an authorized path.
- Do not fabricate historical results or weaken the assertions merely to make the check pass.
- Provide any required pinned Git history explicitly.
- Validate the focused test and its public CI host in a clean environment with no historical `/out/logs` artifacts.
