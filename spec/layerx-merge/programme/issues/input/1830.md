# Issue 1830: [Coherence] Web search and RPC payment verification still pass the ledger payer as `payer`, which now has to match the recovered EVM sender

## Defect and impact

The commit changes the meaning of `verify_payment_receipt(payer=...)` from the ledger account in calldata (the PaymentExact `from` topic) to the recovered EVM transaction sender, and adds a separate `ledger_payer` for the old meaning. `web_search.verify_sequencer_receipt` was not updated and still passes `offer.payer`. That value is the ledger payer taken from the `payer` term of the offer. `verify_rpc_payment` forwards its `expected_payer` as `payer`, and the existing test still passes the ledger payer there. For the recorded payment vector the two accounts differ, and the commit's own new test asserts this, so valid payments are rejected with a payer binding failure.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Callers that pass the ledger account should switch to `ledger_payer=`, and the EVM-sender binding should get the recovered sender. `verify_rpc_payment` and the web search verifier should pass the right account to each argument.

Actual: Web search exact payments fail with `receipt-unverified`. `verify_rpc_payment` with a ledger payer raises `payment-binding-mismatch`, so test_sequencer_receipt and test_web_search_sequencer fail on valid receipts.
