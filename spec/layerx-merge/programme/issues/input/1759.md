# Issue 1759: [Coherence] The bypass_through ruling for 22.35.9 still sends the request through BlockScoutWeb.Router, so GET / raises the same NoRouteError

## Defect and impact

Decision 2667 and 22.35.9 do_3 say the chain page should be tested with Phoenix.ConnTest.bypass_through(conn, BlockScoutWeb.Routers.WebRouter, [:browser]) followed by a GET of the root path. The test endpoint dispatches to BlockScoutWeb.Router, and that router only forwards / to WebRouter when the web router is enabled at compile time. That flag defaults to disabled. In Phoenix 1.6.16 the router raises NoRouteError before it looks at the bypass, and the bypass only applies when it names the router doing the dispatch. So attempt 2 will fail the same way attempt 1 did.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: The ruling should avoid router dispatch altogether. For example: build the conn with Phoenix.ConnTest.build_conn, run it through the browser plugs it needs or use bypass_through(:all) style init_test_session, then call ChainController.show/2 directly. Alternatively, it could make the test build enable the web router.

Actual: Phoenix 1.6.16 router.ex line 405 raises NoRouteError when no route matches, and the bypass clause at line 327 only fires when phoenix_bypass names the router doing the dispatch. GET / through BlockScoutWeb.Endpoint therefore still fails before the controller is ever called.
