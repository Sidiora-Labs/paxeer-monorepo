# Issue 1804: [Coherence] The new programs-reference-fixtures job rebuilds the committed fixtures in place but never compares the result with the committed files, so fixture drift cannot fail CI

## Defect and impact

The job's only test step is `make programs-reference-fixtures`. That runs program-fixtures.sh, which overwrites the committed naming, LXT721 and swap-cpmm wasm, interface and registry-value files and then prints their sha256 sums. The script exits non-zero only if the build fails or a checkout path leaks into an artifact. Nothing in the job runs `git diff --exit-code` or checks the hashes against expected values. If a change to an example program or interface generator leaves the committed fixtures stale, the job still passes, even though the commit says it puts this project under test.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: After `make programs-reference-fixtures`, the job should fail when the regenerated fixtures differ from the committed ones, for example with `git diff --exit-code -- programs/crates/layerx-programs-registry/tests/fixtures programs/fixtures/pay5`.

Actual: The job passes whenever the build succeeds, so stale or non-reproducible committed fixtures go undetected.
