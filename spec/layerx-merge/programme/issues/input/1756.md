# Issue 1756: [Coherence] The capability-install evidence digest that agentd now computes still cannot match the digest the Human service checks, so every capability narrowing is refused

## Defect and impact

install_capability now builds its response digest with agent_evidence_digest over the rung rank. That helper puts a u32 length prefix in front of every preimage part. The Human consumer recomputes AgentEvidence::expected_digest(CapabilityNarrowing) by hashing the same parts concatenated with no length prefixes, so the two digests never agree, and ProductionAgentCreation refuses the stage with "capability evidence differs from request". The repair record says this change makes the response match what expected_digest requires. It does not: the commit fixed the rung byte but kept the length-prefixed preimage, so capability narrowing, and therefore agent creation, still fails end to end.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: The capability-install response digest should be byte-identical to AgentEvidence::expected_digest(CapabilityNarrowing): the same domain, stage, ids, sequence and rung rank, hashed with the Human service's preimage framing.

Actual: agentd hashes length-prefixed parts while the Human service hashes the parts back to back, so the digests always differ and the Human service refuses capability narrowing.
