# Issue 1550: [Coherence] The added recipient, spending limit and expiry on version-1 budgetCreate disclosures break two existing tests that still assert the old shape

## Defect and impact

For the plain budgetCreate selector, bind_call now also discloses the budget account as a Recipient counterparty, the per-period limit as a SpendingLimit amount, and the expiry. Two existing tests in other files still expect one amount and no counterparties for this exact call, so they now fail. One is in the same layerx-crypto crate and one is in layerx-intents. The commit's own test covers the new shape, but the older assertions were never updated.

Kind: connective. Severity: major.

## Expected versus actual

Expected: Every test that binds a version-1 budgetCreate call should assert the new disclosure: a Recipient counterparty, Transfer and SpendingLimit amounts, and the expiry.

Actual: budget_call.rs and budget_payloads.rs still assert one amount and an empty counterparty list, so they fail against the new binder.
