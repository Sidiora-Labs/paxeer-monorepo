# Issue 1678: [Coherence] Unknown internal errors from gRPC queries are re-wrapped in a registered error before reaching ABCIInfo, so their full text still leaks in non-debug query responses

## Defect and impact

After this change, defaultErrEncoder only shows the message when the root cause is a registered *Error. But baseapp's production gRPC query path first passes any handler error that is not an SDK error through gRPCErrorToSDKError. That function wraps the raw err.Error() text inside ErrInvalidRequest, ErrKeyNotFound or ErrUnknownRequest, which are all registered roots, so the encoder treats the result as safe and returns the original text. The legacy rootmulti query does the same with Wrap(ErrInvalidRequest, err.Error()). The task asks for the repair to be proven through real query responses. The new tests only call the QueryResult/ResponseDeliverTx constructors directly, and the task record lists no wiring request for these out-of-path rewrappers, so the leak the audit flagged stays open on the main ABCI query path.

Kind: connective. Severity: major.

## Expected versus actual

Expected: With debug=false, an unknown internal error returned by a gRPC query handler or a store query should come back as "internal error" with code 1, or the task record should file a wiring request against sdk/baseapp and sdk/store to stop flattening err.Error() into registered errors.

Actual: gRPCErrorToSDKError and rootmulti Query copy the unknown error's text into a registered ErrInvalidRequest/ErrUnknownRequest/ErrKeyNotFound wrapper, and the new encoder returns that text verbatim in the non-debug ResponseQuery.Log.
