# Issue 1661: Load-test deploy-wasm still invokes retired DEX commands

## Problem
At [131ca5cf](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/131ca5cf77d8eea3514d4ccede53ca225703a6af), [DeployWasm](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/tools/benchmark/loadtest/operations/deployment.go#L281-L327) delegates stake and instantiates two CW20 contracts, then invokes `tx dex register-contract` and `register-pairs`. The current [paxd command tree](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/daemon/paxd/cmd/root.go) is derived from [registered module basics](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/node/app.go), which no longer include the legacy DEX. The current exchange and spot modules do not provide those transaction commands.

## Expected versus actual
The deployment operation should complete through supported commands or refuse before making partial changes. Instead, if earlier steps succeed, it reaches an unavailable DEX command and returns before unbonding the temporary delegation or printing the contract addresses. This is inherited retirement drift surfaced during the artifact-path repair in [fb15c3ca](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/fb15c3ca096875a1f434b56a365660fba7aa20a7), not evidence of a live deployment failure.

## Validation
Inspect the real `paxd tx --help` command tree and exercise DeployWasm against a disposable test chain with the current binary. Compare it with the [focused repair test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/tools/benchmark/loadtest/operations/repair_22_31_500_test.go), which stops after stores, and the [full transcript test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/131ca5cf77d8eea3514d4ccede53ca225703a6af/tools/benchmark/loadtest/repair_m879_test.go), which supplies synthetic success for the retired commands.

## Acceptance criteria
- Use a supported CW20-only completion or an explicitly defined native-exchange migration, without restoring retired DEX commands.
- Validate command availability before consequential steps or provide a reliable cleanup/recovery path for temporary delegation and partial artifacts.
- Add a regression exercising the real command tree and failure cleanup, not only a synthetic successful transcript.

Source inspection only; no tests, transactions or deployment were executed. The related deploy-ten migration is tracked separately in 22.33.859.
