# Issue 1699: [Coherence] A rejected or failed wallet signature permanently blocks that advanced action for the account and deployment

## Defect and impact

AdvancedActionRecovery.run writes the signing reservation to durable storage before calling send(). If the wallet rejects the request or writeContract throws before broadcast, the finally block only clears the in-memory dispatch flag and the hashless reservation stays in storage. From then on, pending() returns that reservation: placeOrder, executeRoute and executeCustomRoute throw 'Advanced action unresolved; resume existing hash', and recoverAction throws 'Signature outcome unknown'. The provider exposes no way to discard the reservation, so one cancelled wallet prompt disables the action until storage is cleared by hand.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: A send() that fails without returning a hash should either remove the reservation or leave it in a state the user can resolve and clear. A wallet rejection, for example, proves nothing was broadcast.

Actual: Any send() failure leaves a hashless reservation that pending() treats as unresolved, and recoverAction always refuses it. The action is blocked for that account and deployment indefinitely.
