# Issue 1683: [Coherence] The v5.7.5 addr precompile still calls the context-free GetAddresses, so the new historical address-conversion route is never reached

## Defect and impact

GetAddresses now passes an empty sdk.Context, which is never historical, so it always takes the current validators. The only production caller, the v5.7.5 addr precompile, was not changed and still calls helpers.GetAddresses. The repair's own record asks for that caller to be switched to GetAddressesForContext. The request lives in a kvx file inside the helper directory, and spec.kvx has no matching task. As things stand, the unchecked historical conversion this change says it preserves for replay is dead code in production.

Kind: connective. Severity: minor.

## Expected versus actual

Expected: The v5.7.5 precompile should call GetAddressesForContext(ctx, ...), or the follow-up should be recorded as a spec task, so that replay uses the historical conversion path.

Actual: Every call from the precompile goes through the empty-context wrapper and the current validators, so the historical conversion branch has no production caller.
