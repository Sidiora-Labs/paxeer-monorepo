# Issue 1744: [Coherence] startup_refuses_a_chain_id_mismatch now starts its own node with a hard-coded chain id, while its spec task and decision 1896 still say it reads the gate environment's node

## Defect and impact

The repair stops reading LAYERX_TEST_PAXEER_CHAIN_ID and LAYERX_TEST_PAXEER_RPC_PORT. Instead the test starts a private node through proof_native_reads::disposable_node::LocalNode and fixes the chain id at 125. The task that owns this test still describes the old behaviour, and decision 1896 still names it as a gate that runs against the node the environment exports. The test no longer follows the chain id that run-real-node-tests.sh or PAXEER_X_RUNTIME_MANIFEST supplies. The spec now describes a test that does not exist, and a future repair that follows do_6 would undo this change.

Kind: connective. Severity: minor.
