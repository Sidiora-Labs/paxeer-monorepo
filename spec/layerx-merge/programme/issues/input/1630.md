# Issue 1630: [P2] Isolate AI-market receipt tests after journal revision checks

## Problem

The production rejection is correct, but the test still expects a different receipt to overwrite the terminal record.

Verified by static inspection at current main [5e533910](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/5e53391065cb6bcef690e368d8e184fa90227650).

## Expected versus actual

Expected: each receipt/revert scenario starts from its own valid pending journal state and proves the original typed refusal, retry classification, details, and durable failed state.

Actual: the first revert scenario reuses an already-resolved predecessor, so the intended refusal assertions are no longer reached. This is a test compatibility/default-suite regression; no production outage or failed executed CI run is claimed.

## Acceptance criteria

- Give each independent terminal-result/revert case a fresh journal and pending record, or another valid independent operation.
- Preserve all existing typed-error, retryability, detail, and durable-result assertions.
- Keep a separate assertion that a stale pending revision cannot overwrite a terminal record.
- Keep the production CAS protection intact and qualify the focused AI-market test.
