# Issue 1815: [P2] Handle ancestor type changes in path-filtered source diff and history

## Problem

The new path-filtered query path does not handle a selected file whose ancestor changes between a directory and a non-directory. For example, compare a revision containing `src/main.ts` with one where `src` is a regular file, using `paths: ["src/main.ts"]` and authorized prefix `""`.

Two source-derived outcomes follow:

- Diff omits the removal of `src/main.ts` and can return an empty page with `coverage.state: "COMPLETE"`. The reverse transition also omits its addition.
- Path-filtered history propagates `PATH_CONFLICT` while looking up the selected path in the revision where `src` is a file, instead of treating that descendant as absent and returning the revision that removed it.

This is a static source finding. No tests were executed and no deployed incident is claimed.

## Evidence

Introduced with 987381c3c8492c34af137dcd98b7243d87aae99c (task 22.37.12). The prior API rejected path filters for these actions; the new filter now reaches the existing ancestor representation/lookup behavior. Relevant source blobs were rechecked unchanged at current main c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741.

- [Selection semantics](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/queries.ts#L64-L104): for the selected nested file, `intersects("src")` is true but `includes("src")` is false.
- [Diff traversal](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/queries.ts#L608-L650): recursion occurs only when both sides are directories or absent. Directory-to-file does not recurse, and the ancestor's `TYPE_CHANGED` record is emitted only if the ancestor itself is included. The selected descendant therefore disappears from the result.
- [Completion](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/queries.ts#L650-L665): the exhausted directory frontier is reported complete despite the omitted descendant change.
- [History comparison](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/queries.ts#L311-L326) calls `pathIdentity` on both revision and parent.
- [API path identity](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/api.ts#L526-L535) directly invokes `PersistentTree.lookup`.
- [Tree lookup](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c23ceff9cd8dd87ba1ffcf9403803efb0dfdb741/tools/hyperfide/core/control-plane/src/source_control/trees.ts#L18) throws `PATH_CONFLICT` when a path ancestor is not a directory. No query-layer handling converts this expected historical absence to `null`.

## Regression cases and repair direction

1. Build two valid revisions: A has directory `src` containing `main.ts`; B has a regular file `src`.
2. Query diff A to B for `src/main.ts`: expect its removal. Reverse the comparison: expect its addition.
3. Query history from B for that path: include the revision that removed it, without `PATH_CONFLICT`.
4. Repeat with a symlink ancestor and with an authorized nested prefix. Keep pagination, coverage and redaction honest.

When one side is a directory and the other a non-directory, descend the directory side against an absent subtree for selected descendants. In history, treat only the expected ancestor-type conflict as absence; do not swallow unrelated storage or authorization errors.
