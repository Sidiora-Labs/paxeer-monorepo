# Issue 1825: [P2] Remove the deleted glTF model from both size allowlists

## Summary

The cleanup in [c3975b3](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/c3975b3cee9bf838d84b478d58dea4b8b24aa6f2) deletes `apps/perps/public/model.gltf` but leaves two size-budget allowances that require this file to exist. Rechecked at current main `a90d47ae5d0e79361a49bf7bdc6a5544f709b786` on November 7, 2026, 19:19 UTC.

## Expected versus actual

Expected: removing an unused asset also removes its stale allowances, so repository asset and file-size checks continue to accept the intended tracked-file set.

Actual:

- [LARGE_ASSET_ALLOWLIST still includes model.gltf](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/tests/ci/test_web_asset_weight.py#L66). [test_public_assets_under_weight_cap](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/tests/ci/test_web_asset_weight.py#L147-L157) requires every allowance to appear in tracked visitor assets and raises `Stale asset allowance: apps/perps/public/model.gltf` for this entry.
- [large_file_allowlist.txt also retains it](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/tests/ci/data/large_file_allowlist.txt#L12). [The growth check](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/tests/ci/test_tracked_file_size_budget.py#L68-L79) calls `lstat()` on every listed file, and [the existence check](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/tests/ci/test_tracked_file_size_budget.py#L82-L90) rejects any missing or untracked entry.
- [make test-tests-python](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/Makefile#L264-L268) includes `tests/ci`. [The main CI job](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a90d47ae5d0e79361a49bf7bdc6a5544f709b786/.github/workflows/ci.yml#L38-L43) runs that target before the new Python runtime-suite step.

The current pinned public directory listing confirms that model.gltf is absent. The follow-up commits after the watch snapshot only change vendored checksum files/tests and do not repair these consumers.

## Reproduction and validation

In a clean checkout of the pinned revision, run:

```sh
python3 -m pytest -q \
  tests/ci/test_web_asset_weight.py::test_public_assets_under_weight_cap \
  tests/ci/test_tracked_file_size_budget.py::test_allowlist_entries_exist \
  tests/ci/test_tracked_file_size_budget.py::test_allowlisted_files_have_not_grown
```

The stale entry is sufficient to fail these checks: the asset test rejects it, the existence test lists it, and the growth check cannot stat the deleted file.

Validation in this review was static: the deletion, both retained allowances, test bodies, Make target and CI caller were inspected at pinned revisions. The commands above were not executed, and no actual CI-run failure or exclusive cause of all suite failures is claimed.

## Impact

The cleanup leaves a deterministic inconsistency in the repository checks used by the main CI job. This is a maintenance/CI defect, with no deployed outage or security impact claimed.

## Acceptance criteria

1. Remove the deleted model from both allowance collections without restoring the intentionally removed asset.
2. Run the focused tests above and the applicable CI target.
3. Extend the cleanup qualification to cover the asset/file-size allowance consumers so future removals cannot leave stale entries.
