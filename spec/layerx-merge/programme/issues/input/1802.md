# Issue 1802: [Coherence] The perps app now crashes at startup in the browser when the embedded-wallet endpoint is unset, which also takes down injected wallets

## Defect and impact

resolvePaxeerConfig now throws when NEXT_PUBLIC_PAXEER_WALLET_API is missing. That check runs before the publishable-key check, and the publishable-key check is the documented way to switch the embedded wallet off and fall back to injected wallets. wagmi.ts calls getPaxeerWallet() while it builds the module-level wagmiConfig in the browser, so a deployment without that variable throws while the module loads, and the whole wallet layer goes with it, injected connectors included. The Dockerfile and docker-compose both default the variable to empty, so this happens in a default build.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: When no endpoint is set, the embedded wallet should be switched off (return null), or the error should only be raised when the publishable key is present, so that injected wallets keep working.

Actual: If the endpoint is unset, resolvePaxeerConfig throws no matter what the publishable key says, and wagmiConfig fails to build in the browser.
