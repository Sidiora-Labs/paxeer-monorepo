# Issue 1680: [Coherence] The legacy REST body limit is a fixed 1,000,000-byte constant, while the API server's limit comes from the operator's rpc-max-body-bytes setting

## Defect and impact

ReadRESTReq now wraps every legacy REST body in http.MaxBytesReader with the compile-time constant MaxRequestBodyBytes. The comment says this matches the server's default. But the API server applies its own limit from cfg.API.RPCMaxBodyBytes, which operators can change. If an operator raises that setting, legacy REST transaction routes still reject bodies over 1 MB. If an operator lowers it, the server's own MaxBytesReader trips first, and ReadRESTReq still reports the error as "exceeds maximum size of 1000000 bytes", which names the wrong limit.

Kind: cross-system. Severity: minor.

## Source proof

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a2a291cb095768b9204db48886ccffe6a65f5d79/sdk/types/rest/rest.go#L29 — The limit is hardcoded, and the comment claims it matches the server's 1 MB default.

  ```
  MaxRequestBodyBytes = 1_000_000
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a2a291cb095768b9204db48886ccffe6a65f5d79/sdk/types/rest/rest.go#L151 — Every legacy REST transaction handler goes through this fixed limit.

  ```
  r.Body = http.MaxBytesReader(w, r.Body, MaxRequestBodyBytes)
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a2a291cb095768b9204db48886ccffe6a65f5d79/sdk/types/rest/rest.go#L155 — The 413 message always names the constant, even when a different, outer limit tripped.

  ```
  fmt.Sprintf("request body exceeds maximum size of %d bytes", MaxRequestBodyBytes)
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a2a291cb095768b9204db48886ccffe6a65f5d79/sdk/server/api/server.go#L103 — The server's real limit is configurable. Its default is set at sdk/server/config/config.go:279 (RPCMaxBodyBytes: 1000000).

  ```
  tmCfg.MaxBodyBytes = int64(cfg.API.RPCMaxBodyBytes)
  ```

- https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a2a291cb095768b9204db48886ccffe6a65f5d79/consensus/rpc/jsonrpc/server/http_server.go#L259 — The server already wraps request bodies with the configured limit, so whichever limit is smaller decides, but the error text always says 1000000.

  ```
  req.Body = http.MaxBytesReader(w, req.Body, h.maxBytes)
  ```


Reviewed commits: a2a291cb095768b9204db48886ccffe6a65f5d79

## Expected versus actual

Expected: The legacy REST limit should follow the configured API body limit, or at least the 413 message should report the limit that actually tripped.

Actual: The limit is fixed at 1,000,000 bytes no matter what rpc-max-body-bytes is set to, and the 413 message always reports 1,000,000 bytes.
