# Issue 1823: [P2] Include shared chart declarations in the launchpad Docker build

## Summary

The declaration consolidation in [637c9c63](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/637c9c63da15d53eae493665591a26bcb2799d6c) adds a cross-app dependency that is absent from the launchpad production Docker builder. Rechecked on current main `32ca106c5bc559408173aa43f2bd1f169a6106b5` at 2026-11-07T16:22:40.937Z.

## Expected and actual

Expected: the launchpad image includes every declaration required by its real chart consumers.

Actual: the [forwarding declaration](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/apps/launchpad/web/public/charting_library/charting_library.d.ts#L1-L2) exports from `../../../../perps/public/static/charting_library/charting_library`. In the builder, this resolves to `/src/apps/perps/public/static/charting_library/charting_library.d.ts`.

[Dockerfile.web](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/deploy/launchpad/Dockerfile.web#L4-L10) only copies `apps/launchpad`, SDK packages and `cap-admission.ts`. It does not supply `apps/perps` before [running the web build](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/deploy/launchpad/Dockerfile.web#L48-L49).

The real [chart component](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/apps/launchpad/web/src/widgets/trading/tv-chart.tsx#L4) and [datafeed](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/apps/launchpad/web/src/widgets/trading/udf-datafeed.ts#L6) import named types from that forwarding module. The [package build](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/apps/launchpad/web/package.json#L6-L13) runs `next build`; [Next configuration](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/32ca106c5bc559408173aa43f2bd1f169a6106b5/apps/launchpad/web/next.config.ts#L42-L117) does not disable TypeScript validation. `skipLibCheck` cannot supply missing named exports to these TS/TSX consumers.

## Reproduction and validation

1. Check out the pinned revision.
2. Run `docker build -f deploy/launchpad/Dockerfile.web .` with the normal required build arguments, or reproduce its exact COPY layout in a clean temporary tree and run the configured web typecheck after installing dependencies.
3. Confirm that the sibling declaration is absent in the builder and that the named chart imports fail type resolution.

This is a source-supported packaging finding. Docker, Next and TypeScript compilation were not executed in this review; the steps above are proposed reproduction steps, not reported runtime output. A full-monorepo typecheck can mask the problem because the sibling file exists there.

Impact: the production launchpad image's normal type-validation path lacks required chart declarations. No deployed outage is claimed.
