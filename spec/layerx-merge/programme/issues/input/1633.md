# Issue 1633: [P2] Preserve tx_hash in node-root history responses

## Summary

Node-root `px_getHistory` and `px_getUnifiedHistory` return history rows without `tx_hash`, so the existing TypeScript `PxClient` rejects every nonempty page from these new endpoints. The hosted gateway already supplies the required field.

Introduced by [745659e6d62d69b4f1aa8b2afd12d6b2bf7982f2](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/745659e6d62d69b4f1aa8b2afd12d6b2bf7982f2), task 22.34.3. Rechecked against main at `f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb`; the affected node reader, gateway and SDK sources are unchanged.

## Expected versus actual

Expected: The node-root history methods preserve the served gateway transaction-hash contract, so the existing SDK can decode a nonempty page.

Actual: [The new Go Row type](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/src/modules/history/indexer.go#L105-L127) has only `TxID json:"tx_id"`, not `tx_hash`. [rowFrom](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/src/modules/history/indexer.go#L163-L194) decodes into that struct without adding a hash alias, and [the RPC result](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/rpc/px_history.go#L106-L123) serializes those rows. Even if the input contains `tx_hash`, decoding into the struct discards it.

## Producer and consumer evidence

- [The indexer serializer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/services/platform/hosted/indexer/src/store.rs#L2182-L2206) emits `tx_id`.
- [The current hosted gateway](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/services/platform/hosted/gateway/src/history.rs#L260-L268) copies that field into `tx_hash` on every row.
- [PxClient.getHistory/getUnifiedHistory](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/services/agent/sdk/typescript/src/px.ts#L181-L202) decode the returned page with the history decoders.
- [decodeHistoryRow](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/services/agent/sdk/typescript/src/history.ts#L190-L232) requires `tx_hash` and validates its transaction-hash shape. A node row fails the required-field check before decoding.
- The new commit's own [gateway recording](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/rpc/testdata/px-history/gateway-recording.json#L61-L71) contains both fields, but [the node transport test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/rpc/px_node_root_history_test.go#L155-L170) checks IDs, amounts, metadata and side rather than this required field.

## Source-derived reproduction and impact

1. Configure the node with an indexer containing an ordinary valid Paxeer transfer.
2. Call node-root `px_getHistory` or `px_getUnifiedHistory`.
3. Feed the nonempty response through the existing TypeScript `PxClient` history decoder, or point that client at the node-root endpoint.
4. The decoder throws `Incomplete history document` because the row has `tx_id` but no `tx_hash`. The corresponding hosted-gateway response passes that field check.

Empty pages do not exercise the row decoder. This blocks SDK compatibility with the new node-root history methods; it does not establish that any deployed client has already switched endpoints. The [cutover plan](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/f9ba7f7cd7c4b08ee9a826af0742882c7bacfeeb/spec/layerx-merge/docs/architecture/px-node-root.md#L3073-L3101) requires result parity before migration.

## Acceptance criteria

- Emit `tx_hash` from the same authoritative transaction ID used by the hosted gateway while retaining `tx_id`.
- Exercise both node-root history methods over HTTP and WS with a real producer-derived nonempty page.
- Decode that node response with the existing TypeScript history decoder and assert the exact transaction hash is preserved.
- Add a producer-to-consumer parity assertion so this field cannot disappear while subset-only tests remain green.
