# Issue 1670: [Coherence] The existing EmptyBlocksSanitizer tests still send block numbers and hashes the new validator rejects, so both cases now hang and fail

## Defect and impact

The new block_fields/2 only accepts a block if "number" is a "0x" string, "hash" is a binary, and the hash casts to the hash of the database row. The Mox-backed tests in empty_blocks_sanitizer_test.exs were not updated: they return the integer block number (first case) and the %Hash{} struct straight from the row (both cases). Because Mox responses never pass through JSON, the sanitizer now rejects both responses and never updates the block. Each test's wait_for_results on updated_at then times out, so the existing suite turns red.

Kind: connective. Severity: major.

## Expected versus actual

Expected: The existing sanitizer tests should return wire-shaped responses (a hex string number and a hex string hash) so they still exercise classification under the stricter validator.

Actual: Both existing tests still return an integer number and/or a %Hash{} struct. The new validator rejects these as malformed, so the block is never classified and both tests time out.
