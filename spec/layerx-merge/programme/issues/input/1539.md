# Issue 1539: [Coherence] eth_sendRawTransaction over WebSocket on the sequencer still re-accepts an identical resubmission and refuses it with the sequence error

## Defect and impact

The duplicate-hash check only runs when SendConfig.SequencerSource is set. Only NewEVMHTTPServer sets that field. NewEVMWebSocketServer builds its own SendConfig from seq.sendConfig and registers a SendAPI with it, but it never sets SequencerSource, and it rejects SequencerReceiptOption as an unknown option. The node also passes the WebSocket server an option list without the receipt option. As a result, a client that resubmits identical raw bytes over the sequencer's WebSocket endpoint gets a second Accept and a wrong-sequence refusal, when it should get back the known hash.

Kind: connective. Severity: major.

## Expected versus actual

Expected: An identical resubmission on the sequencer should return the recorded hash without a second Accept on both transports that serve eth_sendRawTransaction, HTTP and WebSocket.

Actual: Only the HTTP endpoint short-circuits. On the WebSocket endpoint the identical bytes are accepted a second time and refused with ErrWrongSequence.
