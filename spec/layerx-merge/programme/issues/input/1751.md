# Issue 1751: [Coherence] evidence_inventory now refuses any tenant whose legacy receipt evidence was archived by the existing migration path, so migrated tenants can no longer recover

## Defect and impact

The commit adds a check that fails the whole tenant inventory with EvidenceVersion if a receipt-legacy-evidence archive key exists for any receipt. Existing code writes that key in two places. persist_authenticated_receipt archives the version 1 record there during migrate_authenticated_evidence. persist_evidence writes there when the public slot already holds version 2 evidence. After a legitimate migration, every later evidence_inventory call for that tenant fails, and both callers in human_runtime then refuse budget recovery and policy budget reads. The existing migration test asserts that inventory still returns the archived legacy record after migrating, so this change breaks it.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Migrated receipts (archive key plus v2 public record) should be inventoried as current evidence, or as legacy evidence as before. Only a truly unsupported record should be refused.

Actual: Any tenant with a migrated receipt fails evidence_inventory with EvidenceVersion. Restart budget recovery is then refused for that tenant, and repair_22_31_364's migration test fails.
