# Issue 1658: Markets stream drops valid snapshots with nullable feed metrics

## Problem

At [40e98be0](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb), the [market numeric parser](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/hooks/perps/useMarketsStream.ts#L285-L293) maps null to NaN and the [normalizer rejects the entire snapshot](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/hooks/perps/useMarketsStream.ts#L330-L366). This validation was changed in [34996678](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/34996678).

The [wire type](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/services/platform/perps-data/internal/records/records.go#L67-L80) and [feed contract](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/spec/release-v6-12-0/contracts/data-services.md#L471-L477) explicitly allow nullable fields. In particular, [the producer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/services/platform/perps-data/internal/feeds/topics.go#L1136-L1225) can emit `change_24h: null` without an opening fill while other metrics are available.

## Expected versus actual

Expected: retain a valid market snapshot, showing unavailable nullable metrics as unavailable while preserving valid price, open interest, volume and funding. Continue rejecting genuinely malformed non-null values. Actual: one valid null drops the row, so the [markets row builder](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/widgets/markets/useMarketsRows.ts#L51-L80) loses otherwise available live values.

## Validation

Feed the normalizer an otherwise valid producer-shaped record with current price and open interest, but `change_24h: null` because there is no opening fill. Verify the current normalizer drops it. After fixing, verify the row retains the available fields and renders the null metric unavailable rather than inventing a zero; repeat for every documented nullable field and malformed non-null values.

## Acceptance criteria

- Align client types and normalization with documented producer nullability, retaining valid metrics independently.
- Add producer-shaped regression cases for each allowed null and for malformed values.
- Verify the mounted markets view remains usable when some or all snapshots contain allowed nulls.

Source inspection only; validation was not executed.
