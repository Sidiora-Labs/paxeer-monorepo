# Issue 1732: [Coherence] The install journey's A2A receipt check now takes its batch, asset and state-root facts from the receipt it is verifying, so those checks always pass

## Defect and impact

`receipt verify` compares the receipt's batch id, asset and previous/resulting state roots against facts the caller supplies from somewhere else. The rewritten journey gets the state roots by slicing them out of the canonical receipt bytes (offsets 54:86 and 90:122), the batch id from the same node response's height, and the asset from that response's paymentDenom. Those checks can no longer fail, and the asset is no longer tied to `LAYERX_PAYMENT_ASSET`, the asset the journey actually paid with. A receipt for another asset or another state transition would still report `verified == true`.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: The journey should pass `--asset "$LAYERX_PAYMENT_ASSET"`, as the previous revision did, and take batch and state-root facts from an independent source such as a batch or header query. The receipt being verified should not supply them.

Actual: Every authority fact except the sequencer key is copied from the receipt under test. Batch, asset and state-root mismatches can no longer be detected, and the paid asset is never checked.
