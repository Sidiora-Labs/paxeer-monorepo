# Issue 1552: [P2] Align cold scheduler ABI metadata with the served contract

## Defect and impact
At main 4f11a9dd256708e32917b39d8d616b5039e3e8c7, GetPrecompileInfoE exposes a different scheduler ABI before initialization than the served scheduler constructor. The newly added cold-versus-served parity test cannot satisfy its complete ABI equality assertion: cold metadata contains two extra events.

Introduced by 054988c9f53ec52ac1f21d54dfcdb58d6e0f9ffa. Task 22.6.4 is marked done by de036d25cef971e05feeffe567b2df0797a6937f.

## Expected versus actual
Expected: metadata lookup without keepers returns the served contract ABI without initializing or publishing VM state.
Actual: both definitions have matching methods, but cold metadata contains JobExecuted and JobFailed in addition to JobScheduled, JobCancelled and JobRescheduled. The served ABI contains only the latter three events.

## Reproduction and verification
Extract mergeAgentInfoABIs["scheduler"] from setup.go and abiJSON from scheduler.go, decode their JSON and compare event-name sets. Cold minus served is {JobExecuted, JobFailed}. An isolated Python JSON structural comparison was executed across eight agent ABI pairs: seven match; scheduler differs only in these additional events.

Run go test ./precompiles -run TestPrecompileInfoResolvesWithoutMergeKeepers in the supported Go/cgo environment to exercise the integration assertion. This Go test and the full project build were not executed in this review. The assertion mismatch follows directly from the parsed ABI event maps; no deployed incident is claimed.

## Acceptance
Reconcile cold metadata with the intended served ABI, preferably using one ABI source. Retain and pass the cold/served equality assertion rather than weakening it.
