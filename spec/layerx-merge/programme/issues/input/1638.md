# Issue 1638: Preserve completed registry job results across cleanup reload

A successful registry job returns its result to the immediate caller, but its completed result is lost from the durable lifecycle history.

**Expected:** Persist each completed job alongside the reconciled cleanup state, so later inspection and restart retain its exit code, output, command and observations.

**Actual/source proof:** run_job appends the result to its in-memory jobs list, but does not write that state before cleanup. Cleanup independently reloads and writes the previously persisted state. The Python finalizer then reloads that state, replacing the object that held the appended result, and writes it back: https://github.com/Sidiora-Labs/paxeer-monorepo/blob/9a6a7edb1a4e02bed162fb87d95a22a617dd97cc/tools/bringup/registry-artifacts.py#L353-L375. Subsequent inspect reads the durable jobs list: https://github.com/Sidiora-Labs/paxeer-monorepo/blob/9a6a7edb1a4e02bed162fb87d95a22a617dd97cc/tools/bringup/registry-artifacts.py#L252-L259.

**Reproduction:** Run a successful bounded job against a prepared registry fixture, retain the returned result, then inspect the lifecycle state. The immediate result reports success, but the durable jobs list has not gained the completed result.

**Verification:** An isolated harness executed the actual extracted run_job, inspect and JSON persistence functions against a temporary filesystem. The returned successful result was absent from durable and inspected history; an earlier sentinel job remained. Docker, subprocess, cgroup, quota and Go lifecycle operations were mocked. No real Docker/Go integration or deployed behavior was tested.
