# Issue 1790: [Coherence] The gateway's same-namespace NetworkPolicy selectors no longer match the registry, faucet, trusted-boundary and web peers, which stay in layerx-testnet

## Defect and impact

A NetworkPolicy podSelector without a namespaceSelector only matches pods in the policy's own namespace. The gateway's egress rules to layerx-program-registry, layerx-faucet and the trusted-boundary pods now select pods in layerx-mainnet-beta, but those workloads are still declared in layerx-testnet. The peer policies are broken in the same way: the registry and the web app admit or reach `app: layerx-gateway` only inside layerx-testnet. Under default-deny, the gateway loses registry, faucet and identity traffic, and the web app can no longer reach it.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: The gateway and its peers either share a namespace, or every cross-namespace rule carries a namespaceSelector for the other side.

Actual: Rules on both sides select bare podSelectors across what are now two different namespaces, so the traffic is denied.
