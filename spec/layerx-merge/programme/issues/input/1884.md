# Issue 1884: [P3] Refresh the published crypto API contract after legacy codec removal

## Problem

The maintained `layerx-crypto` crate documentation still advertises compatibility APIs removed by [f2ca9f35](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/f2ca9f35edf084513f34954793456128c87b45b7). Rechecked on current main `a08f6e9ee622b859eb2b83cf020c3843c8288c3f` at 2026-11-08 21:24 UTC.

The document says it is maintained with the implementation, and [lib.rs includes it directly as crate documentation](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/lib.rs#L1).

## Expected and actual

Expected: published crate documentation lists available APIs and directs consumers to supported call preparation and disclosure.

Actual:

- [Lines 50–60](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/api-contract.md#L50-L60) say `disclosure::bind`, `bind_budget_mutation`, `send::EnvelopeOptions`, `DisclosedEnvelope` and `encode_send_envelope` remain available as deprecated compatibility APIs. Those exports were removed.
- [Lines 28–36](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/api-contract.md#L28-L36) say the generic request constructor is removed and `sign_disclosed` remains deprecated. Current [signer.rs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/signer.rs#L45-L69) retains `SigningRequest::new` for the validated compatibility request, while `sign_disclosed` was removed.

## Impact and validation

Consumers following the maintained contract are directed to unavailable imports, such as `use layerx_crypto::send::EnvelopeOptions;` and `use layerx_crypto::disclosure::bind;`. This obstructs integration and obscures the supported migration path.

Source validation:

1. Inspect the included contract at the current revision above.
2. Compare the removal commit with its parent. It removes the advertised exports without changing `api-contract.md`.
3. Inspect current [send.rs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/send.rs#L157-L211), [disclosure.rs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/disclosure.rs#L53-L80), and [signer.rs](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/a08f6e9ee622b859eb2b83cf020c3843c8288c3f/services/agent/crates/layerx-crypto/src/signer.rs#L331-L349). The replacement call APIs exist; the advertised legacy exports do not.

This is a source-confirmed documentation mismatch. No Cargo build or tests were executed, and no runtime failure is claimed.

## Acceptance criteria

- Remove claims that deleted compatibility APIs remain available.
- Document `bind_call`, `CallOptions`/`DisclosedCall`, `ledger_payment_call`, and `sign_disclosed_call` as the applicable supported interfaces.
- Describe the retained request constructor and genuinely retained onboarding compatibility accurately.
- Review rendered crate documentation with the custody feature and add or update a compilable supported-call example.
- Preserve runtime behavior and existing validation tests; do not restore retired APIs to match stale prose.
