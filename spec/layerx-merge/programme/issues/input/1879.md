# Issue 1879: [P2] Provide historical checkout input for the new tools authority test

## Problem

The newly enabled `WorkspaceRefusalTests.test_historical_checkout_enforces_interpreter_and_validator_path` depends on a historical Git object that the owning `tools-python` CI job does not fetch. In a fresh default-depth checkout, its local shared clone cannot switch to that commit, so the test fails before exercising either intended validator refusal.

Introduced by [e1ae6e09](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/e1ae6e09248f858d494c1a53c9c3cb538dc5893b). Revalidated against current main [81f0e5a9](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/81f0e5a93ff980826998fb9b41c495ae81bb90c8) on 2026-11-08 at 13:25:31 UTC. The affected test, CI workflow, Makefile and baseline were fetched at that revision.

## Producer and consumer

- The [authority fixture](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/tools/paxeer-x/tests/ai_evidence_test.py#L59-L65) sets `candidate.base_revision` to `ce269bfe23c1db984a8ae62ce13aa36c238ce2fd`.
- The [new test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/tools/paxeer-x/tests/ai_evidence_test.py#L497-L517) runs `git clone --shared --no-checkout`, configures sparse checkout, then unconditionally switches to that historical revision. Line 508 asserts every Git command exits zero.
- The [tools-python job](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/.github/workflows/ci.yml#L45-L95) checks out using pinned `actions/checkout` with only `persist-credentials: false`. There is no history-fetch step. The [pinned action](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/action.yml#L74-L76) defaults `fetch-depth` to 1.
- CI runs on main pushes and pull requests. Its [test step](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/.github/workflows/ci.yml#L94-L95) invokes `make test-tools-python`. The [Makefile target](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/Makefile#L291-L296) includes the paxeer-x tests and applies the current [baseline](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/81f0e5a93ff980826998fb9b41c495ae81bb90c8/tests/ci/data/tools_python_suite_baseline.json), whose only entry is the separate retired-catalogue test. The new historical-checkout test is not deselected.

## Expected versus actual

Expected: a clean checkout produced by the declared CI job provides the inputs required to reach and assert the interpreter or validator-location refusal.

Actual: the historical object is absent. The shared clone cannot supply it, and `git switch` exits 128 with `fatal: unable to read tree (...)`. The test raises `AssertionError` before calling its validator.

## Reproduction and validation

In a fresh depth-1 checkout of the affected revision, with the ordinary Python test dependencies installed:

```sh
git rev-parse --is-shallow-repository
git cat-file -e ce269bfe23c1db984a8ae62ce13aa36c238ce2fd^{commit}
python3 -m pytest -q tools/paxeer-x/tests/ai_evidence_test.py::WorkspaceRefusalTests::test_historical_checkout_enforces_interpreter_and_validator_path
```

Executed evidence: the exact current test method was extracted with Python AST and invoked using a synthetic two-commit local origin and a depth-1 `file://` clone. Its admission base was set to the synthetic historical commit. The local shared clone and sparse-checkout commands succeeded; the unchanged method then failed at line 508 when `git switch` exited 128. The harness confirmed `is_shallow=true` and failure before validator invocation.

This is an isolated Git/test-method reproduction, not a hosted Actions run, execution against the real historical Paxeer revision, or a full tools-suite pass. The workflow/action source establishes the corresponding missing-history input in fresh CI.

## Impact

The tools-python suite gains a failing test unrelated to the behavior it intends to check. A full-history local checkout can hide the mismatch. No application runtime, security, value-transfer or deployed impact is alleged.

## Acceptance criteria

- Explicitly provide the required pinned historical object to the owning CI test path, or remove the unavailable-history dependency while preserving the interpreter and validator-location refusal assertions.
- Exercise this exact test in a fresh checkout matching CI's history configuration.
- Run the normal tools-python path at the repaired revision and report any separate failures.
- Do not skip or baseline the new test to hide the missing input.
