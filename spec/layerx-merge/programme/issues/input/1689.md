# Issue 1689: [Coherence] Middleware still calls walletParentOrigins() and browserConnectOrigins() without guarding them, so a malformed wallet origin or RPC override makes every request fail

## Defect and impact

walletParentOrigins() used to skip unusable entries. It now throws BackendOriginError for any entry that is not a strict origin. browserConnectOrigins() also calls getPaxeerRpcUrls() unguarded, which now throws. middleware.ts calls both on every non-charting request without catching anything. A single bad NEXT_PUBLIC_WALLET_IFRAME_ORIGIN entry, such as a trailing path or http in production, therefore fails every page in the middleware. The layout's configuration error page never renders, even though the repair record says invalid entries are 'visible in backendConfigurationProblems'.

Kind: connective. Severity: major.

## Expected versus actual

Expected: With an invalid wallet origin or RPC override, the middleware still produces a fail-closed CSP (for example, no wallet ancestors), and the layout renders the configuration error page.

Actual: The middleware throws on every request, so no page, including the configuration error page, is served.
