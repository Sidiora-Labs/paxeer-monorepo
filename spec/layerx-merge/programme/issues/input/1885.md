# Issue 1885: [Coherence] The checkpoint settlement document types are not deleted; only a three-line re-export alias is removed while the full types survive under layerx_types::historical::settlement

## Defect and impact

Task 9.26.3 and the commit title say the checkpoint settlement document types are deleted from layerx-types. Those types are DeclaredCheckpointSettlement, DeclaredGuarantor, DeclaredSettlementDomain, DeclaredFinalityPolicy, SettlementError, CHECKPOINT_SETTLEMENT_PATH and CHECKPOINT_SETTLEMENT_SCHEMA. The deleted src/settlement.rs was only `pub use crate::historical::settlement::*;`, and every declaration is still public in src/historical/settlement.rs, which historical/mod.rs exports. Two tests still use the type: layerx-types tests/repair_22_33_1542.rs and paxeer tests/repair_22_33_1324.rs. The task's grep for the string 'layerx_types::settlement' passes without checking for the types themselves. As a result, the interfaces marked `retire` are still reachable, and the proof test support now carries a second hand-written reader of the same document next to the surviving one.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: Deleting the checkpoint settlement document types removes DeclaredCheckpointSettlement and its sibling declarations from layerx-types, including src/historical/settlement.rs and its module line, and ports or retires the remaining consumers. The alternative is for the task to state explicitly that it removes only the deprecated alias.

Actual: Only the deprecated `layerx_types::settlement` re-export is removed. Every type is still public at layerx_types::historical::settlement with live test consumers, and layerx-proof's test support now duplicates a JSON reader for the same document instead of using that surviving type.
