# Issue 1600: [Coherence] The audit marks the oracle floor-half median as a high blocking defect, but requirement 2297.1 explicitly requires that rule

## Defect and impact

The record lists weighted-median-rounds-down as a blocking high finding and says the contract keeps the lower price only on an exact half-weight tie. Acceptance criterion 2297.1 requires the opposite: return the first price whose cumulative confidence reaches floor(total/2). That is exactly what Aggregate does, and the 'odd floor' test case asserts it on purpose. The contract text only says 'weighted median'; nowhere does it state the tie rule the record cites. So the record reports an implementation defect where the real issue is that the spec disagrees with itself. Its proposal would change the code against a stated acceptance criterion, and the finding wrongly helps hold upgrade_ready at false.

Kind: semantic. Severity: major.
