# Issue 1657: Portfolio Assets chart treats sparse active days as calendar-day windows

## Problem
At [40e98be0](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb), the [Assets chart](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/widgets/portfolio/PortfolioAssetsChart.tsx#L198-L233) implements 7D/30D/90D by taking the latest N records. The [history producer omits days without settlements](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/services/platform/perps-data/internal/pnl/pnl.go#L381-L414), so N records need not cover N consecutive days. The [portfolio page](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/page-modules/portfolio/index.tsx#L147-L168) supplies the history to the chart.

## Expected versus actual
The [qualification ruling](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/spec/release-v6-12-0/qualification.kvx#L2600-L2606) defines these ranges as N UTC calendar days including today. Instead, Assets can show months-old points in a 7D view. The sibling [Performance grid](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/src/widgets/portfolio/PortfolioPerformanceGrid.tsx#L395-L410) applies a date cutoff.

## Validation
Freeze time on October 21 and supply only January 1 and 2 history rows with a current balance anchor. Select 7D: Assets retains the January points, while Performance excludes them. Add cases with sparse rows inside and outside the interval and test the inclusive UTC boundary and midnight rollover. Compare with the existing [window tests](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/40e98be0b75cf79a3cd5a7e0e2064c2f2b36b6eb/apps/perps/tests/portfolio-windows.test.ts#L12-L47).

## Acceptance criteria
- Apply the specified UTC calendar windows to Assets, including sparse and entirely stale histories.
- Keep Assets and Performance consistent on N-day boundaries; preserve ALL-range cap disclosures.
- Add regression tests for stale, sparse, boundary and rollover cases.

This is separate from closed #694, which addressed ALL-history truncation. Findings are from source inspection; the scenario and tests were not executed.
