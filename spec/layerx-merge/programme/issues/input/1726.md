# Issue 1726: [Coherence] The node RPC client now rejects any /rpc URL while the wallet fee path, the global --rpc help and the program override still require one

## Defect and impact

RpcClient::connect now refuses any node URL whose path is not "/". The wallet fee/quote path builds RpcClient::new(endpoint) and then, on the next line, insists the same endpoint ends in /rpc and posts eth_estimateGas to "/rpc". No URL passes both checks, so the command always fails. The global --rpc flag still documents an endpoint ending in /rpc, and program_client still requires that suffix, so users are told to supply exactly the form the client now refuses.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: Every consumer of the node endpoint (wallet quote and estimate, wallet --rpc users, program_client, --rpc help) accepts and documents the node root URL, as RpcClient now requires.

Actual: RpcClient::new requires the root, while the wallet estimate, program_client and the help text still require or advertise /rpc. The wallet fee path cannot succeed with any URL.
