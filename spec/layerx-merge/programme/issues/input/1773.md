# Issue 1773: [Coherence] The new delta charge lets the execution observer hold far more than its 64 MiB bound, because every boundary still keeps a full copy of linear memory

## Defect and impact

After the first observation, the observer is now charged only for memory growth, changed 4 KiB pages and changed instance members. But every boundary snapshot still copies the whole linear memory, and the snapshot's instance states copy it a second time. The trace and witness paths keep all of those snapshots in the observer's transition list until the call returns. The aggregate byte and work limit (MAX_TRACE_STATE_BYTES, documented as the 'Aggregate canonical state bytes retained by one trace') therefore no longer limits memory that is actually held. An unprofiled traced call, or a call_with_boundary_witnesses run, can hold up to its commitment limit (MAX_TRACE_COMMITMENTS = 65536) times the full guest memory before the after-the-fact peak check in execute.rs refuses it. Before this change, the observer refused as soon as the real retained total passed 64 MiB.

Kind: semantic. Severity: major.

## Expected versus actual

Expected: A boundary's charge to the observer's byte limit should match what the observer actually keeps. Either keep only page deltas, or keep charging full snapshot sizes wherever full snapshots are accumulated (the trace and boundary-witness paths).

Actual: After the first boundary, observations are charged as page and instance deltas while full memory copies keep accumulating. The 64 MiB limit is enforced only after the call, so a guest with large memory can make the host hold up to 65536 full memory images during one traced call.
