# Issue 1562: [P2] Decode transfer-authority terminal wrappers in the AI market receipt reader

## Defect
The AI market decoder introduced by [e45224a](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/e45224abc88855de961e47ee57644c22002759c4) cannot decode a supported runtime terminal wrapper. Verified on 2cf0003e39bceca841b9186e009f9d3824131abd; task9.97.15 is marked done there.

[validateProgramsExecutionResponse](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/services/agent/sdk/typescript/src/ai_market.ts#L3259-L3287) removes only an optional occupancy wrapper, then requires an execution/v2–v5 prefix. A transfer-authority wrapper therefore reaches ReceiptMismatch even when the surrounding applied-legs envelope is valid.

## Producer and consumer evidence
- [Runtime producer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/programs/crates/layerx-programs-runtime/src/ffi_call.rs#L3405-L3422) wraps execution with occupancy and then, when present, transfer-authority/v2. The transfer-capable branch accepts guest ABI2–5.
- [Existing runtime reader](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/programs/crates/layerx-programs-runtime/src/terminal.rs#L325-L348) unwraps authority before occupancy.
- [Existing fixture test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/services/agent/sdk/typescript/test/account-bound-call.test.ts#L13-L24) confirms the checked-in account-bound-call terminal has applied-legs → authority → execution nesting.
- [AI value effects](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/programs/crates/layerx-programs-ai-market/src/[the request routing module]#L1076-L1084) reach the [wasm value adapter](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/programs/crates/layerx-programs-ai-market/src/value_adapter.rs#L314-L343), which stages supported funding/payment operations. The [SDK builder](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/services/agent/sdk/typescript/src/ai_market.ts#L2274-L2282) carries caller capabilities in its ABI5 call.
- The precompile packs the runtime response via [method_call.go](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/precompiles/layerxprograms/method_call.go#L40-L50). AI [journal resolution](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/2cf0003e39bceca841b9186e009f9d3824131abd/services/agent/sdk/typescript/src/ai_market.ts#L3074-L3095) depends on successful receipt decoding.

## Expected versus actual
Expected: valid supported authority-bearing terminal responses decode while retaining all authority and receipt bindings.
Actual: the decoder rejects the authority prefix as ReceiptMismatch. This blocks the consumer's result/journal resolution path. This is a fail-closed compatibility report, not a demonstrated authorization bypass, value loss or deployment incident.

## Acceptance criteria
- Decode the bounded authority wrapper before occupancy/execution, validating its transfer/authority binding rather than simply skipping it.
- Preserve applied-leg root, signature, transaction, log, terminal-kind and guest-response-capacity checks.
- Cover ordinary no-transfer and authority-bearing results, malformed/mismatched wrapper negatives, and journal resolution/restart.
