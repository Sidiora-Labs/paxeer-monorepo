# Issue 1822: [P2] Preserve the shared Swagger contract in regeneration paths

## Summary

[Commit a2bf776a](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/a2bf776a9fbdd7265c4a1dfcc89cb2fe8e755d13) replaces the SDK's embedded Swagger bundle with an import-only shim, but leaves both generation paths on the previous contract.

The expected contract is one shared archive serving both the default and `swagger` namespaces. The root generator produces only the named registration, while the SDK generator overwrites the shim with a separate archive.

## Producer and consumer evidence

- [The SDK shim](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c083270cba62b5939c980deca856d9917a6cb3d8/sdk/client/docs/statik/statik.go#L1-L4) now imports `docs/swagger`. [The new synchronization test](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c083270cba62b5939c980deca856d9917a6cb3d8/tests/ci/test_copied_artifacts_in_sync.py#L180-L205) requires a single archive, both registrations and both schema filenames.
- [The documented root command](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/docs/paxeer-chain-docs.md#L73-L90) is `./scripts/update-swagger-ui-statik.sh`. [That script](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c083270cba62b5939c980deca856d9917a6cb3d8/scripts/update-swagger-ui-statik.sh#L11-L13) generates fresh statik output, then calls `swagger_assets.py`.
- [The transform](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c083270cba62b5939c980deca856d9917a6cb3d8/scripts/swagger_assets.py#L20-L28) replaces the sole default registration with `fs.RegisterWithNamespace(swaggerNamespace, data)`. It does not retain a default registration.
- [Wasm's Swagger consumer](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/wasm/app/app.go#L834-L842) and [the interchain test application](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/interchain/testing/simapp/app.go#L691-L699) still call default-namespace `fs.New()` and panic on failure. Both import the SDK shim. The node's named-namespace consumer is not the affected route.
- [The SDK Make target](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/450b0b318c1864ed886e45117b56ae9aa7f5522d/sdk/Makefile#L165-L173) and [SDK generation script](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/c083270cba62b5939c980deca856d9917a6cb3d8/sdk/scripts/update-swagger-ui-statik.sh#L1-L2) still generate a separate archive directly into `client/docs/statik`, replacing the shim.

## Expected versus actual

After supported regeneration, both consumer namespaces should remain available and the SDK should continue importing the one shared archive.

Instead, root regeneration supplies only the named namespace. Default consumers then cannot load their Swagger filesystem through the shim. The separate SDK command restores duplication and reports the generated file out of sync. This makes ordinary regeneration incompatible with the newly landed artifact contract.

## Reproduction and validation

In a prepared disposable checkout:

1. Run the documented root generation command.
2. Verify that the generated bundle initializes both `fs.New()` and `fs.NewWithNamespace("swagger")`, then run the copied-artifact synchronization check.
3. Run `(cd sdk && make update-swagger-docs)` and check that the SDK shim is preserved rather than replaced with another archive.

Only source inspection and isolated execution of the actual Python namespace transform against synthetic statik output were performed during this review. The transform produced named-only registration. Neither complete generation command nor a Go consumer runtime test was run. The large generated archive could not be read through the available interface, so this does not claim independently verified current dual registrations or an existing checked-in runtime failure.

The generator, transform, SDK shim and synchronization contract were rechecked at current main `c083270cba62b5939c980deca856d9917a6cb3d8` on November 7, 2026, 15:50 UTC.

## Acceptance criteria

- Make both supported generators preserve the single shared bundle and both consumer namespaces.
- Preserve the schema aliases required by the synchronization contract.
- Add a generation round-trip regression that loads both consumer namespaces and verifies that SDK regeneration does not recreate the removed duplicate.
- Reconcile the existing namespace-transform fixture with the shared-bundle output.

All-state issue/PR searches for statik, swagger_assets, namespace/swagger, update-swagger and swagger/regeneration found no matching report. Explorer schema issues #1181 and #1313 concern different contracts.
