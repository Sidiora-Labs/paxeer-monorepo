# Issue 1901: [Coherence] Decision 3038 is applied to only one of the three arbiter test binaries that call the failing producer functions, so the repair gate of 22.39.183 leaves two done-task gates red

## Defect and impact

The two cases this commit moves to 22.39.183 fail because they call producer::repair_v5_authority and producer::repair_executor_payer_replay, which panic at the boundary-pair replay (proof_arbiter_crate.rs lines 1318 and 1539). Two other binaries, tests/repair_22_31_252.rs and tests/repair_22_33_214.rs, include the same producer module by path and call the same two functions. They are the verify_cmd gates of the done tasks 22.31.252 and 22.33.214, but neither the new 22.39.183 verification nor do_6 lists them. Decision 3038 states the rule for any binary that includes the producer module, yet 22.39.183 can qualify while those two gates still fail on the same Witness(Encoding) replay, and no task owns them.

Kind: connective. Severity: major.
