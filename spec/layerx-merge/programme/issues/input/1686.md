# Issue 1686: [Coherence] GraphQL tickers now take the latest index from mark events and successful aggregates, but the REST tickers and market records still read it only from mark events

## Defect and impact

This commit moves every GraphQL index selector (latestPrices, poolState, Market.latestPrice, orderlyTickers, orderlyPriceChanges, latestPricesUpdated) onto indexPriceRowsSQL. That source merges perps.mark_prices with successful perps.index_prices aggregates. The REST venue tickers (/api/tickers, /api/ticker/{symbol}) and the REST market records (/markets) still take index_price, and the basis built from it, from the latest perps.mark_prices row only. The pricefeed emits an aggregate on every update, but MarkPriceUpdated fires only when the mark changes, so the two transports now return different index prices for the same market. A market that has aggregates but no mark event has an index on GraphQL and none on REST. The finding asked for REST snapshots to be compared, and the repair record lists wiring requests only for the contract and records.go, not for these REST readers.

Kind: cross-system. Severity: major.

## Expected versus actual

Expected: Every index_price surface, on GraphQL and on REST tickers and market records, uses the same latest-index ordering. Failing that, the out-of-path REST readers get a recorded wiring request.

Actual: GraphQL and REST now return different index_price and basis values whenever the newest index observation is a pricefeed aggregate, and nothing records the REST side as pending.
