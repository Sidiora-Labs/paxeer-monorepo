# Issue 1750: [Coherence] The 'exact signed' Claim and RefundFree requests carry Native authentication; their signature is never checked by the program

## Defect and impact

signed_request signs the encoded envelope with a test key and stores the signature next to it. The envelope itself declares Authentication::Native, so dispatch never sees or checks that signature. The tampered-request check only verifies the detached signature in the test, and the tampered request is never routed. The test therefore does not show that replaying the exact signed request is what the program accepts.

Kind: semantic. Severity: minor.

## Expected versus actual

Expected: The replayed request should carry the authentication the program verifies, for example Delegate as in try_publish and task_step, so that a tampered replay is refused by dispatch.

Actual: The signature is a test-side side channel, and the program would accept the same request with any signature or none.
