# Issue 1660: Receipt-key tests still expect forwarding after node-local authority change

## Problem
At [76571314](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/76571314de50d22895a33bb3b062abc0904f016b), [the node discovers its local sequencer keeper](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt.go#L260-L274) and [`GetReceiptKeys` reads local governed pins](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt.go#L384-L401), consistent with the [node-root design](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/spec/layerx-merge/docs/architecture/px-node-root.md#L525-L542). The behavior changed in [561806a6](https://github.com/Sidiora-Labs/paxeer-monorepo/commit/561806a6529dcbcf892d71a309c73ca4bc3ea5d0), but retained tests still assert the old forwarding-only contract.

## Expected versus actual
The tests should assert local governed authority behavior, including a genuine missing-authority failure. Instead:
- [TestReceiptKeysNotServedNamesRequestedMethod](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt_test.go#L414-L440) expects an error even though its [fixture commits valid local pins](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt_test.go#L130-L139).
- [TestPublicPxReceiptKeysCanonical](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt_test.go#L443-L452) repeats the stale error expectation before its SDK interoperability checks.
- [TestReceiptKeysServedByTheNode](https://github.com/Sidiora-Labs/paxeer-monorepo/blob/76571314de50d22895a33bb3b062abc0904f016b/rpc/sequencer_receipt_test.go#L680-L725) empties the forwarding node's local pins but expects the proposer's nonempty response, whereas the node-local reader returns the local result.

## Validation
Run the three named RPC tests against this revision and compare their assertions with the actual local fixture and keeper reads. Update the fixture and assertions to exercise valid local pins, empty local pins, and genuinely missing authority, then run the SDK error-propagation and interoperability coverage.

- Tests agree with the local-governed authority contract for direct and forwarding configurations without restoring forwarding-based key discovery.
- Preserve explicit missing-authority refusal and SDK error/interoperability checks.
- Run the named tests and the relevant SDK checks in CI.
