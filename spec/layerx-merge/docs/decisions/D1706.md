# D1706: address-table reality: production serves none of the twelve merge addresses

Source: `[decision.1706]` in [the installed specification](../../spec.kvx). Programme carry status: **kept**; source carry: `new`.

## Value

MergeAddressTable names twelve addresses (0x101A-0x101D, 0x0901-0x0908) whose names win (decision.605), but at HEAD no production import registers a constructor, so a merged node serves none of them until the node imports the constructor packages; the programme activation table records served_at_head = false for all twelve.

## Basis

`MergeAddressTable`, `RegisterMergeConstructor` and `newMergePrecompiles` in `precompiles/setup.go` separate reserved names from registered constructors. `precompiles/layerxagent/teeattestor/teeattestor.go` registers its constructor in `init`; the specification baseline imports that package only from tests. `node/app.go` obtains the served set through `GetCustomPrecompiles`.

## Carry-forward

The table fixes names for four construct addresses (0x101A–0x101D) and eight agent addresses (0x0901–0x0908), as required by decision.605. A table entry alone does not register a served precompile. At the specification baseline, the only registrar is the test-imported TEE attestor package; production imports register none of the twelve constructors. The programme activation table therefore records `served_at_head = false` for all twelve until production wiring imports the constructors.
