# Chain-authenticated arbiter interfaces

The public declarations of `VerifiedReplayAuthority`, `AuthenticatedCatalogue`
and `VerifiedReplay` describe the current chain-proof interface. Reconstruct
verified objects from transported bytes for each consumer; do not deserialize a
previously verified object and treat it as authenticated.

| Entry point | Inputs in declaration order (all return `Result<Self, ReplayError>`) |
| --- | --- |
| `VerifiedReplayAuthority::derive` | `&VerifiedReceipt`, `&AdmissionEvidence`, `&VerifiedBatchHeader`, `&ChainCommitProof` |
| `VerifiedReplayAuthority::derive_program_call` | `&VerifiedReceipt`, `&AdmissionEvidence`, `&VerifiedBatchHeader`, `&ChainCommitProof` |
| `AuthenticatedCatalogue::verify` | `&AdmissionEvidence`, `&BTreeMap<[u8; 32], Vec<u8>>` code blobs |
| `AuthenticatedCatalogue::verify_with_module` | `&AdmissionEvidence`, `&ChainCommitProof`, `[u8; 32]` host store root, `&[u8]` host multistore proof, `&BTreeMap<[u8; 32], ics23::ExistenceProof>` code proofs, `&BTreeMap<[u8; 32], Vec<u8>>` code blobs |
| `VerifiedReplay::verify` | `&VerifiedReceipt`, `&AdmissionEvidence`, `&ChainCommitProof`, `[u8; 32]` host store root, `&[u8]` host multistore proof, `&ics23::ExistenceProof` metadata proof, `&[u8]` authority bytes, `&[u8]` hosts bytes, `AuthenticatedCatalogue` |
| `VerifiedReplay::verify_with_batch_context` | `&VerifiedReceipt`, `&AdmissionEvidence`, `&VerifiedBatchHeader`, `&ChainCommitProof`, `[u8; 32]` host store root, `&[u8]` host multistore proof, `&ics23::ExistenceProof` metadata proof, `&[u8]` authority bytes, `&[u8]` hosts bytes, `AuthenticatedCatalogue` |

## Call sequence

1. Obtain a trusted committed block's app hash and height independently of the
   transported proofs. `ChainCommitProof` is an untrusted transport structure;
   successful proof verification authenticates its contents against its app hash,
   not consensus or the caller's choice of trust anchor.
2. Decode transported IAVL record proofs with `ics23::decode_existence`, then
   call `AdmissionEvidence::verify_under_app_hash(app_hash, host_store_root,
   &host_multistore_proof, &activity_id, &record_proofs)`. This authenticates the
   admission header, signed activity, program, governance and account records.
3. Reconstruct `ChainCommitProof` with its sequencer store root, multistore proof,
   receipt key `[3]` and decoded receipt-key-table proof. Verify receipt/header
   signatures using its authenticated `receipt_keys()`. The receipt's batch id
   encodes its height as 24 zero bytes followed by a big-endian u64; key selection
   requires the matching sequencer id and inclusive key validity range.
   `verify_receipt` also requires a nonzero receipt height at most the commit
   height. These heights are not the activity execution sequence.
4. Derive replay or ordinary-call authority with the corresponding constructor
   and call `verify_native` on the transported authority bytes. The signed batch
   header, receipt digest, activity, sequence, prestate and authority must agree.
5. Call `AuthenticatedCatalogue::verify_with_module` with transported code proofs
   and blobs. It authenticates the lxphost multistore root and each
   `[5, 0, 9] || code_hash` key/value, validates blob hashes and module/interface
   data, and pins the catalogue to `commit.app_hash`. `verify` alone validates
   admission's program records and blobs but does not establish this app-hash pin.
6. Call either replay constructor with the transported metadata proof and native
   authority/host bytes. Metadata must authenticate at
   `[1, 0, 9] || b"progreplay/v1/" || activity_id` under lxphost at the commit app
   hash. Receipt/admission/catalogue bindings and native input digests remain
   checked. `verify_with_batch_context` additionally derives authority from the
   signed batch and verifies its native encoding. Consume adjacent boundary
   proofs with `verify_step` and assert their resulting indices and activity id.

The [interface tests](../tests/repair_22_33_215.rs) exercise both authority
constructors, transported chain proofs and adjacent replay steps.
