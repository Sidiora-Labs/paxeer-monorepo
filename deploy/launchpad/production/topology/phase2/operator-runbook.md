# Topology v2 operator

Run every command from the monorepo root, `/work/paxeer-monorepo` in this checkout. The [topology overview](../README.md) describes the offline compiler and its capacity assumptions; this runbook describes the connected [operator CLI](operator.py), [evidence evaluator](evidence.py), [Kubernetes provider](providers.py) and [capacity CLI](capacity.py).

Paxeer is one BFT network with the kernel participating in block proposals, EVM chain ID 125 (`0x7d`) and final receipts once their blocks commit. Set `topology.rpcEndpoints` to two to eight distinct verified HTTPS node URLs at the root path, such as `https://api1.mainnet-beta.paxeer.network/` and `https://api2.mainnet-beta.paxeer.network/`. The public node names are `api1` through `api14.mainnet-beta.paxeer.network`, plus `api-mainnet-beta.paxeer.network`. Verify chain identity and committed hashes; quarantine a conflicting endpoint rather than rolling back committed application effects. Sub-chains are database tenant domains, not additional infrastructure fleets.

The command shape is:

```sh
PYTHONPATH=deploy/launchpad/production/topology python3 -m phase2.operator ACTION \
  --inputs /reviewed/operator-inputs.json \
  --source-root "$PWD" \
  --journal /durable/topology/operator.db \
  --actor OPERATOR \
  --output /evidence/result.json
```

Replace `ACTION` and add its required arguments. All actions require the arguments shown above; `--phase` defaults to `2` and accepts `2` or `3`.

| Action | Additional arguments and effect |
| --- | --- |
| `render` | Produce the connected resource plan without invoking Kubernetes. |
| `diagnostics` | Produce digest, address, runtime-owner and capacity metadata without document contents. |
| `propose` | Record a new monotonically increasing revision in the journal. |
| `validate` | `--evidence /reviewed/signed-evidence.json`; verify evidence and perform server-side dry-run before recording validation. |
| `activate` | `--evidence /reviewed/signed-evidence.json --authorization /reviewed/signed-activation.json`; check authority, persist intent, apply and wait for rollouts. Resume uses this same CLI action with authorization payload action `resume`. |
| `reject` | `--authorization /reviewed/signed-rejection.json`; reject a proposed or validated revision under activation-purpose authority. |
| `rehearse` | `--phase 3 --rehearsal /reviewed/request.json --authorization /reviewed/authority.json`; inject and recover a bounded fault in a qualification namespace. |
| `recover-rehearsal` | `--phase 3 --rehearsal /reviewed/request.json --authorization /reviewed/recovery-authority.json`; recover an interrupted rehearsal using the unchanged request. |

## Source and runtime prerequisites

`--source-root "$PWD"` identifies the monorepo, including `tools/launchpad/production/load` for capacity checks. `connected_plan` resolves the runtime adapter as `<source-root>/tools/launchpad/production/integration/adapters.py`. Every connected action, including `render`, `diagnostics` and capacity capture/check, constructs this plan and requires that checked-in adapter and its reviewed byte digest in `adapterSHA256`. A missing adapter or a digest mismatch rejects the operation before performing its action. Review the adapter and runtime document bindings before attempting connected qualification or activation; do not substitute synthetic documents or bypass the digest check. The offline commands in the [overview](../README.md) do not load that adapter.

The operator input is a closed `schemaVersion: 2` object containing `topology` (the integrated topology schema v2), `adapterSHA256`, `documents`, `chainFile`, `chainSHA256`, `expectedSourceDigest`, `expectedInterfaceDigest`, `kubectl`, `openssl`, and `trust`. Source/interface expectations come from the admitted prior serial gate. `documents` contains all twelve runtime roles and their actual document bindings `{path,sha256}`. Budget and readiness are mandatory for every role; `api` additionally requires `accounting_read`, `indexer` requires `receipt` and `delivery`, `charts`, `stats` and `pnl` require `delivery`, and `gateway` requires `identity`. Provision these documents as `<kind>.json` keys in each role's runtime Secret, mounted read-only at `/run/kindle`; for example, `budget.json`, `readiness.json` and `accounting_read.json`. Credentials remain in external Secret references. The operator reads the referenced local documents to verify their bindings, but never exports their contents or reads Kubernetes Secret values.

`chainFile` must match `chainSHA256`, declare `core.chainId: 125`, and contain nonzero 20-byte hexadecimal contract addresses. The connected plan records those addresses and `core.recordedStatus`; production activation requires the recorded status to be `active` or `eligible`. Use the reviewed chain manifest rather than copying addresses from another deployment. Topology schema 2 declares every role's `workloads` and `runtimeDocuments`; its pooler-plus-direct-server budget is at most 480, within the global 600 connections and 60 reserved slots described in the [overview](../README.md#contracts-and-arithmetic).

`kubectl` is `{path,sha256,context}` and `openssl` is `{path,sha256}`. Executables are independently reviewed absolute paths with exact byte digests. `trust` maps approved Ed25519 key identities to `{path,sha256,purposes}` public-key records. Purposes are explicitly `qualification`, `activation`, or both; an evidence signer without activation authority cannot authorize deployment. Provision trusted public keys independently from proposals, preserve the journal on durable storage, and restrict journal write access to the authorized controller. SQLite FULL-sync transactions serialize proposals and compare-and-swap activation intents; this local journal does not supply cross-region controller availability. A hosted controller must adopt these transitions into its durable authority before multi-region operation.

A signed evidence bundle has `{schemaVersion:2,payload,signature}`. Signature is `{schemaVersion:2,keyId,algorithm:"Ed25519",signature:BASE64}` over the exact canonical JSON bytes of `payload`. Payload contains schemaVersion, configuration/deployment/source/interface/chainManifest digests, references for `baseEvidence`, `inventory`, `restore`, `canary`, and all eighteen `requirements`. Every reference is `{path,sha256}` over exact file bytes. Base evidence retains the frozen declaration compiler's evidence contract and declaration deployment digest. The separately signed connected deployment digest binds the complete runtime document wiring and real Kubernetes resource list; neither binding replaces the other.

Each requirement binds `artifact`, `input`, `reconciliation`, and `metric` references. Metric artifacts contain `{metric,samples}` with timestamp/value/service/environment/zone per sample. The complete signed scenario inputs and reconciliations must come from actual isolated provider journeys. Missing, changed, failed, duplicate, expired, oversized or incomplete artifacts reject qualification. An explicit failure result is emitted for all eighteen requirements when the operation cannot qualify. Arithmetic and synthetic contract fixtures never establish measured production capacity.

Inventory contains `schemaVersion:2`, three provider `zones` mapped to independent failure-domain identifiers, three distinct-zone `postgres` members `{id,zone,allocatedBytes}`, three distinct-zone `nats` members `{id,zone,allocatedBytes,configuredStoreBytes}`, and exact `runtimeOwners`. PostgreSQL capacity includes the 555360000000 raw-byte thirty-day fixture, 1666080000000 amplified bytes per member, measured derived tables/WAL/vacuum and free headroom. Normal broker retention and 72-hour 2000/s qualification are independent ledgers. Raw-only R3 with twofold headroom needs 3732480000000 bytes before derived streams and measured overhead. Compare against actual configured stores, each at most 90% of its volume; expand before qualification when insufficient.

Restore evidence must report a real successful restore, zero duplicate database effects, zero lost acknowledged writes, and exactly one PostgreSQL writer. Canary evidence binds the same configuration/deployment/source/interface, observes exactly 5% traffic for at least the configured 600 seconds, includes first/last interval samples and passing SLO/accounting observations, and must remain fresh. The canary executor and traffic routing are external reviewed control-plane responsibilities; absent actual measurements prevent activation.

`validate` verifies the complete external signature and measured evidence before actual server-side Kubernetes dry-run, then records the validated target. Its `--actor` must equal the evidence signature's `keyId`. `activate` rechecks current evidence, signature, exact target, and independent activation authority before creating a durable intent or applying any resource. Authorization is `{payload,signature}`; payload is `{action:"activate",revision,expectedActiveRevision,actor,configurationDigest,deploymentDigest,evidenceDigest,notBefore,expiresAt,context,namespace}` and its actor must equal the trusted signing key identity. Its interval is at most 900 seconds. Qualification contexts and production contexts require separate reviewed authority; no default context is selected.

After a durable activation intent, actual server-side apply and rollout status run against the approved context. A crash or failed partial apply retains the intent and blocks another deployment. Resume the same revision/digests with fresh signed authority carrying action `resume`; idempotent server-side apply reconciles before marking activated. Never delete the intent to bypass reconciliation. Rejected proposals and actor/revision/audit records remain durable. Rollback is a new monotonic, independently authorized compatible configuration revision; database downgrades and implicit resource pruning are not performed.

## Phase 3 adversarial evidence and isolated rehearsal

Select `--phase 3` for validation and activation. A phase 3 bundle and its signed payload use `schemaVersion:3`; the signature object still uses `schemaVersion:2`, and the base declaration evidence retains schema 1. The signed reference keys are unchanged. Phase 2 evidence cannot satisfy phase 3. Every requirement observation artifact now has `{schemaVersion:3,requirement,configurationDigest,deploymentDigest,startedAt,finishedAt,observations}`. Input artifacts have `{schemaVersion:3,requirement,action,environment,context,namespace,namespaceUID,configurationDigest,deploymentDigest,faultStartedAt,faultFinishedAt,parameters}`. The environment must be `qualification`; the fault interval must fall inside the observed scenario. `parameters.removedZone` identifies the exact withdrawn zone for zone-loss scenarios.

Actions, in D14_001 through D14_018 order, are `zone_application_loss`, `fleet_arithmetic`, `api_zone_loss`, `socket_zone_loss`, `frame_burst`, `postgres_primary_loss`, `maximum_connections`, `broker_loss`, `retention_ledgers`, `worker_zone_loss`, `cache_loss`, `combined_zone_loss`, `denied_promotion`, `busy_sigterm`, `postgres_disconnect`, `committed_hash_conflict`, `media_isolation`, and `public_database_drift`. The evaluator checks the requirement's observations, including per-survivor throughput and latency, receipts, bounded cold reads, stale lease rejection, explicit snapshot age, endpoint quarantine and exposed resource identity. A signed `passed:true` flag or HTTP health alone does not satisfy these checks. Exact observation fields and bounds are defined by `validate_adversary` in `evidence.py`.

Each reconciliation artifact has `{schemaVersion:3,requirement,beforeDigest,afterDigest,acknowledgedWriteIds,receiptIds,effectCounts,lostAcknowledgedWrites,duplicateDatabaseEffects,activePostgresWriters,restored,recoveredAt,timeline}`. Every acknowledged write must have a durable receipt; every receipt has exactly one database effect. Mutation-bearing failures require nonempty acknowledged-write sets. `timeline` is an ordered list of `{at,phase,stateDigest}` and must include `before`, `fault`, `recovering`, and `recovered` observations within their actual intervals. Its first and last digests bind the reconciled state digests. Failed restore, missing receipts, duplicate effects, multiple writers and missing incident observations fail validation.

Retention observations keep normal and qualification ledgers separate, identify the 1200-byte envelope, itemize derived traffic and measured broker overhead, and reconcile measured allocation/free bytes for every PostgreSQL member. The 555360000000-byte raw fixture and 1666080000000 amplified bytes per member exclude derived tables, WAL, vacuum workspace and reserved free headroom. No aggregate three-member allocation can hide a deficient member.

Native infrastructure actions are available through `rehearse` and `recover-rehearsal`, with `--phase 3 --rehearsal /reviewed/request.json --authorization /reviewed/authority.json`. A request is `{id,action,namespaceUID,removedZone,pods,holdSeconds}`; each pod is `{name,uid,role}`, and holdSeconds is bounded to 1–60. Supported native injections are application-zone loss, combined application/broker-zone loss, current PostgreSQL primary loss, single broker loss and busy replica SIGTERM. Zone withdrawal must name every owned replica in the specified zone. Application scheduling temporarily excludes that zone; storage claims and chain infrastructure remain intact. The independently provisioned namespace must have label `kindle.io/environment=qualification`, and its actual UID must match the signed request. The operator never modifies nodes or validators.

Rehearsal authorization payload is `{action,actor,requestDigest,configurationDigest,deploymentDigest,context,namespace,notBefore,expiresAt}`. Action is `rehearse` or `recover-rehearsal`; the trusted signing key must have activation purpose, actor must match its key identity, and the interval is at most 900 seconds. A durable rehearsal intent records the reviewed recovery resources before fault injection. Interrupted rehearsals block activation and another rehearsal. Reusing the same request ID cannot repeat injection. Recovery needs independently signed authority for the unchanged request and candidate. Recovery restores affinity with resource-version checks, waits for Ready replicas, and reconciles the original replica count and exactly one database writer.

Rehearsal snapshots contain projected pod identities, readiness, placement and writer labels. They explicitly return `notQualificationEvidence:true`: application workload, durable SQL effects, measured network overhead, CDN accounting, cache rebuild, readiness dependency and RPC integrity artifacts must come from their real provider journeys. These infrastructure snapshots are insufficient for capacity or business-state certification.

Activation interruption retains the original authority digest. Reusing the unchanged authorization can retry; renewing it requires an explicitly signed authorization with `action:resume`, the same actor, candidate, evidence and active-revision comparison. A changed authorization with `action:activate` is rejected. Explicit rejection also requires activation-purpose authorization over `{action:"reject",actor,revision,configurationDigest,deploymentDigest,notBefore,expiresAt}`. An untrusted evidence signer or a caller whose actor differs from the evidence key cannot reject a proposal by submitting invalid evidence.

Phase 3 measured inventory uses schemaVersion3 and additionally requires `qualificationTarget:{context,namespace,namespaceUID,environment:"qualification"}`. Every scenario input must match that independently attested target. Metric samples must include the scenario endpoints and a sample inside the fault interval.

## Phase 4 native capacity capture

From the monorepo root, after satisfying the [source and runtime prerequisites](#source-and-runtime-prerequisites), run:

```sh
PYTHONPATH=deploy/launchpad/production/topology python3 -m phase2.capacity capture \
  --inputs /reviewed/capacity-inputs.json \
  --source-root "$PWD" \
  --output /durable/new-topology-capture
```

The output directory must be new. Capture polls actual authenticated Prometheus series and Kubernetes pod/node/PVC allocation; it writes fsynced raw NDJSON, exact file hashes, actual UTC timing and a machine-readable `capture.json` manifest. Capture never generates application traffic or changes infrastructure. The D16 orchestrator supplies the actual workload and authorized adversarial controls.

Inputs are a closed `schemaVersion:4` object with `operatorInputs:{path,sha256}`, `loadSources`, `expectedGeneratorSHA256`, `metricAuthority:{path,sha256}`, and `run`. Operator inputs retain the connected operator schema. `loadSources` maps the filenames `capture.py`, `phase2_types.py`, `phase2_http.py`, `workload.py`, and `final-shared-capture.schema.json` to the SHA-256 digests of their actual bytes in `tools/launchpad/production/load`; the checker resolves that directory under `--source-root`. Generator identity comes from the actual admitted D16 run. `run` is `{runId,target,durationSeconds,intervalSeconds,scope}`. Target is `{context,namespace,namespaceUID,environment:"qualification",zones}` and must match the connected Kubernetes target; the namespace's actual UID and independent qualification label are reread. Capture duration is 60–259200 seconds, interval is 1–60 seconds, duration must be divisible by interval, and scope is `isolated_component` or `final_shared`. Begin capture before workload warmup and finish after the measured windows.

Metric authority is `{payload,signature}` authenticated by a qualification-purpose Ed25519 key. Payload is `{schemaVersion:4,origin,ca,clientCertificate,clientKey,bindings,target,metrics}`. TLS references are `{path,sha256}`; actual CA, client certificate and private key are required, copied into a private temporary directory for SSL initialization, and never exported in captures. TLS 1.3, a credential-free HTTPS origin, bounded requests and two-second freshness are enforced. Bindings are `{candidate,interface,topology,generator}` from the actual source/interface/deployment/generator digests. Metrics maps every semantic field in `capacity.NATIVE_FIELDS` to `{metric,kind,labels}`. Native metric names are explicit reviewed inputs; arbitrary expressions and absent series are rejected. Labels select the exact qualification environment and namespace. Counter mappings and gauge mappings must describe actual exporter semantics; no sample metrics or default provider mappings are supplied.

The collector records raw Prometheus series and their timestamps, exact image and CPU/memory requests/limits, pod identity/placement/readiness, independently bound durable volumes and actual allocated PVC bytes. The evaluator correlates per-member free bytes, raw fixture payload and amplified storage, derived tables, WAL, vacuum workspace and reserved free headroom. Normal 72-hour retention and the 2000/s replay ledger stay separate. It verifies actual stream retention, R3, retained logical data and measured overhead against usable broker store allocation. Missing allocation or capacity telemetry fails the result.

Evaluate the signed measurements with a new output file:

```sh
PYTHONPATH=deploy/launchpad/production/topology python3 -m phase2.capacity check \
  --inputs /reviewed/capacity-inputs.json \
  --source-root "$PWD" \
  --measurements /reviewed/signed-phase4-references.json \
  --output /durable/new-result.json
```

Signed measurements are `{payload,signature}`. Payload is `{schemaVersion:4,runId,configurationDigest,deploymentDigest,sourceDigest,interfaceDigest,phase3Evidence,capture,sharedCapture,windows}`; the three artifact references are exact `{path,sha256}` files. Phase 3 evidence retains its signed schemaVersion3 and all eighteen interpreted adversarial results. The shared manifest retains the genuine D16 `kindle-shared-capture-v1` contract and exact candidate/interface/topology/generator bindings; it must identify this run and L42. Checking requires both native and D16 capture scopes to be `final_shared`; an `isolated_component` capture cannot satisfy this release measurement check.

Windows are `{soak:{startNs,endNs},burst:{startNs,endNs},zoneLoss:{startNs,endNs}}`. Soak is at least 86400 actual seconds, burst at least 600, zone loss at least 60; burst and zone loss occur inside the soak and do not overlap each other. Native and D16 windows must agree. Raw samples must cover every window, remain ordered and contemporaneous with allocations, and contain no hidden gaps or counter resets. A changed counter replica/epoch requires real reconciliation and a fresh capture; no implicit zero baseline is used. The capacity check applies 10000/20000 dynamic RPS, write/quote subsets, error rates, read/quote p99 bounds, 100000/200000 connections, 100/400 MB/s market payload and measured wire overhead. Zone-loss survivors must each demonstrate at least 625 API RPS with the measured allocation. Existing D16 capture checks remain authoritative and can reject incomplete gateway fleet observations.

All eighteen requirements receive explicit pass or failure results. Missing data, stale digests, failed restore, lost receipts, duplicate effects, stale metrics and insufficient measured storage fail. Successful owned measurements retain `capacity_qualified:false` and `monthly_availability_qualified:false`; final shared serial9.1 signoff and approved operating budget are separate release obligations. A bounded isolated capture prepares the lane harness without claiming a full shared soak, restore or production release.

Physical storage zones come from each actual PV node-affinity contract and must match pod placement where scheduled. Unschedulable replicas remain visible in raw allocation snapshots. D16 fault intervals must reference an immutable indexed `native_provider` control artifact by `native_control_sha256`, report recovered outcome and match the measured zone-loss interval. The native manifest additionally binds the selected metric authority file digest.
