# JVM SDK

Java and Kotlin SDK (`com.sidiora.layerx:layerx-sdk`, package
`com.sidiora.layerx.sdk`) for the Agent and Human APIs of Paxeer X Network.
LayerX is merged into the network. The kernel is part of the `paxd` BFT node
and proposes blocks; a receipt is final once its block is committed.
Hosted documentation lives at [docs.paxeer.app](https://docs.paxeer.app/).

## Features

- **Schema-generated types**: `GeneratedSchema` holds Agent and Human operation
  constants, request and response records, and events, generated by
  [`../generators/generate_jvm.py`](../generators/generate_jvm.py).
- **Local verification**: `verify.LocalVerifier` checks signed receipts against
  pinned receipt keys and the original transaction. `verify.Committed` checks
  block commits and inclusion proofs; `verify.PortableReceipt` verifies and
  exports portable evidence with independently supplied trust anchors.
- **Resumable streaming**: `ResumableStream` publishes a `Flow.Publisher` over
  cursor-paged sources.
- **Integer-only money**: `ProtocolAmount` is backed by `BigInteger` and has no
  floating-point constructor.
- **Security primitives**: `IdempotencyKey` and `SecretBytes`.
- **Kotlin helpers**: top-level functions and `ProductionClient` extensions in
  [`LayerX.kt`](src/main/kotlin/com/sidiora/layerx/sdk/LayerX.kt), including
  `protocolAmount`, `idempotencyKey`, `streamCursor`, and typed `agent`/`human`
  calls with default options. Import the package or the top-level functions.

## Requirements

- Java 21 (`maven.compiler.release` in [`pom.xml`](pom.xml))
- Maven; the build depends on Jackson, Bouncy Castle and the Kotlin 2.0.20
  standard library

## Network and API configuration

Public node JSON-RPC uses HTTPS at the root of
`https://api-mainnet-beta.paxeer.network` or the numbered hosts
`https://api1.mainnet-beta.paxeer.network` through
`https://api14.mainnet-beta.paxeer.network`. Check `eth_chainId` for `0x7d`
(decimal `125`) before signing or broadcasting. See
[Public RPC endpoints](../../../docs/site/docs/reference/public-rpc.md).
`node.hyperpaxeer.com` is only the hpx library mirror, never an RPC endpoint.
Sub-chains are tenant domains in the database and share the network.

`ProductionClient` uses schema-defined authenticated service APIs.
`HttpProductionTransport.create(humanBaseUri, agentBaseUri, credential)` takes
service base URIs: it appends the generated Human route to `humanBaseUri` and
selects the Agent route from `agentBaseUri`. Obtain these service addresses
and credentials from your deployment. Public node URLs do not imply that
Human or Agent operations are available there. Hosted gateway `px_` methods
have their own [OpenRPC contract](../../../services/platform/hosted/gateway/openrpc.json).

Agent calls additionally require an `HttpProductionTransport.AgentSessionCredential`,
passed to the four-argument `create` overload. It carries the authorised tenant,
session ID, secret token ID and generation. Mutating Agent operations require a
32-byte idempotency key encoded as 64 lowercase hexadecimal characters; read
operations reject an idempotency key. Use the generated operation catalogue and
request types rather than treating Agent calls as node JSON-RPC methods. See
[`HttpProductionTransport.java`](src/main/java/com/sidiora/layerx/sdk/HttpProductionTransport.java)
for the envelope and session validation.

## Quick start

These examples request a Human move quote and return its ID; obtaining a quote
does not submit a transfer. Supply your service base URIs, an issued bearer
token, valid source and destination identifiers, and the service's currency
identifier. The amount is in integer base units. The credential remains open
until the asynchronous response completes, then its owned secret bytes are
cleared.

### Java

```java
import com.sidiora.layerx.sdk.*;
import java.net.URI;
import java.nio.charset.StandardCharsets;

public final class QuoteExample {
    public static String quote(URI humanBaseUri, URI agentBaseUri, String token,
                               String source, String destination, String currency) {
        try (var credential = new HttpProductionTransport.BearerCredential(
                new SecretBytes(token.getBytes(StandardCharsets.UTF_8)))) {
            var transport = HttpProductionTransport.create(
                humanBaseUri, agentBaseUri, credential);
            var client = new ProductionClient(transport);
            var money = new GeneratedSchema.HumanModels.Money(
                ProtocolAmount.parse("1000000"), currency);
            var request = new GeneratedSchema.HumanOperations.MoveQuoteRequest(
                source, destination, money);
            var response = client.human(GeneratedSchema.HumanOperations.MOVE_QUOTE,
                request, ProductionClient.Options.none()).toCompletableFuture().join();
            return response.quote_id();
        }
    }
}
```

### Kotlin

```kotlin
import com.sidiora.layerx.sdk.*
import java.net.URI

fun quote(humanBaseUri: URI, agentBaseUri: URI, token: String,
          source: String, destination: String, currency: String): String =
    HttpProductionTransport.BearerCredential(
        SecretBytes(token.toByteArray(Charsets.UTF_8))).use { credential ->
        val transport = HttpProductionTransport.create(
            humanBaseUri, agentBaseUri, credential)
        val client = ProductionClient(transport)
        val money = GeneratedSchema.HumanModels.Money(protocolAmount("1000000"), currency)
        val request = GeneratedSchema.HumanOperations.MoveQuoteRequest(
            source, destination, money)
        client.human(GeneratedSchema.HumanOperations.MOVE_QUOTE, request)
            .toCompletableFuture().join().quote_id()
    }
```

String-named and `Class`/`TypeReference` overloads of `agent` and `human` remain
available for known operations. Typed `GeneratedSchema` constants keep Agent
and Human requests, responses and events distinct at the JVM type boundary.
The historical files in [`examples/`](examples/) contain obsolete endpoint,
request and verifier usage and are not runnable integration guidance.

## Local verification

The node's `pax_sequencerReceipt` lifecycle is `submitted`, `receipted`, then
`committed`. `submitted` is pending and has no verifiable receipt. A signature
verified at `receipted` does not establish block commitment. The current
`LocalVerifier.VerificationLevel` values are `RECEIPTED` and `COMMITTED`, with
wire values `receipted` and `committed`.

### Signed receipts and receipt key pins

For new submissions, sign a raw EIP-1559 transaction locally and retain the exact
bytes submitted to `eth_sendRawTransaction`, together with its transaction hash.
Do not substitute calldata, a transaction JSON object or a transaction rebuilt
after submission for those signed bytes. The verifier also accepts retained
historical transaction encodings; this does not change the submission guidance.
Supply the canonical signed receipt bytes and independently trusted key pins,
not a key accepted merely because the response carries it. Save the following
complete Java snippet as `ReceiptExample.java`:

```java
import com.sidiora.layerx.sdk.verify.LocalVerifier;
import java.math.BigInteger;
import java.util.List;

public final class ReceiptExample {
    public static LocalVerifier.SequencerReceiptVerification verify(
            byte[] signedReceipt, byte[] rawTransaction, byte[] trustedKeyId,
            byte[] trustedPublicKey, BigInteger firstHeight, BigInteger lastHeight) {
        var pins = new LocalVerifier.ReceiptKeys(List.of(new LocalVerifier.ReceiptKey(
            trustedKeyId, trustedPublicKey, firstHeight, lastHeight)));
        var verified = LocalVerifier.verifySequencerReceipt(
            signedReceipt, rawTransaction, pins);
        verified.requireSuccess();
        return verified;
    }
}
```

Each pin has a nonzero 32-byte key ID, a nonzero 32-byte Ed25519 public key and
an inclusive unsigned height range. Obtain pins through independently trusted
chain configuration. The verifier selects the receipt's key ID, enforces its
height range, checks the signature and canonical encoding, binds the activity
ID to the transaction hash, and validates the sequence hash and effect layout.
Its overload accepting the RPC view and a previous sequence hash also checks
that view and the supplied predecessor. Verification can authenticate a reverted
transaction: `status()` is `1` for success and `0` for revert; `requireSuccess()`
throws for the latter. Payment consumers must also match the expected log,
asset, recipient and amount before acting on an authenticated receipt.

### Portable v2 committed evidence

For portable evidence, use
[`verify.PortableReceipt`](src/main/java/com/sidiora/layerx/sdk/verify/PortableReceipt.java)
and the format `layerx-receipt-proof-v2`. A receipted bundle carries
`rawTransaction`, `signedReceipt`, `receiptDigest`, `receiptKey` and `receiptJson`,
alongside `format` and `verificationLevel`. A committed bundle also carries
`blockHeader`, `receiptInclusion`, `commit` and `validatorSet`.

The following complete Java snippet (`PortableExample.java`) requires committed
evidence for the transaction retained by the application. Use Java 21 with this
SDK and its declared dependencies for both snippets.

```java
import com.fasterxml.jackson.databind.ObjectMapper;
import com.sidiora.layerx.sdk.PlatformSdkException;
import com.sidiora.layerx.sdk.verify.ConsensusTrust;
import com.sidiora.layerx.sdk.verify.LocalVerifier;
import com.sidiora.layerx.sdk.verify.PortableReceipt;
import java.io.IOException;
import java.security.MessageDigest;
import java.util.HexFormat;
import java.util.List;

public final class PortableExample {
    public static PortableReceipt.Verification verifyCommitted(
            byte[] bundle, byte[] retainedRawTransaction,
            LocalVerifier.ReceiptKeys pinnedKeys, String trustedChainId,
            long trustedHeight, byte[] trustedValidatorsHash,
            List<ConsensusTrust.Step> transitions) throws IOException {
        var trust = new ConsensusTrust(
            trustedChainId, trustedHeight, trustedValidatorsHash);
        byte[] snapshot = bundle.clone();
        var verified = PortableReceipt.verify(snapshot, pinnedKeys, trust, transitions);
        if (!"committed".equals(verified.verificationLevel())) {
            throw PlatformSdkException.verificationFailure();
        }
        var document = new ObjectMapper().readTree(snapshot);
        byte[] carriedTransaction = HexFormat.of().parseHex(
            document.required("rawTransaction").textValue().substring(2));
        if (!MessageDigest.isEqual(retainedRawTransaction, carriedTransaction)) {
            throw PlatformSdkException.verificationFailure();
        }
        verified.requireSuccess();
        return verified;
    }
}
```

The evidence level is a caller policy: `PortableReceipt.verify` accepts both
receipted and committed bundles. Supplying consensus trust alone does not require
commitment, so the snippet explicitly checks `verificationLevel()` before
returning. It also compares the carried transaction with the separately retained
bytes; internal consistency alone does not identify the payment you expected.

For committed evidence, `ConsensusTrust` pins an independently obtained
consensus chain ID, positive height and 32-byte validator-set hash. The consensus
chain ID is the header's string identifier, not the EVM chain ID `125`.
Supply verified transition evidence from that trusted height to the execution
header, or an empty list when the heights match. The portable verifier requires
this anchor for a committed bundle, authenticates the headers, and checks the
transaction, batch and execution-result inclusion proofs and validator commits.
The bundle's own key and validator set do not establish trust by themselves.
`verificationLevel()` reports the verified evidence level;
`PortableReceipt.export(verified)` re-exports the verified bundle. The
receipt-only `PortableReceipt.verify(bundle, pinnedKeys)` overload refuses a
committed bundle because it lacks consensus trust. A receipt pin authenticates
the sequencer signature; it cannot substitute for the consensus trust anchor.
Provision receipt keys and consensus trust through independently authenticated
chain configuration before importing a bundle, and retain that configuration
separately. Never initialise `trustedValidatorsHash` from the bundle's own
`validatorSet` or turn its `receiptKey` into a pin merely to make it verify.

The committed proof includes the execution header and its commit as well as a
successor header and commit in `receiptInclusion` to prove the execution results.
The verifier authenticates that successor through the execution header's next
validator hash. A signed receipt or an RPC `rung` string alone cannot supply this
proof. The published [portable vectors](../conformance/fixtures/vector-v5-portable.json)
show both exact wire shapes; their fixture keys and consensus roots are test
material, never production trust anchors.

The generated Human API intentionally uses `unverified`, `receipt-verified`
and `checkpoint-finalised` in `HumanModels.HumanVerificationLevel`.
`checkpoint-finalised` names the committed rung in that API;
it does not add another network finality step or change the local verifier enum.
The [README verifier, transaction binding and independent trust tests](test_repair_22_33_1394.py)
check these evidence levels and the snippets above against the production
verifiers and retained producer vectors. The
[signed receipt tests](src/test/java/com/sidiora/layerx/sdk/SequencerReceiptTest.java)
and [portable receipt tests](src/test/java/com/sidiora/layerx/sdk/PortableReceiptTest.java)
exercise receipt authentication and portable evidence verification.

## Streaming

With a configured `ProductionClient client`, open the typed Human stream:

```java
var stream = client.openHumanStream().toCompletableFuture().join();
var publisher = client.humanStreamPublisher(stream);
```

The publisher emits `ResumableStream.Event<GeneratedSchema.HumanModels.StreamEvent>`
with backpressure on a virtual thread. Persist the last processed event's cursor
with your application's work so it can resume after restart. Restore a
`ResumableStream` with that cursor and pass it to `humanStreamPublisher`; Kotlin
also provides `client.resumeHumanStream(savedCursor)`.

For custom sources, `ResumableStream.publisher(PageSource<T>)` fetches a
`CompletionStage<ResumableStream.Page<T>>` carrying the requested cursor, events
and next cursor. Cursor continuity and duplicate IDs are checked before a page
is accepted. The stream state is in memory; the application owns durable cursors
and durable deduplication of side effects.

## Money

```java
import com.sidiora.layerx.sdk.ProtocolAmount;
import java.math.BigInteger;

ProtocolAmount amount = ProtocolAmount.of(new BigInteger("1000000"));
ProtocolAmount parsed = ProtocolAmount.parse("1000000");
```

Amounts range from zero through `2^128 - 1` in base units. JSON encoding uses
canonical decimal strings; signs, fractions, leading zeroes and JSON numbers
are rejected.

## Errors

Calls return `CompletionStage` values. Failures observed through `join()` are
wrapped in `CompletionException`; argument and idempotency validation can also
throw `PlatformSdkException` synchronously when starting a call. Inspect
`code().wire()`, `retry().wire()` and optional `retryAfterMs()` rather than
parsing exception messages. Local verification failures use `verification-failure`;
an authenticated revert raised by `requireSuccess()` uses `revert`.

Retry classifications are `never`, `safe`, `after` and `unknown-outcome`.
Persist idempotency keys and the original signed transaction bytes and hash
before submission. After a timeout or `unknown-outcome`, reconcile the original
transaction hash and receipt before deciding to retry; do not create a
replacement transaction with the same nonce. `ProductionClient` and stream
instances do not supply an application recovery journal.
